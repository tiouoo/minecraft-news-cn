洞穴与山崖：第二部分的第二个快照来了！这个快照主要包含微调和漏洞修复，但也有一些新的技术性新增内容，例如一个独立的模拟距离滑块和增加的线程数量（不，我不是在说你想买的那种高级床单的线数）。

哦，而且你们似乎也非常喜欢要塞，所以我们决定将它们重新加入游戏。尽情享受吧！

21w38a的已知问题

  • 此快照仍与旧世界不兼容——要在此快照中游玩，你必须创建一个新世界
  • 世界保存有时可能需要非常长的时间——如果你看到世界有一段时间静止不动，原因就是这样

21w38a中的更改

  • 当你只是轻轻将袖子蹭到墙壁时，疾跑不再变为行走
  • 修复了矿石的分布

矿石分布

  • 铜矿石最高生成至y=95（如最初设计）
  • 增加了铜的生成数量
  • 青金石像其他矿石一样以团块形式生成（而不是分散分布）

疾跑

  • 之前，与方块发生任何碰撞都会使疾跑变为行走。现在，当与方块碰撞的角度非常小时，玩家会保持疾跑。当碰撞角度较大时，将保留旧行为。

21w38a中的技术性更改

  • 新增了一个设置：“模拟距离”
  • 增加了后台线程的最大数量
  • 加入了世界加载的遥测

模拟距离设置

  • 模拟距离之外的实体不会被更新。
  • 允许以更低的CPU负载实现更高的渲染距离。
  • 在客户端的视频设置中新增了一个滑块。
  • 在专用服务器属性中新增了一个simulation-distance属性。
  • 我们将继续对此进行完善，目标是让模拟距离也影响方块和流体的刻更新。

后台线程最大数量增加

包括世界生成在内的各种后台任务在后台线程池中执行。线程池的大小等于可用CPU线程数减一，但之前上限是7。现在这个上限是255。这应该有助于高端机器提升世界生成的性能。

这个上限可以通过max.bg.threadsJava系统属性覆盖，例如在一台机器上运行多个服务器时。

遥测

在此版本中，我们重新引入了诊断跟踪，这项功能在2018年之前曾是Minecraft：Java版的一部分。我们将它带回来，是为了更好地了解玩家并改善他们的体验。具体来说，我们希望确保在今年晚些时候的洞穴与山崖更新第二部分中，极其繁重的世界生成能拥有更强劲的性能。

在实际中，这意味着识别游戏中的技术痛点，例如较弱的硬件在高复杂度地形中的表现。这些信息还将帮助我们确定开发的优先方面，平衡游戏特性（例如，了解到山羊把每个玩家都从悬崖上撞下去），并在发现许多新玩家卡在相同地方之后向他们伸出援手。所有数据都按照GDPR和CCPA的最佳实践处理，用于打造性能更好、总体上更令人愉快的Minecraft：Java版。

目前，唯一实现的事件是世界加载。

世界加载事件

  • 在加载单人世界或连接多人服务器时发送
  • 包含以下信息：
    • 启动器标识符
    • 用户标识符（XUID）
    • 客户端会话ID（重启时更改）
    • 世界会话ID（每次加载世界时更改，供后续事件复用）
    • 游戏版本
    • 操作系统名称和版本
    • Java运行时版本
    • 客户端或服务器是否安装模组（与崩溃日志中的信息相同）
    • 服务器类型（单人、Realms或其他）
    • 游戏模式
