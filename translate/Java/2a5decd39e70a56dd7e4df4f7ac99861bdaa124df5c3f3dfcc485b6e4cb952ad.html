实验性功能

以下更改仅会在相应实验项开启时生效，开启方式可以是激活对应的实验性数据包，也可以在创建世界时于“实验性”界面中打开相应开关。

这些实验项在未启用时不会产生任何效果。你可以在此处找到关于功能开关的更多信息。

收纳袋

  • 收纳袋的提示框现在可容纳 3 行，并且始终至少能显示 8 种物品类型

开发者注：收纳袋中的物品按每行四个填装，当一行填满后，会被上方的新行向下推挤。这意味着最上面一行可能出现空位。

在 2020 年的收纳袋实验性功能中，物品会从顶部开始填装且不会留下任何空隙。我们更改了这一行为，因为原先的机制意味着当新物品加入时，袋中的物品会左右移动。这让部分玩家更难追踪物品的顺序，甚至有人反馈物品像是在随机移动！

当时提示框只有两行，把已满的一行向下推挤会直接让一半的可见物品被挤出去，这实在太多了。所以我们加入了第三行，让这个设计更好用，也让玩家在收纳袋逐渐填满时能看到更多袋中物品。

矿车改进

请注意，此开关背后的实验性功能目前并不针对任何未来版本，而是我们尝试改动并收集反馈的空间。

我们很期待听到你对这些改动的想法：请在此反馈页面上分享你的意见。

  • 矿车落在铁轨上时不再会被强制对齐到方块中心
    • 矿车会沿对角线对齐到拐角处，并且被活塞推动后也会对齐
    • 这允许活塞推进装置等类似机械正常工作
  • 发射器现在又可以堆叠发射矿车了
  • 矿车现在更容易在相对的斜坡上停稳
  • 矿车在短距离下落或竖直下落时不再倾斜
  • 矿车现在被放置（或发射）到铁轨上时会立即拥有正确的旋转方向
    • 放到斜坡上时也会以正确的旋转方向放置
  • 矿车在斜坡上上下行驶时不再穿过方块，而是会发生碰撞

数据包版本 50

更改的物品组件

minecraft:food

  • 食物组件已更改为一个数据容器，仅存储物品被消耗时应用的饥饿值数据
    • 该组件不再赋予物品被消耗的能力，此能力改由新的 consumable 组件提供
  • 格式：包含以下字段的对象
    • nutrition 消耗时应用的营养值
    • saturation 消耗时应用的饱和值
    • can_always_eat 是否即使在玩家不饥饿时也能消耗

新物品组件

minecraft:use_remainder

  • 如果存在该组件，当物品在使用后堆叠数量减少时，会用剩余物物品替换该物品
    • 如果物品在使用后堆叠数量仍大于 0，则剩余物物品会被加入物品栏
    • 如果尝试将剩余物加入物品栏时物品栏已满，则会掉落在地上
  • 格式：单个物品堆叠值
    • 例如 use_remainder={id:'minecraft:stick', count:1}

minecraft:use_cooldown

  • 如果存在该组件，此物品被使用后将对所有同类物品施加冷却时间
  • 格式：包含以下字段的对象
    • seconds：正浮点数，表示冷却时间持续的秒数
    • cooldown_group：可选的命名空间 ID，表示冷却组
      • 如果存在，此物品将属于某个冷却组，不再与其基础物品类型共享冷却
      • 相反，施加到此物品上的冷却只会与同属该冷却组的其他物品共享
    • 例如 use_cooldown={seconds:1.5, cooldown_group:"minecraft:custom_weapon"}

minecraft:consumable

  • 如果存在该组件，此物品可以在使用时被消耗
    • 如果此物品上也存在 food、potion_contents、ominous_bottle_amplifier 或 suspicious_stew_contents，消耗此物品将应用这些组件的效果与状态
  • 格式：包含以下字段的对象
    • consume_seconds：非负浮点数，玩家消耗该物品所需的时间（秒）
      • 默认值：1.6
    • animation：消耗该物品期间使用的动画
      • 默认值：eat
      • 可接受的值：
        • none
        • eat
        • drink
        • block
        • bow
        • spear
        • crossbow
        • spyglass
        • toot_horn
        • brush
    • sound：声音事件，在物品消耗过程中及完成时播放的声音
      • 默认值：entity.generic.eat
    • has_consume_particles：布尔值，是否在消耗此物品时产生消耗粒子
      • 默认值：true
    • on_consume_effects：可选的副作用列表，消耗此物品后触发
      • 目前有 5 种有效的消耗效果
      • minecraft:apply_effects
        • effects：消耗后应用的状态效果实例列表
        • probability：浮点数，上述效果在消耗后被应用的概率
          • 默认值：1.0
      • minecraft:remove_effects
        • effects：消耗后移除的一组状态效果，可为标签或 ID 列表
      • minecraft:clear_all_effects
        • 清除消耗者的所有状态效果
      • minecraft:teleport_randomly
        • diameter：正浮点数，消耗者将在该直径范围内被随机传送
          • 默认值：16.0
      • minecraft:play_sound
        • sound：声音事件，消耗后播放一次
    • 例如 consumable={consume_seconds:3.0, animation:'eat', sound:'entity.generic.eat', has_consume_particles:true, on_consume_effects:[{type:'minecraft:clear_all_effects'}]}

资源包版本 36

着色器与后期处理效果

开发者注：虽然在资源包中覆盖核心着色器是可行的，但这被视为不受支持的操作，并非资源包的设计用途。这些着色器是游戏内部实现的一部分，因此随着游戏内部的演进，它们可能随时发生变化。我们理解覆盖核心着色器被用于制作非常酷的资源包功能，其中许多功能缺乏受支持的替代方案。我们希望在未来提供更好、受支持的替代方案。

  • 着色器程序配置现在可以指定应用于其链接后着色器的预处理宏定义指令
    • 许多着色器实现已通过利用这一点进行了合并
  • 核心着色器和后期处理着色器配置的格式已统一
  • rendertype_entity_glint_direct 着色器已被移除（由 rendertype_entity_glint 替代）
  • rendertype_entity_translucent_cull 着色器已被移除（由 rendertype_item_entity_translucent_cull 替代）

着色器程序定义

  • 后期处理效果的程序定义（assets/<namespace>/shaders/program/<name>.json）已与核心着色器定义（assets/<namespace>/shaders/core/<name>.json）保持一致
    • blend 字段已被移除，因为它没有用处
    • attributes 字段已被移除，取而代之的是 Position 属性将始终被绑定
    • 提供的 uniform 变量已与核心着色器提供的统一
      • Time 已更名为 GameTime
  • 程序定义（包括后期处理效果）中的 vertex 和 fragment 着色器引用现在使用带命名空间的着色器 ID
    • 顶点着色器 <namespace>:<path> 将解析到 assets/<namespace>/shaders/<path>.vsh
    • 片段着色器 <namespace>:<path> 将解析到 assets/<namespace>/shaders/<path>.fsh
  • 着色器源文件不再必须位于 shaders/core 子目录中，该目录仅用于组织整理
  • 程序定义中新增了 defines 字段（包含以下字段的对象）
    • 允许将 GLSL 宏定义指令注入到着色器源代码中，可在着色器中引用
    • values（字符串到字符串的映射）
      • 将以 #define <key> <value> 的形式注入到文件顶部
    • flags（字符串列表）
      • 将以 #define <key> 的形式注入到文件顶部

着色器导入

  • #moj_import 指令现在支持使用绝对路径的命名空间包含
    • 例如，#moj_import <minecraft:fog.glsl> 将导入 assets/minecraft/shaders/include/fog.glsl
  • 相对导入不带命名空间，行为与之前相同

后期处理效果定义

  • 后期处理效果配置已从 assets/<namespace>/shaders/post 目录移动到 assets/<namespace>/post_effect
  • 这些效果使用的顶点和片段着色器已从 assets/<namespace>/shaders/program 移动到 assets/<namespace>/shaders/post
  • name 已更名为 program，现在是一个着色器程序配置的命名空间 ID
    • <namespace>:<path> 将解析为 assets/<namespace>/shaders/<path>.json
