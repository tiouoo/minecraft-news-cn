在本周的快照中，我们将一项期待已久的功能带入了同步：倒下的树木将在 Java 版中首次亮相。此外，萤火虫灌木丛现在可以在红树林沼泽中生成，并罕见地在恶地中生成。

在技术方面，命令中的 SNBT 语法已得到扩展和改进，包括修复了与 SNBT 文本组件阻止转义生效相关的错误。

新特性

  • 添加了倒下的树木，以与基岩版功能同步

倒下的树木

  • 倒下的树木是树木的一种新的装饰性变种
  • 倒下的树木有四种不同的木材类型变种：
    • 橡木
    • 白桦木
    • 丛林木
    • 云杉木
  • 白桦倒木可以有较短的版本或较长的版本
  • 一些倒下的树木可能带有蘑菇或藤蔓作为装饰
  • 倒下的树木可以在其对应的立木变种生长的所有生物群系中找到，但以下情况除外：
    • 草甸
    • 竹林
    • 河流
    • 树林
    • 繁花森林有倒下的白桦树，但没有倒下的橡树

NBT 更改

  • 游戏中任何处理 NBT 数据的接口（SNBT 表示法、/data）现在都支持异质列表，即元素类型不相同的列表
    • 使用 /data 向不同类型的列表插入或替换元素将不再产生错误
    • 向数组类型（例如 [I;1,2,3]）插入仍然受类型限制
    • 这意味着，以前用于表示异质列表的“包装器”对象将无法再通过游戏内手段观察到
  • /data 无法再遍历带有空键的路径（例如 /data get ... foo.''.bar）
  • NBT 文件格式不变：
    • 异质列表在存储前会进行转换，以绕过 NBT 的限制
    • 转换示例：['a', {'b':3}] 会存储为 [{'':'a'},{'b':3}]
    • 现有的外部工具仍然可以像以前一样读取 NBT 文件，但异质列表将以转换后的形式显示
  • 游戏生成的数据没有变化：诸如文本组件之类的对象已经在以这种形式生成异质列表
  • 注意：这些包装器对象可能永远无法在游戏内观察到，它们仅与直接处理 NBT 文件或网络格式的开发者相关

SNBT 更改

  • 命令中描述类似对象数据（如 NBT、文本组件、谓词等）的文本格式已扩展

数字格式

  • 浮点数的小数部分或整数部分可以被省略
    • 例如：.1 和 1. 现在都是有效的
  • 浮点数现在支持 E 科学计数法
    • 例如：1.2e3、1.2E3、1.2E+3 和 12000e-1 现在都是表示 1200.0 的有效方式
  • 整数现在可以加上 0x 前缀表示十六进制数，以及 0b 前缀表示二进制数
    • 例如：0xbad（等于 2989）、0xCAFE（等于 51966）、0b101（等于 5）
  • 整数现在不能以 0 开头
    • 通常这表示八进制数，但我们现在进行了限制，以避免误用
  • 数字现在可以在数字序列之间包含 _ 字符（但不能在序列的开头或结尾）
    • 例如：0b10_01、0xAB_CD、1_2.3_4__5f、1_2e3_4
  • NaN、Inf 或十六进制浮点表示法不受支持
  • 类型后缀已扩展：
    • 整数类型后缀（b 或 B - 字节，s 或 S - 短整型，i 或 I - 整型，l 或 L - 长整型）现在可以加上 s（有符号）或 u（无符号）前缀
    • 新后缀仅影响解析时的有效范围——值仍以有符号形式存储
      • 例如：240ub 等于 -16sb，而 240sb 无法解析
    • 当后缀未使用 u 或 s 时，对于十进制数默认为有符号，对于二进制和十六进制数默认为无符号
    • 注意：由于 b 也是有效的十六进制数字，字节大小的十六进制值只能使用有符号后缀编写，例如 0x11ub 或 0x11sb

字符串

  • 带引号的字符串现在可以使用超出 \'、\" 和 \\ 的转义序列：
    • Unicode 转义：
      • \x - 两位转义，如 \x42
      • \u - 四位转义，如 \u2603
      • \U - 八位转义，如 \U00002603
      • \N{<name>} - 命名的 Unicode 字符，如 \N{Snowman}
    • 内置转义序列：
      • \b - 退格，Unicode \x08
      • \s - 空格，Unicode \x20
      • \t - 水平制表符，Unicode \x09
      • \n - 换行，Unicode \u0a
      • \f - 换页，Unicode \u0c
      • \r - 回车，Unicode \u0d
  • 不带引号的字符串现在不能以 0-9、.、+、- 开头，以避免与数字意外冲突

数字数组

  • 数组（[B;]、[I;]、[L;]）中没有后缀的值现在会被认定为具有与数组类型匹配的后缀
    • 例如：[B;1,2] 等同于 [B; 1b, 2b]
  • 数组现在也可以接受小于数组类型的类型
    • 例如：[I;1b,2s,3] 是有效的，等同于 [I;1i,2i,3i]

列表

  • 列表现在接受尾随逗号
    • 例如：[1,2,] 是有效的，等同于 [1,2]
    • 只允许一个尾随逗号，且必须位于有效元素之后——[,] 和 [1,,] 都是无效的

复合标签

  • 复合标签（映射）现在接受尾随逗号
    • 例如：{a:b,}
    • 只允许一个尾随逗号，且必须位于有效的键值对之后——{,} 和 {a:b,,} 都是无效的
