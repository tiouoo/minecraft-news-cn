铜箱子

  • 铜箱子是一种新型箱子，拥有上蜡和氧化变种
  • 铜箱子会随时间氧化，可以像其他铜方块一样上蜡
  • 铜箱子可以使用箱子和 8 个铜锭合成

铜傀儡

  • 铜傀儡是一种新生物，可以通过将南瓜灯或雕刻南瓜放置在铜方块顶部来生成
  • 铜傀儡会随时间氧化，可以像铜方块一样上蜡
  • 如果铜傀儡完全氧化且未上蜡，它会变成铜傀儡雕像
    • 变成雕像后，铜傀儡会掉落其持有的任何物品
    • 雕像保留铜傀儡的名字
  • 铜傀儡可以帮助将物品分类到箱子中
  • 空手与铜傀儡互动会使其掉落携带的物品
  • 铁傀儡偶尔会在附近的铜傀儡身上放置一朵装饰花
    • 花朵可以使用剪刀移除
    • 铜傀儡变成铜傀儡雕像时，花朵会掉落

铜傀儡物品分类

  • 如果铜傀儡没有持有物品，它会寻找附近的铜箱子来尝试拾取物品
    • 铜傀儡会在任何氧化和上蜡的铜箱子变种中寻找拾取物品
    • 它一次最多拾取一组中的 16 个物品
    • 铜箱子中的任何物品都可以被拾取
  • 如果铜傀儡持有物品，它会寻找附近的箱子来尝试放置物品
    • 铜傀儡会在箱子和陷阱箱中寻找放置物品的地方
    • 如果箱子为空，或装有与铜傀儡手持物品相同类型的物品，它就可以放置物品
  • 铜傀儡会依次访问最多 10 个箱子或铜箱子来尝试拾取或放置物品
  • 如果找不到匹配的箱子，铜傀儡会闲置 7 秒后再次尝试
  • 从铜傀儡位置开始搜索箱子的区域为水平 32 格，垂直 8 格

铜傀儡雕像方块

  • 铜傀儡雕像是一种新型装饰方块，拥有上蜡和氧化变种
  • 铜傀儡雕像会随时间氧化，可以像铜方块一样上蜡
  • 如果铜傀儡雕像没有氧化，使用斧头与其互动时，雕像会变回铜傀儡
  • 铜傀儡雕像可以有四种姿势：站立、坐下、奔跑和星光
    • 可以通过与其互动来改变雕像的姿势
    • 每种姿势都会发出红石比较器信号

置物架

  • 置物架是一种新型装饰方块，有以下变种：
    • 橡木
    • 云杉木
    • 白桦木
    • 丛林木
    • 金合欢木
    • 深色橡木
    • 红树木
    • 樱花木
    • 苍白橡木
    • 竹
    • 绯红木
    • 诡异木
  • 置物架可以使用六个匹配的任意去皮原木、去皮菌柄或去皮竹块合成，填满顶部和底部一行
    • 此配方产出 6 个置物架
  • 置物架最多可以存储 3 组物品：
    • 与其前面的 3 个槽位中的任意一个互动，会将玩家主手中的物品与该槽位的内容交换
    • 置物架会将其包含的所有物品显示在其前方，类似于物品展示框
  • 当置物架被红石充能时，其正面纹理会改变以反映其被充能的状态
    • 充能时，最多 3 个置物架会相互连接
    • 与单个充能置物架互动会将其所有内容与玩家快捷栏最右侧的 3 个物品交换
    • 与两个连接的置物架互动会将其内容与玩家快捷栏最右侧的 6 个物品交换
    • 与三个连接的置物架互动会将其内容与玩家快捷栏中的所有物品交换
    • 玩家与哪个连接的置物架互动无关紧要

Minecraft 服务器管理协议

为专用服务器加入了一个服务器管理 API（基于 WebSocket 的 JSON-RPC）

  • 该 API 默认禁用，可以在 server.properties 中启用
    • management-server-enabled=true
    • management-server-host=localhost
    • management-server-port=0
  • 启用后，API 可在 ws://<management-server-host>:<management-server-port> 访问
  • 支持查询和更新服务器状态（玩家、白名单、管理员、设置、游戏规则）
  • 在状态变化时发送通知（例如玩家加入、游戏规则更新）
  • 调用 {"id":1,"method":"rpc.discover"} 会返回一个 API 模式，其中包含当前运行服务器支持的方法和通知
  • 数据生成器会在报告输出文件夹中生成一个 API 模式（json-rpc-api-schema.json），镜像 rpc.discover 方法返回的内容
  • API 符合 JSON-RPC 2.0 规范
  • 使用带命名空间的方法，保留的命名空间为 minecraft（例如 minecraft:players、minecraft:allowlist/add）
    • 可通过自定义命名空间扩展额外的方法和事件
  • 核心方法组：players、allowlist、operators、server（保存、停止）、服务器设置、游戏规则
  • 方法调用示例：
    • 请求： {"method":"minecraft:allowlist/add","id":1,"params":[[{"name":"jeb_"}]]}
    • 响应： {"jsonrpc":"2.0","id":1,"result":[{"id":"853c80ef-3c37-49fd-aa49-938b674adae6","name":"jeb_"}]}
  • 通知示例：
    • {"jsonrpc":"2.0","method":"minecraft:notification/players/joined","params":[{"id":"853c80ef-3c37-49fd-aa49-938b674adae6","name":"jeb_"}]}
  • 错误示例：
    • 请求： {"method": "minecraft:foo/bar","id": 1}
    • 响应： {"jsonrpc":"2.0","id":1,"result":{"jsonrpc":"2.0","id":1,"error":{"code":-32601,"message":"Method not found","data":"Method not found: minecraft:foo/bar"}}}
    • 错误和错误代码遵循 JSON-RPC 2.0 错误对象格式
  • 客户端必须验证身份才能访问 API
    • 客户端应提供带有服务器特定密钥的 Authorization Bearer 令牌头
    • 密钥在 server.properties 中配置
      • management-server-secret=
      • 密钥应为恰好 40 个字母数字字符（A-Z、a-z、0-9）
      • 如果服务器属性为空，将自动生成密钥
      • 未经授权的请求将被以 401 Unauthorized 拒绝
  • 默认启用 TLS
    • 可以在 server.properties 中禁用
      • management-server-tls-enabled=false
    • 需要在 server.properties 中设置密钥库文件
      • management-server-tls-keystore=path/to/keystore.p12
    • 密钥库文件必须为 PKCS12 格式
    • 密钥库密码可以按以下优先级顺序设置
      • 环境变量： MINECRAFT_MANAGEMENT_TLS_KEYSTORE_PASSWORD
      • JVM 参数： -Dmanagement.tls.keystore.password=
      • 服务器属性： management-server-tls-keystore-password=

聊天草稿

  • 未发送的聊天消息现在会在聊天被强制关闭时保存为聊天草稿
    • 这包括因外部来源而关闭的情况，如死亡或对话框打开，但不包括玩家主动关闭聊天
  • 下次打开聊天时，任何现有的聊天草稿都会预填入消息框中
  • 草稿文本在完全恢复前呈灰色显示
    • 可以通过与其互动将草稿文本恢复为常规文本：
      • 输入额外文本
      • 使用方向键移动文本光标
      • 点击它
      • 高亮它
    • 在聊天草稿恢复前按回车会像普通聊天消息一样发送它
    • 在聊天草稿恢复前按退格键会删除它
  • 在聊天设置界面加入了一个选项，默认启用保存未发送的聊天消息
    • 启用此选项后，未发送的消息将始终保存为聊天草稿，即使玩家主动关闭了聊天

服务器行为准则

当连接到服务器时，现在可以显示行为准则界面。

  • 必须接受行为准则才能在该服务器上游玩
  • 提供一个复选框，用于以后不再显示相同的行为准则
    • 如果行为准则发生变化，将再次显示

服务器设置

  • 在 server.properties 中加入了名为 enable-code-of-conduct 的新布尔字段
    • 将其设置为 true 会使服务器在 server.properties 所在文件夹的 codeofconduct 子文件夹中查找行为准则文件
    • 文件夹中的每个文件应采用 <language_code>.txt 的形式，并使用 UTF-8 编码
      • 显示的语言将尝试匹配玩家的语言
      • 如果不存在，将使用 en_us 行为准则
      • 如果也不存在，则使用任意可用的条目

声音

  • 音乐和声音选项中的一些声音滑块现在在游戏世界之外调整设置时会播放预览声音

辅助功能

  • "攻击/破坏"和"使用物品/放置方块"按键绑定现在可切换，这意味着它们可以在控制界面中设置为"按住"或"切换"
  • 在鼠标设置界面加入了"反转鼠标 X 轴"选项，用于反转鼠标 X 轴
  • 在控制界面加入了"疾跑窗口"选项，表示双击前进键激活疾跑的时间窗口（以刻为单位）
  • 多个绑定到同一按键的按键绑定现在可以同时工作，而之前只有一个会生效
    • 例如，你现在可以将 D 绑定为 跳跃 和 左平移 来同时跳跃和左平移
    • 将相同按键分配给多个按键绑定的红色警告更改为黄色
  • 旁观者快捷栏菜单键现在可以重新绑定
    • 它是按键绑定界面中新的 旁观者 类别的一部分，与现有的 高亮玩家 按键绑定一起

更改

  • 性能改进
  • 锁链方块已更名为"铁锁链"
  • 在和平难度下，生物刷怪蛋现在会有工具提示警告
  • 对世界加载和"出生点区块"的更改
  • 拥有任何玩家活动、强制加载区块、活跃传送门或飞行中的末影珍珠的维度将被视为"活跃"，并将继续处理区块和实体
    • 之前，这仅适用于玩家在维度中或区块被强制加载的情况
  • 重新设计了调试叠加层，以减少杂乱并提高可配置性
  • 在当前服务器的游戏世界中可见的玩家现在始终显示在社交互动界面中，即使他们处于离线状态
  • 当玩家在接近地面时从旁观模式切换到创造模式时，现在会停止飞行
    • 如果玩家下方 1 格内有可碰撞表面（即方块、快乐恶魂、船等），则认为玩家接近地面
    • 如果玩家在方块或可碰撞实体内，飞行不会被禁用
      • 这是为了防止玩家突然从地面掉下去
  • 将多个服务器属性迁移到游戏规则中
  • 现在需要 OpenGL 3.3 才能运行游戏，从 3.2 提升而来。这不会改变我们公布的最低配置要求

开发者备注： 我们预计 OpenGL 版本更新不会对很多人产生影响，如果有的话。我们公布的最低配置要求自 2017 年以来一直是 OpenGL 4.0，而 OpenGL 3.3 最近刚满 15 岁。

性能改进

  • 实体渲染顺序已改进，可获得显著更好的性能
    • 你会在大量生物的区域中看到更流畅的游戏体验，例如生物农场
    • 如果你的大部分卡顿来自实体以外的因素，例如在高渲染距离下游玩而附近没有很多生物，FPS 不会有太大改善
  • 玩家视野之外的粒子不再渲染，这在某些情况下提供了性能改进

世界加载和出生点区块

  • 固定"出生点区块"的概念已被移除
  • 游戏将确保以下区块在玩家加入或服务器启动前完全加载，方式与之前的出生点区块相同：
    • 由 forceload 命令加载的区块
    • 由于传送门活动而活跃的区块
    • 抛出的末影珍珠（仅单人游戏）
    • 玩家周围的一小片区域区块（仅单人游戏）
    • 分配全局世界出生点所需的区块（仅世界创建时）
  • 世界加载界面现在显示玩家即将进入的区块，而不是世界出生点周围加载的区块
  • 加载界面现在有了进度条
    • 此进度条涵盖上述所有类型的区块加载

开发者备注： 出生点区块会为所有玩家带来内存和性能成本，并且已经超出了其最初的技术目的，即保持出生点区域准备就绪以供玩家快速加入。

然而，我们也认识到出生点区块多年来促成了大量巧妙的装置和农场，因此仅仅移除它们而不在游戏中加入其他机制来支持这些设计从来都不是一个选项。

我们相信，出生点区块所占据的特殊位置现在已被替代性的区块加载方法所填补，例如使用传送门或末影珍珠，尤其是在本次发布中对游戏在世界开始运行前加载这些区块的方式所做的更改。

服务器属性

多个服务器属性被移除，转而作为游戏规则，允许在服务器运行时更改这些设置。

  • 移除了服务器属性 allow-nether，取而代之的是新的游戏规则 allowEnteringNetherUsingPortals
  • 移除了服务器属性 spawn-monsters，取而代之的是新的游戏规则 spawnMonsters
  • 移除了服务器属性 enable-command-block，取而代之的是新的游戏规则 commandBlocksEnabled
  • 移除了服务器属性 pvp，取而代之的是新的游戏规则 pvp
  • 加入了服务器属性 management-server-enabled，控制是否启用新的 Minecraft 服务器管理协议
    • 默认为 false
  • 加入了服务器属性 management-server-port，控制 Minecraft 服务器管理协议启动的端口
    • 默认为 0，每次管理服务器启动时分配一个可用端口
  • 加入了服务器属性 management-server-host，控制新的 Minecraft 服务器管理协议启动时使用的主机
    • 默认为 localhost
  • 加入了服务器属性 management-server-tls-enabled，控制 Minecraft 服务器管理协议是否使用 TLS
    • 默认为 true
  • 加入了服务器属性 management-server-tls-keystore，控制用于 TLS 的密钥库文件路径
    • 默认为空字符串
    • 当 TLS 启用且未提供密钥库时，专用服务器将无法启动
  • 加入了服务器属性 management-server-tls-keystore-password，控制用于 TLS 的密钥库文件密码
    • 默认为空字符串
  • 加入了服务器属性 status-heartbeat-interval，控制管理服务器向已连接客户端发送心跳通知的间隔
    • 默认为 0，表示禁用
  • 加入了服务器属性 enable-code-of-conduct
    • 有关此属性的详细信息请参见"服务器设置"标题

游戏规则

  • 加入了 pvp 游戏规则，控制玩家是否可以伤害其他玩家

    • 默认为 true

    • 默认为 true
  • 加入了 spawnerBlocksEnabled 游戏规则，控制刷怪笼方块是否应启用
    • 默认为 true

生物生成

数据组件

修改了 minecraft:profile

新的解析行为

  • 以前，该组件的内容会在档案被解析时（即从 Minecraft 服务下载时）永久改变
  • 为了避免这种意外更改带来的问题，解析后的值不再被存储，档案的内容将始终保持不变
  • 这意味着此组件现在有两种行为：
    • 静态：当它具有 properties 字段，或 name 和 id 同时存在，或两者同时缺失时
      • 在此状态下，档案将始终按原样渲染
      • 如果 properties 字段缺失，将使用默认皮肤（根据 id 选择，与离线模式相同）
      • 这意味着皮肤将在组件创建时冻结
      • 此选项最适合装饰用途
    • 动态：当 name 或 id 中仅设置了其中一个（但不能同时设置两个）时
      • 当包含此档案的物品在客户端侧渲染时，档案将被解析为最新值
      • 这意味着此物品将始终以目标玩家的当前皮肤渲染
        • 注意：如果玩家在游戏运行时更改了皮肤，则更改在客户端重启之前不会可见
      • 解析可能会有延迟，期间物品将以默认皮肤渲染
      • 只有当档案名称存在时，档案名称才会替换物品名称
        • 仅带 id 的物品将显示默认名称
      • 带有动态档案的物品通过其工具提示中的标签与静态档案区分
  • 物品根据确切内容堆叠，因此即使动态组件最终被解析为与静态组件相同的档案，它们也不会堆叠在一起
  • 旧地图中尚未在新版本中加载过的玩家头颅通常会转换为动态内容

玩家皮肤覆盖

  • 档案现在还可以包含可以替换用于渲染的各种值的附加字段

  • 新字段

    • elytra - 可选的用于渲染的鞘翅纹理命名空间 ID

    • model - 可选的模型类型，wide 或 slim 之一

  • density - 要近似其表面的密度函数
  • upper_bound - 提供最高可能 y 值的 2D 密度函数
  • lower_bound - 整数，最低可能 y 值
  • cell_height - 正整数，定义扫描的网格分辨率

开发者备注： 虽然在资源包中是可能的，但覆盖核心着色器被视为不受支持的功能，不是资源包的预期功能。这些着色器作为游戏内部实现的一部分存在，因此随着游戏内部的演进可能随时更改。我们理解覆盖核心着色器被用于制作非常酷的资源包功能，其中许多缺乏受支持的替代方案。我们希望在将来提供更好的、受支持的替代方案。
