是时候体验主世界的新奇观了，我们发布了 Spring to Life 更新，这是 Minecraft 在 2025 年的首次游戏更新。

Spring to Life 更新带来了更多探索远近之地的理由！温暖的风吹过生物群系，带来了新的生物变种、环境音效和繁茂的植物等待你去发现。与毛茸茸的猪交朋友，惊叹于闪闪发光的萤火虫灌木，倾听沙子的低语，并沉醉于充满新生气息、生机盎然的主世界。

在此版本中，我们还通过新的 test 命令，让游戏测试系统可以通过数据包使用。像往常一样，我们会继续重建引擎，以改善玩家和内容创作者的体验。我们确信地上那些多余的零件不可能那么重要，对吧？

  • 添加了倒木生成

寒冷与温暖生物群系中的羊羊毛颜色

  • 羊现在会根据其生成的生物群系来决定羊毛颜色：
    • 温带生物群系：（这些颜色与之前的行为相同）
      • 常见羊颜色为白色
      • 不常见羊颜色为黑色、灰色、浅灰色和棕色
      • 有稀有几率生成粉红色羊
    • 寒冷生物群系：
      • 常见羊颜色为黑色
      • 不常见羊颜色为灰色、浅灰色、白色和棕色
      • 有稀有几率生成粉红色羊
    • 温暖生物群系：
      • 常见羊颜色为棕色
      • 不常见羊颜色为灰色、浅灰色、白色和黑色

狼音效变种

  • 添加了 6 种新的狼音效变种，每种都有独特的环境、受伤、死亡、低吼、呜咽和喘息音效
    • 新音效属于名为“Big”、“Cute”、“Puglin”、“Angry”、“Grumpy”和“Sad”的变种
    • 原始狼音效现在用于名为“Classic”的变种
    • 每只狼都会从这 7 个变种中随机分配一个音效变种
    • 音效变种与纹理变种无关

刷怪蛋外观全面翻新

  • 每种刷怪蛋现在都有自己独特的外观，以展现其所生成生物的性格与特征
  • 每个蛋的外观形状各不相同，以反映所生成生物在游戏世界中的尺寸
    • 例如，较小的生物通常拥有较小的刷怪蛋

倒木

  • 倒木是一种新的装饰性树木变体
  • 倒木有四种不同的木材类型变种：
    • 橡木
    • 白桦木
    • 丛林木
    • 云杉木
  • 白桦倒木有较短和较长两种版本
  • 有些倒木可以用蘑菇或藤蔓装饰
  • 倒木可以在其对应直立树木生长的所有生物群系中找到，但以下生物群系除外：
    • 竹林
    • 繁花森林（有白桦倒木，但没有橡木倒木）
    • 雪林
    • 草甸
    • 河流

萤火虫灌木

  • 萤火虫灌木生成在沼泽、红树林沼泽、恶地中邻近水的地方，以及河流附近
  • 天黑时，萤火虫灌木周围会出现发光的萤火虫粒子
  • 对萤火虫灌木使用骨粉会在随机相邻空间生长出萤火虫灌木（如果可能）
  • 萤火虫灌木发出 2 级光照
  • 当满足以下条件时，萤火虫灌木有几率播放环境音效：
    • 处于夜晚
    • 其上方没有被任何可碰撞方块阻挡（树叶除外）

落叶

  • 落叶是一种新的装饰性方块，可以在森林、黑森林和疏林恶地中找到
    • 注意：落叶仅在世界生成时生成，不会在游戏过程中重新生成
  • 落叶在单个方块空间内可以有不同数量的落叶片
    • 同一方块空间内最多可以放置四片落叶
    • 将落叶放入已有落叶的方块中会增加落叶数量
  • 落叶可以按四种朝向放置
  • 落叶可以放置在任何顶部为完整面的方块上
  • 落叶可以通过熔炼任意类型的树叶方块获得
  • 落叶可以用作熔炼燃料
  • 落叶可以用于堆肥桶
  • 落叶有独特的方块音效
  • 落叶会根据其所在的生物群系进行着色
  • 落叶在建筑时可以被替换

野花

  • 野花是一种新的花，生长在白桦森林、原始白桦森林和草甸中
  • 野花在单个方块空间内可以有不同数量的花朵
    • 同一方块空间内最多可以放置四朵野花
    • 将野花放入已有野花的方块中会增加花朵数量
    • 对野花使用骨粉会产生更多野花
  • 野花可以按四种朝向放置
  • 野花可以合成黄色染料

灌木

  • 灌木是一种新的装饰性方块，可以在以下生物群系的小片区域中找到：
    • 白桦森林
    • 森林
    • 冻河
    • 原始白桦森林
    • 平原
    • 河流
    • 风袭森林
    • 风袭沙砾丘陵
    • 风袭丘陵
  • 灌木可以用于堆肥桶
  • 对灌木使用骨粉会在随机相邻空间生长出灌木（如果可能）
  • 灌木只能通过剪刀或精准采集工具破坏时掉落
  • 灌木在建筑时可以被替换

矮干草和高干草

  • 添加了两种新类型的草：矮干草和高干草
  • 两者都是 1 格高，这意味着高干草与通常为 2 格高的普通高草丛不同
  • 两者都会在沙漠和恶地生物群系中生成
  • 两者都可以放置在各类沙、陶瓦、泥土方块和耕地方块上，就像枯萎的灌木一样
  • 两者都可以使用骨粉催熟
    • 对矮干草使用骨粉会使其生长为高干草
    • 对高干草使用骨粉会在随机相邻空间生长出矮干草（如果可能）
  • 两者都可以用于堆肥桶
  • 羊可以通过吃它们来重新长出羊毛
  • 两者都可以用作熔炼燃料
  • 两者在建筑时都可以被替换

仙人掌花

  • 仙人掌花是一种新的花，有几率生成在沙漠和恶地的仙人掌上
  • 仙人掌花可以放置在仙人掌方块、耕地方块或任何顶部有中心支撑的方块上
  • 仙人掌花有几率在仙人掌方块上生长，而不是让仙人掌长得更高
    • 如果仙人掌高 1-2 格，仙人掌花有 10% 的几率生长
    • 如果仙人掌高 3 格或以上，仙人掌花有 25% 的几率生长
    • 仙人掌花只会在四周都有空间时生长
  • 仙人掌花可以用于堆肥桶
  • 仙人掌花可以合成 1 个粉色染料

落叶粒子

  • 所有树叶方块现在都有几率生成落叶粒子
  • 以下方块受此更改影响：
    • 金合欢树叶
    • 杜鹃树叶
    • 白桦树叶
    • 深色橡树树叶
    • 盛开的杜鹃树叶
    • 丛林树叶
    • 红树林树叶
    • 橡树树叶
    • 云杉树叶

沙漠与恶地的新环境音效

  • 沙子、红沙和任意颜色的陶瓦在被同一组中的另一个方块至少三面环绕时，有几率在 8 格距离内播放环境音效
    • block.sand.idle 可以在任何生物群系中播放
    • block.sand.wind 仅在沙漠或恶地生物群系中播放
  • 枯萎的灌木在放置于任意颜色的陶瓦、沙子或红沙方块组成的两个方块之上时，有几率播放环境音效（可在任何生物群系中触发）

制图师与流浪商人交易平衡调整

制图师交易

  • 制图师现在出售 7 种新地图，每种地图分别指向不同生物群系中的不同村庄或其他结构

  • 部分价格和数量也已调整

流浪商人交易

  • 流浪商人现在拥有更好的价格、更多的交易，并且许多物品的库存数量更大
  • 他们现在也会向玩家购买基本补给品，因此即使你不想买东西，也可以通过帮助他们为下一次旅程做准备来获得一些绿宝石
  • 流浪商人会提出购买以下列表中的两种物品：
    • 水瓶
    • 水桶
    • 奶桶
    • 发酵蛛眼
    • 烤马铃薯
    • 干草捆
  • 流浪商人现在有几率出售以下物品（除原有交易外）：
    • 原木（金合欢、白桦、深色橡木、丛林、橡木、云杉、苍白橡木或樱花）
    • 附魔铁镐
    • 隐身药水

世界生成更改

  • 草甸中的矮草现在生成得略稀疏一些

模拟距离

  • 玩家模拟距离内的任何方块，或由其他区块加载源（如末影珍珠）加载的方块，现在都可能接收随机刻，而不再仅限于玩家周围 8 个区块
    • 例如：如果某个区块由末影珍珠加载或位于出生点区块，作物可以生长、冰可以融化、雪可以落下，炼药锅可以被雨水填满
    • 生物生成、熔岩蔓延火焰和闪电击中仍发生在玩家周围 8 个区块的原有半径内
  • 如果 8 个区块内没有玩家，火焰将不再燃烧或蔓延

吱吱怪与吱吱之心

  • 吱吱怪现在可以使用命名牌命名

      • 不过，如果它们与玩家发生碰撞或距离其心脏太远，仍会被分解
    • 被命名的吱吱怪仍然对所有伤害免疫，并可以通过粒子与其心脏交流
  • 正确放置在原木之间的吱吱之心在白天有新的休眠纹理
    • 休眠的吱吱之心无法生成新的吱吱怪或树脂
  • 吱吱之心的唤醒与休眠状态转换，以及眼斑花的状态转换，现在基于固定的白天时间

游戏测试

游戏测试系统是一个用于测试游戏各方面的新集成系统。每个测试都是一个资源，定义了测试执行方式的一些参数，并结合一个包含基础设置的已保存结构文件。

通常，测试框架会期望在单独的超平坦世界中运行测试。

测试实例

测试实例定义在 test_instance 注册表中。它们是需要运行的测试的小型资源。

字段：

  • environment：测试环境的命名空间 ID，该测试将作为此环境的一部分运行
  • structure：用于测试的结构的命名空间 ID
  • max_ticks：正整数，表示允许经过的最大刻数，超过此值则测试被视为超时
  • setup_ticks：可选非负整数（默认值：0），表示在放置结构后、开始测试前需要等待的刻数
  • required：可选布尔值（默认值：true）——此测试是否被视为完整测试套件通过所必需的测试
  • rotation：可选，应用于测试结构的旋转
    • 可以是 none（默认值）、clockwise_90、180 或 counterclockwise_90
  • manual_only：可选布尔值（默认值：false），对于不包含在自动测试运行中的测试设置为 true
  • sky_access：测试是否需要无障碍的天空通道
    • 默认情况下（false），测试会被屏障方块包围——如果设置为 true，顶部会保持开放
  • max_attempts：运行测试的尝试次数（默认值：1）
  • required_successes：测试被视为成功所需的成功尝试次数（默认值：1）
  • type：测试类型——可以是 block_based 或 function

函数测试

函数测试依赖于内置函数来运行测试并指示成功或失败。它们有一个额外字段：

  • function：要运行的测试函数的命名空间 ID

更多信息请参阅“从代码中使用游戏测试框架”更新日志部分。

基于方块的测试

基于方块的测试使用测试结构中的测试方块来运行测试并指示成功或失败。

测试环境

测试环境是一种将测试分组并为其提供正确运行前置条件的方式。测试环境是 test_environment 注册表中的资源。每个测试环境定义都有一个 type 字段，决定其设置：

  • all_of 定义通过 definitions 字段应用多个子定义的设置
  • function 定义使用 mcfunction 文件作为设置和拆除
    • setup：可选，用于设置的 mcfunction 的命名空间 ID（如果有）
    • teardown：可选，用于拆除的 mcfunction 的命名空间 ID（如果有）
  • game_rules：定义设置任意数量的游戏规则
    • bool_rules：要设置的布尔游戏规则列表及其值
    • int_rules：要设置的整数游戏规则列表及其值
    • 每条规则是一个具有两个字段的对象：
      • rule：要设置的规则的确切名称
      • value：要设置的值
    • 游戏规则会在测试环境完成后重置为其默认值
  • weather 定义设置天气状态
    • weather：要设置的天气——可以是 clear、rain 或 thunder
  • time_of_day 定义设置给定的白天时间
    • time：要设置的白天时间，以刻为单位，为非负整数

游戏默认提供一个空的测试环境：minecraft:default。

测试方块

测试方块是用于实现基于方块的测试的方块。它有四种模式：

  • start：测试开始时触发红石脉冲
  • log：被红石充能时将消息记录到日志文件
  • fail：被红石充能时使测试失败
  • accept：被红石充能时完成测试

基于方块的测试在结构中必须至少有一个 start 方块和一个 accept 方块。

test 命令

test 命令是一个用于创建和运行测试的新命令。

语法：

test clearall [<radius>]
test clearthat
test clearthese

test create <test> [<width>] [<height> <depth>]

test locate <selector>

test resetclosest
test reseetthese
test resetthat

test pos [<variable>]

test run <selector> [<numberOfTimes>] [<untilFailed>] [<rotationSteps>] [<testsPerRow>]
test runclosest [<numberOfTimes>] [<untilFailed>]
test runfailed [<numberOfTimes>] [<untilFailed>] [<rotationSteps>] [<testsPerRow>]
test runmultiple <selector> [<amount>]
test runthat [<numberOfTimes>] [<untilFailed>]
test runthese [<numberOfTimes>] [<untilFailed>]

test stop

test verify <tests>

参数：

  • radius：要清除测试的半径范围
  • test：测试的命名空间 ID
  • selector：用于测试 ID 的通配符选择器
    • 支持 * 和 ? 匹配命名空间 ID
    • 如果未提供命名空间，默认使用 minecraft
    • 示例：
      • *:* - 匹配所有 ID
      • * - 匹配 minecraft 命名空间中的所有内容
      • custom:folder/*_test_? - 匹配 custom 命名空间 folder 文件夹中的 ID，格式为前缀后跟 _test_ 再跟一个有效字符
  • width：测试结构的宽度——如果省略，使用 5
  • height：测试结构的高度——如果省略，使用宽度值
  • depth：测试结构的深度——如果省略，使用宽度值
  • variable：要包含在复制代码片段中的变量名
  • numberOfTimes：每个测试重复的次数——如果省略，使用 1
  • untilFailed：布尔值（默认值：false），表示只要一次迭代失败就应停止测试
  • rotationSteps：应用于测试的额外 90 度步进数——如果省略，使用 0
  • testsPerRow：网格布局中每行放置的测试数——如果省略，使用 8

test clear*

这些子命令会清除与所选测试关联的结构和方块。

test create

此子命令会在当前位置为给定测试创建测试设置，为给定大小的结构做准备。这为创建测试结构提供了一个起点。

test locate

尝试定位给定的测试。注意，只会搜索已加载的区块。

test reset*

这些子命令会重置所选测试的结构，移除任何周围的屏障并从头放置结构。

test pos

显示测试中指向方块的局部坐标。如果指定了可选的变量名，该变量名将用于通过点击输出消息中的坐标获得的代码片段中。

test run*

运行一个或多个测试。如果同时运行多个测试，它们会以网格布局放置并并行运行，但最多只能达到一定数量。超过该数量后，测试将按轮次运行，每一轮完成后再开始下一轮的测试。

对于每个测试，会加载给定的结构并运行关联的测试。每个测试位置都会有信标光束显示测试状态。

  • 灰色信标 = 进行中
  • 红色 = 失败（必需测试）
  • 橙色 = 失败（可选测试）
  • 绿色 = 成功

如果测试失败，错误会显示在讲台书本上和覆盖层中。

注意，游戏测试设计为在标准超平坦世界中运行。每个测试运行时，其周围区域会被替换为石头，并且运行中的测试会被屏障方块包围。

test stop

这会停止所有正在运行的测试。注意，由测试触发的游戏事件可能仍然存在。

test verify*

通过运行同一测试的多个实例来验证一个或多个测试。

测试实例方块

要在世界中运行测试，需要使用测试实例方块。这种方块代表放置在世界中的测试，用于与该测试互动、保存结构、重置或运行测试。

使用 test 命令运行或创建测试时，也会放置一个测试实例方块来控制该测试。

从代码中使用游戏测试框架

游戏测试框架也可以从代码中以比基于方块的测试更多样化的方式使用。为此，你需要对游戏进行模组开发，将测试函数添加到 test_function 注册表（Registries.TEST_FUNCTION）中。

在某个启动方法（注册表预启动）中挂钩以添加你的加载器——使用 TestFunctionLoader 的实现调用 TestFunctionLoader.registerLoader()。然后你的实现可以使用提供的 register 消费者以命名空间 ID 注册测试函数。该命名空间 ID 可以在 function 类型的测试实例中引用。

测试函数是一个 Consumer<GameTestHelper>，使用该 GameTestHelper 实例来操作世界并对结果世界的状态进行断言。

该助手可用于召唤生物、设置方块、查询方块和实体，以及断言测试状态。大多数 GameTestHelper 方法采用测试局部坐标，你也可以使用 /test pos 找到这些坐标。

与一个包含锁定漏斗（其中装有鳕鱼，指向熔炉）的测试结构配合的示例代码：

public void furnaceSmeltsItem(final GameTestHelper helper) {
    helper.setBlock(0, 4, 0, Blocks.AIR);
    helper.succeedWhen(() -> helper.assertContainerContainsSingle(new BlockPos(0, 0, 0), Items.COOKED_COD));
}

更复杂的设置通常会使用 helper.startSequence() 来建模必须发生的事件序列。

与基于方块的测试相比，函数测试失败时通常会产生更有帮助的错误消息，包括失败位置以及该位置预期是什么。

  • 游戏内与 NBT 数据交互的任何接口（SNBT 表示、/data）现在都支持异构列表，即元素类型不同的列表
    • 使用 /data 向不同类型的列表插入或替换元素时将不再报错
    • 向数组类型（例如 [I;1,2,3]）插入仍受类型限制
    • 这意味着以前用于表示异构列表的“包装器”对象将不再能在游戏内被观察到
  • /data 不能再穿越具有空键的路径（例如 /data get ... foo.''.bar）
  • NBT 文件格式不变：
    • 异构列表在存储前会被转换以绕过 NBT 约束
    • 转换示例：['a', {'b':3}] 存储为 [{'':'a'},{'b':3}]
    • 现有的外部工具仍然可以像以前一样读取 NBT 文件，但异构列表会以转换后的形式显示
  • 游戏产生的数据没有变化：文本组件等对象此前已经以这种形式生成异构列表
  • 注意：这些包装器对象永远不会在游戏内被观察到，它们仅与直接处理 NBT 文件或网络格式的开发者相关

SNBT 更改

  • 用于在命令中描述类似对象数据的文本格式（如 NBT、文本组件、谓词等）已扩展
  • 为简化数据输入和宏使用，SNBT 现在也支持以下操作：
    • bool(arg) - 将参数转换为布尔值
      • 如果参数是布尔值，直接返回该值
      • 如果参数是数字值，非零时返回 true
    • uuid(str) - 将 UUID 的字符串表示转换为整数数组

数字格式

  • 浮点数的小数部分或整数部分可以省略
    • 示例：.1 和 1. 现在都是有效的
  • 浮点数现在使用科学计数法表示
  • 示例：1.2e3、1.2E3、1.2E+3、12000e-1 现在都可以表示 1200.0
  • 整数现在可以以 0x 前缀表示十六进制数，以 0b 前缀表示二进制数
    • 示例：0xbad（等于 2989）、0xCAFE（等于 51966）、0b101（等于 5）
  • 非零整数现在不能以 0 开头
    • 通常这意味着数字是八进制，但我们限制此用法以避免误用
  • 数字现在可以在数字序列之间包含 _ 字符（但不能在序列开头或结尾）
    • 示例：0b10_01、0xAB_CD、1_2.3_4__5f、1_2e3_4
  • 不支持 NaN、Inf 或十六进制浮点表示
  • 隐式无穷浮点值（如 1e1000）会被拒绝
  • 类型后缀已扩展：
    • 整数类型后缀（b 或 B - 字节、s 或 S - 短整型、i 或 I - 整型、l 或 L - 长整型）现在可以以 s（有符号）或 u（无符号）作为前缀
    • 新后缀只影响解析时的有效范围——值仍作为有符号数存储
      • 示例：240ub 等于 -16sb，而 240sb 无法解析
    • 当后缀未使用 u 或 s 时，十进制默认有符号，二进制和十六进制默认无符号
    • 注意：由于 b 也是有效的十六进制数字，字节大小的十六进制值只能使用有符号后缀书写，例如 0x11ub 或 0x11sb

字符串

  • 带引号的字符串现在可以使用除 \'、\" 和 \\ 之外的转义序列：
    • Unicode 转义：
      • \x - 两位转义，如 \x42
      • \u - 四位转义，如 \u2603
      • \U - 八位转义，如 \U00002603
      • \N{<name>} - 具名 Unicode 字符，如 \N{Snowman}
    • 内置转义序列：
      • \b - 退格，Unicode \x08
      • \s - 空格，Unicode \x20
      • \t - 水平制表符，Unicode \x09
      • \n - 换行，Unicode \u0a
      • \f - 换页，Unicode \u0c
      • \r - 回车，Unicode \u0d
  • 未加引号的字符串现在不能以 0-9、.、+、- 开头，以避免与数字意外冲突

数字数组

  • 数组（[B;]、[I;]、[L;]）中没有后缀的值现在会被假定具有与数组类型匹配的后缀

    • 示例：[B;1,2] 等价于 [B; 1b, 2b]

  • 数组现在也可以接受小于数组类型的类型

    • 示例：[I;1b,2s,3] 是有效的，等价于 [I;1i,2i,3i]

列表

  • 列表现在接受尾随逗号
    • 示例：[1,2,] 是有效的，等价于 [1,2]
    • 只允许一个尾随逗号，且必须位于有效元素之后——[,] 和 [1,,] 都是无效的

复合标签

  • 复合标签（映射）现在接受尾随逗号
    • 示例：{a:b,}
    • 只允许一个尾随逗号，且必须位于有效的键值对之后——{,} 和 {a:b,,} 都是无效的

文本组件数据格式

  • 文本组件不再存储为由字符串包裹的 JSON
  • 格式本身与之前相同，但直接内联到外部结构中
    • 例如，物品组件 minecraft:custom_name="{\"text\":\"Renamed item\"}" 将变为 minecraft:custom_name={text:'Renamed item'}
  • 这包括作为参数传递给 /tellraw 或 /title 等命令的文本组件
    • 例如，/tellraw @s {"text":"Hello world"} 可以变为 /tellraw @s {text:'Hello world'}
  • 注意：在文本组件嵌入 NBT 的情况下，布尔类型和整数类型之间没有区别
    • 要向翻译文本传递布尔参数，必须使用字符串形式
  • 对于 nbt 类型且 interpret 设置为 true 的文本组件，将直接从给定的 NBT 解析文本组件，而不是先转换为字符串再作为 JSON 解析
  • 悬停和点击事件的格式已更新

      • 列表中的每个条目都会贡献一定数量的被格挡伤害，可选地按伤害类型过滤
      • 每个条目增加被格挡伤害，由 clamp(base + factor * dealt_damage, 0, dealt_damage) 确定
      • 攻击中最终作用于实体的伤害由 dealt_damage - clamp(blocked_damage, 0, dealt_damage) 确定
      • 条目格式：
        • horizontal_blocking_angle - 以度为单位的角度，为正浮点数（默认值：90）
          • 使用者的朝向与来袭攻击之间的最大角度，超过此角度则格挡无效
          • 如果伤害没有位置，则比较角度将假定为最大值 180
        • type - 伤害类型 id、伤害类型 id 列表或以哈希开头的伤害类型标签（可选）
          • 只有当受到的伤害类型与此字段匹配时，此条目才会贡献被格挡伤害
          • 如果未指定，接受任何伤害类型
        • base - 浮点数
          • 要格挡的恒定伤害量
        • factor - 浮点数
          • 应格挡的所受伤害的比例
    • item_damage - 具有以下字段的对象（可选）
      • 控制给定攻击应对物品施加多少伤害
      • 如果未指定，每格挡一点伤害就会消耗一点耐久度
      • 对物品的最终伤害由以下公式确定：floor(base + factor * damage_blocked)
      • 最终值可以为负，从而修复物品
      • 格式：
        • threshold - 非负浮点数
          • 在物品受到伤害之前，攻击中必须格挡的最小伤害量
        • base - 浮点数
          • 如果超过 threshold，则对物品施加的恒定伤害量
        • factor - 浮点数
          • 如果超过 threshold，则应施加于物品的被格挡伤害比例
    • bypassed_by - 以哈希开头的伤害类型标签（可选）
      • 如果指定，这些伤害类型可以绕过格挡
    • block_sound - 音效事件（可选）
      • 如果指定，成功格挡攻击时会播放此音效
    • disabled_sound - 音效事件（可选）
      • 如果指定，当物品因攻击进入禁用冷却时会播放此音效

    着色器与后期处理效果

    开发者注：虽然在资源包中可以覆盖核心着色器，但这被视为不受支持，且不是预期的资源包功能。这些着色器是游戏内部实现的一部分，因此可能随游戏内部的演变而随时更改。我们理解覆盖核心着色器被用于非常酷的资源包功能，其中许多缺少受支持的替代方案。我们希望将来提供更好的、受支持的替代方案。

    • 核心着色器和后期处理效果的着色器程序定义（JSON 文件）已移除
    • 着色器程序本身仍然可用，并且可以被覆盖
    • 后期处理效果仍可作为 JSON 配置
    • “全局”uniform 可以在任何着色器中定义，游戏会尝试填充它
      • 目前，这些是：ModelViewMat、ProjMat、TextureMat、ScreenSize、ColorModulator、Light0_Direction、Light1_Direction、GlintAlpha、FogStart、FogEnd、FogColor、FogShape、LineWidth、GameTime、ModelOffset
      • uniform 的类型必须与其通常应有的类型匹配，否则将是未定义行为

    后期处理效果定义

    • program 字段已替换为 vertex_shader 和 fragment_shader
      • <namespace>:<path> 将解析为 assets/<namespace>/shaders/<path>.<vsh|fsh>
    • 每个 uniform 现在都必须有 type 字段
      • 可能的值目前有 int、ivec3、float、vec2、vec3、vec4、matrix4
    • 每个 uniform 中的 values 现在为可选
      • 不建议将其保持未设置，它用于模糊效果的运行时配置
    • 将 uniform 保持未指定会导致未定义行为，你必须指定着色器将使用的每个 uniform
