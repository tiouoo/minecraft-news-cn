新的矿石分布

  • 改变了矿石生成以匹配新的世界高度，并为采矿增加更多策略。不再有一个对所有矿石都最佳的高度——你需要做出取舍！
  • 铁矿石在高度 72 以下生成，明显偏向高度 16。铁矿石也会在 80 以上生成，越高铁矿石越多。
  • 铜矿石在高度 0 到 96 之间生成，明显偏向高度 48。铜矿石在溶洞生物群系中生成量更大。
  • 青金石矿石在高度 64 以下生成，明显偏向高度 0。但是，高度 -32 以下或 32 以上的青金石矿石不能暴露在空气中生成。它要么被掩埋，要么在水中。
  • 煤矿石在高度 0 以上生成，明显偏向高度 96 及以上。煤矿石暴露在空气中的概率降低，因此你会发现掩埋或水下的煤矿石比暴露在空气中的更多。
  • 金矿石在高度 32 以下生成，明显偏向高度 -16。额外的金矿石在高度 -48 以下生成。额外的金矿石可以在高度 32 以上的恶地生物群系中找到。
  • 红石矿石在高度 16 以下生成。随着你从高度 -32 继续往下，红石矿石的生成量逐渐增加。
  • 钻石矿石在高度 16 以下生成，越往下钻石矿石越多。钻石矿石暴露在空气中的概率降低，因此你会发现掩埋或水下的钻石矿石比暴露在空气中的更多。
  • 绿宝石矿石在高度 -16 以上的山地生物群系中生成，越高绿宝石矿石越多。高度 0 以下的绿宝石矿石非常罕见！

噪声洞穴与含水层

  • 噪声洞穴是一种新的洞穴生成方式，提供更自然的多样性。它们有时会变得非常巨大！噪声洞穴有三种类型：
    • 奶酪洞穴：就像瑞士奶酪中的孔洞。这些通常会形成大小不一的洞窟。
    • 意面洞穴：长长的弯弯曲曲的隧道，有时像意大利宽面一样宽
    • 面条洞穴：比意面洞穴更细、更曲折、更令人感到幽闭的类型
  • 不，它们并不吵。“噪声”中的“噪声”是一个技术术语，与声音无关。
  • 旧的洞穴雕刻器和峡谷仍然会生成，与噪声洞穴结合形成有趣的洞穴系统
  • 与雕刻器一样，噪声洞穴在与地表相交处形成洞穴入口
  • 含水层是具有局部水位的区域，独立于海平面
  • 在生成世界时，含水层用于在噪声洞穴内部生成水体
  • 这有时会形成大型地下湖泊
  • 它们也可以在山脉内部和地表形成
  • y0 以下的含水层有时会是熔岩含水层，而不是水含水层
  • 岩浆块有时会在水体底部生成
  • 水下洞穴雕刻器和水下峡谷已被移除，因为现在使用含水层在洞穴中生成水

疾跑

JFR 性能分析

自定义事件

使用 jfr start 命令或 --jfrProfile 启动标志启动性能分析时，所有事件都会启用。 如果通过任何其他方式出于监控目的启动性能分析，则默认仅包含 ServerTickTime、LoadWorld 和 NetworkSummary。

  • minecraft.ServerTickTime：周期性事件（1 秒间隔），提供平均服务器刻时间
  • minecraft.NetworkSummary：周期性事件（10 秒间隔），报告每个连接的总数据包大小和数量
  • minecraft.PacketReceived | minecraft.PacketSent：网络流量
  • minecraft.ChunkGeneration：生成各个区块阶段所花费的时间
  • minecraft.LoadWorld：初始世界加载持续时间

概述

Java Flight Recorder 是 Java 运行时附带的内部 JVM 性能分析工具，用于分析性能和运行时特征。
它是揭示内部 JVM 性能指标以及可使用任何标准 Java 分析器或监控代理进行监控或分析的自定义指标的有用工具。

性能分析生命周期

可以使用以下任一方式开始或停止性能分析运行：

  • --jfrProfile 启动标志，在启动 Minecraft 服务器或客户端时
  • jfr start 游戏内命令
  • 常规 Java CLI 工具，例如 jcmd
  • 关闭 JVM
  • jfr stop 游戏内命令
  • jcmd CLI 工具

报告

摘要 JSON 报告会同时写入日志文件和调试文件夹，并附带 .jfr 记录，可随时在 JMC 或任何支持该格式的其他分析器工具中进行分析。

后台线程的最大数量已增加

  • 包括世界生成在内的各种后台任务都在后台线程池上执行

  • minecraft/textures/gui/container/inventory.png 现在包含一个额外的精灵图，用于物品栏中效果列表的窄版式

服务器捆绑

  • server.jar 现在捆绑各个独立的库，而不是将所有文件合并到单个归档文件中
  • 此更改旨在解决与 Java 模块相关的某些问题
  • 启动时，server.jar 会将库解压到由 bundlerRepoDir 配置的目录中（默认：工作目录）
  • 要运行服务器以外的其他主类，请使用 bundlerMainClass 属性（例如 java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar --reports），或手动解压 jar，并使用 META-INF/classpath-joined 的内容作为命令行参数
  • 如果 bundlerMainClass 为空，程序将仅验证并提取文件，然后退出
  • 服务器类现在已签名

模拟距离设置

  • 一个新的滑块，可在视频设置中找到
  • 模拟距离之外的实体、方块和流体不会更新
  • 允许在 CPU 负载较低的情况下使用更高的渲染距离
  • 专用服务器属性中也有一个新的 simulation-distance 属性

刷怪笼数据更改

示例：

SpawnData: {
    entity: {
        id: "minecraft:cow"
    },
    custom_spawn_rules: {
          sky_light_limit: {min_inclusive: 10, max_inclusive: 15}
    },
}
SpawnPotentials: [
  {
    data: {
      custom_spawn_rules: {
          block_light_limit: {min_inclusive: 0, max_inclusive: 15}
      },
      entity: {id: "minecraft:pig"},
    },
    weight: 2
  },
  {
    data: {
      custom_spawn_rules: {
          block_light_limit: {min_inclusive: 5, max_inclusive: 10},
          sky_light_limit: {min_inclusive: 10, max_inclusive: 15}
      },
      entity: {id: "minecraft:panda"}
    },
    weight: 1
  }
]
  • 刷怪笼现在支持 SpawnData 字段和 SpawnPotentials 列表中的 custom_spawn_rules NBT
  • custom_spawn_rules 目前可以包含 block_light_limit 和 sky_light_limit 字段 - 两者都是带有 min_inclusive 和 max_inclusive 字段的整数范围
  • 为了使 SpawnPotentials 格式与其他加权列表类似，结构已更改为 {weight: <int>, data: <先前的內容不包含 'Weight'，'Entity' 重命名为 'entity'>}
  • 为了适应这一更改，SpawnData 先前的内容已移至 SpawnData.entity（使该字段的格式与 SpawnPotentials.data 的元素相同）

遥测

在此版本中，我们重新引入了诊断跟踪，这是 Minecraft: Java Edition 直到 2018 年的一部分。我们将其带回，以更好地了解我们的玩家并改善他们的体验。具体来说，这些信息将帮助我们确定开发的优先级并找出痛点。所有数据都按照 GDPR 和 CCPA 最佳实践处理，用于开发性能更好、整体更令人愉快的 Minecraft: Java Edition。

  • 目前，唯一实现的事件是世界加载

世界加载事件

  • 在加载单人世界或连接多人游戏服务器时发送
  • 包含以下信息：
    • 启动器标识符
    • 用户标识符（XUID）
    • 客户端会话 ID（重启时更改）
    • 世界会话 ID（每次加载世界时更改，以供后续事件复用）
    • 游戏版本
    • 操作系统名称和版本
    • Java 运行时版本
    • 客户端或服务器是否安装了模组（与崩溃日志中的信息相同）
    • 服务器类型（单人游戏、Realms 或其他）
    • 游戏模式

世界数据：区块格式

  • 移除了区块的 Level，并将其包含的所有内容上移
  • 区块的 Level.Entities 已移至 entities
  • 区块的 Level.TileEntities 已移至 block_entities
  • 区块的 Level.TileTicks 和 Level.ToBeTicked 已移至 block_ticks
  • 区块的 Level.LiquidTicks 和 Level.LiquidsToBeTicked 已移至 fluid_ticks
  • 区块的 Level.Sections 已移至 sections
  • 区块的 Level.Structures 已移至 structures
  • 区块的 Level.Structures.Starts 已移至 structures.starts
  • 区块的 Level.Sections[].BlockStates 和 Level.Sections[].Palette 已移至 sections[].block_states 中的容器结构
  • 区块的 Level.Biomes 现在使用调色板，并位于 sections[].biomes 中类似的容器结构中
  • 区块的 Level.CarvingMasks[] 现在是 long[]，而不是 byte[]
  • 添加了 yPos，即区块中最小子区块的 Y 位置
  • 添加了 below_zero_retrogen，包含支持零下生成的数据
  • 添加了 blending_data，包含支持将新世界生成与现有区块混合的数据

世界生成

  • 用于主世界生成的新的随机数生成器
