新特性

  • 添加了狼的变种

狼变种

  • 添加了新的狼变种
  • 变种由其生成的生物群系决定
    • 苍白狼 - 熟悉的狼变种，现在生成于针叶林生物群系，默认族群大小为4
    • 森林狼 - 生成于森林生物群系的变种。由于森林生物群系非常常见，这将成为你在主世界能找到的主要狼变种
    • 灰烬狼 - 生成于积雪针叶林生物群系的变种
    • 黑狼 - 生成于原始松木针叶林生物群系的变种，以2至4只的小族群生成
    • 栗色狼 - 生成于原始云杉针叶林生物群系的变种，以2至4只的小族群生成
    • 锈色狼 - 生成于狼的新地点 - 稀疏丛林生物群系的变种，以2至4只的小族群生成
    • 斑点狼 - 生成于狼的新地点 - 热带草原高原生物群系的变种，以4至8只的大族群生成
    • 条纹狼 - 生成于狼的新地点 - 繁茂恶地生物群系的变种，以4至8只的大族群生成
    • 雪狼 - 生成于雪林生物群系的变种。一种稀有的类型，总是独自行走
  • 调整了狼的生成条件，允许它们生成在砂土和灰化土上

更改

  • 调整了雪林生物群系中被动生物的生成，现在仅包括兔子、狐狸和狼
  • 当鼠标悬停在包含元素外部时，按钮工具提示将不再出现

技术更改

  • 数据包版本现在为34

数据包版本34

  • 配方结果现在可以指定组件数据
  • 添加了新的实体谓词字段slots，用于匹配物品槽位
  • 添加了用于范围的槽位名称，如container.*
  • 添加了execute if|unless items来检查和计数物品
  • 旗帜图案现在是数据驱动的
  • 对物品堆叠组件格式的更改
  • 玩家头颅方块现在存储一个custom_name标签，在破坏或放置时会将其与物品形式相互复制
  • 玩家头颅方块中的SkullOwner和ExtraType字段已被profile字段取代，格式与物品组件相同
  • 目前，物品堆叠上的count字段总是会被存储，即使为1
    • 如果数据中缺少该字段，仍会回退到1

配方

  • 配方类型crafting_shaped、crafting_shapeless、stonecutting和smithing_transform现在接受用于result物品堆叠的components
  • 配方类型smelting、blasting、smoking和campfire_cooking的result字段现在是不含计数的物品堆叠格式，这意味着你需要指定一个包含id字段的对象
    • 此result现在也接受components数据

谓词

slots实体子谓词

  • 新的实体字段slots允许检查任何实体上的单个或多个槽位
  • 该字段包含从槽位名称（与item命令中使用的相同）到物品谓词的映射
  • 对于槽位范围，只需一个槽位匹配即可使整个条目通过

示例：

{
    "condition": "minecraft:entity_properties",
    "entity": "this",
    "predicate": {
        "slots": {
            "container.*": {
                "items": "dirt"
            }
        }
    }
}

槽位名称

  • 槽位名称（在item命令和slots实体谓词中使用）现在包括槽位范围
  • 除非另有指定，现有命令仍然只能作用于单个槽位
  • 新的槽位名称：
    • container.* - 包含container.0到container.53
    • hotbar.* - 包含hotbar.0到hotbar.8
    • inventory.* - 包含inventory.0到inventory.26
    • enderchest.* - 包含enderchest.0到enderchest.26
    • villager.* - 包含villager.0到villager.7
    • horse.* - 包含horse.0到horse.14
    • weapon.* - 包含weapon.mainhand和weapon.offhand
    • armor.* - 包含armor.head、armor.chest、armor.legs、armor.feed、armor.body
    • player.cursor - 玩家在屏幕上持有的物品
      • 注意：此信息在创造模式中不可用
    • player.crafting.0 - player.crafting.3、player.crafting.* - 玩家的合成槽位
      • 注意：这仅包括玩家物品栏中的合成槽位。合成台（或其他屏幕上的任何其他槽位）不包括在内

execute if|unless items

  • execute if|unless items <source> <slots> <item_predicate>命令可用于计数物品
    • <source>与item命令中使用的相同，即
      • block <x> <y> <z>
      • entity <target>（选择器可以返回多个实体）
    • <slots>可以接受单个槽位（如container.0）或范围（如container.*）
    • <item_predicate>与clear命令中的物品谓词相同
  • 如果单独使用，它将返回匹配谓词的堆叠中物品的总数

旗帜图案

  • 旗帜图案现在将从数据包加载到动态注册表中（data/<namespace>/banner_pattern/<id>）
    • 这些条目有两个字段：
      • asset_id（命名空间字符串）用于解析纹理位置
        • 例如，custom:pattern解析为assets/custom/textures/entity/banner/pattern.png、assets/custom/textures/entity/shield/pattern.png
      • translation_key（字符串）是翻译键前缀
        • 例如，block.minecraft.banner.custom.pattern解析为block.minecraft.banner.custom.pattern.<dye color>

物品堆叠组件

  • minecraft:profile组件不再要求存在name字段
  • 一些额外的物品堆叠组件现在支持可选的简单定义：
    • minecraft:profile可以定义为字符串玩家名称（例如profile="jeb_"）
    • minecraft:dyed_color可以定义为整数RGB颜色（例如dyed_color=16711680）
    • minecraft:attribute_modifiers可以定义为修饰符的直接列表（例如attribute_modifiers=[{type:'generic.scale',uuid:[1,2,3,4],name:'Big!',amount:1.0,operation:'add_multiplied_base'}]）
    • minecraft:potion_contents可以定义为单个药水ID（例如potion_contents="invisibility"）
    • minecraft:enchantments和minecraft:stored_enchantments可以定义为附魔ID到等级的嵌入式映射（例如enchantments={sharpness:1}）
  • 这些只是定义值的替代方式，它们始终会以完整格式存储
  • 所有容器方块在物品形式时现在都使用minecraft:container组件，而不仅仅是潜影盒
  • minecraft:lodestone_target组件已重命名为minecraft:lodestone_tracker
    • pos和dimension字段已移入target对象
    • target字段是可选的，如果不存在，指南针将会旋转
  • lore和烟花条目的最大数量已提高到256
