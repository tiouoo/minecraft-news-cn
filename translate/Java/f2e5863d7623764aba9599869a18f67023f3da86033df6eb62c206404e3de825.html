新特性

  • 新增铜箱子
  • 新增铜傀儡
  • 新增铜傀儡雕像方块
  • 新增铜制装备
  • 新增置物架

铜箱子

  • 铜箱子是一种新型箱子，拥有涂蜡和氧化变种
  • 铜箱子会随时间氧化，并可以像其他铜块一样涂蜡
  • 铜箱子可以使用箱子和铜锭合成

铜傀儡

  • 铜傀儡是一种新生物，可以通过在铜块顶部放置南瓜灯或雕刻南瓜来生成
  • 铜傀儡会随时间氧化，并可以像铜块一样涂蜡
  • 如果铜傀儡完全氧化且未涂蜡，就会变成铜傀儡雕像方块
    • 变成铜傀儡雕像时，铜傀儡会掉落其持有的任何物品
    • 如果使用命名牌命名，变成铜傀儡雕像的铜傀儡会保留其名称
  • 铜傀儡可以帮助将物品分类放入箱子
  • 空手与铜傀儡交互会使其掉落携带的物品

铜傀儡物品分类

  • 如果铜傀儡没有持有物品，它会寻找附近的铜箱子，尝试拾取物品
    • 铜傀儡会在任何氧化和涂蜡的铜箱子变种中拾取物品
    • 它一次最多可以从一组中拾取16个物品
    • 铜箱子中的任何物品都可以被拾取
  • 如果铜傀儡持有物品，它会寻找附近的箱子，尝试将物品放入
    • 铜傀儡会在箱子和陷阱箱中寻找可以放置物品的位置
    • 如果箱子是空的，或者箱子中装有与它手中物品同类型的物品，它就可以将物品放入箱子
  • 铜傀儡会依次访问最多10个箱子或铜箱子，尝试拾取或放置物品
  • 如果没有找到匹配的箱子，铜傀儡会闲置7秒后再次尝试
  • 铜傀儡周围寻找箱子的区域为水平32格、垂直8格

铜傀儡雕像方块

  • 铜傀儡雕像方块是一种新型装饰性方块，拥有涂蜡和氧化变种
  • 铜傀儡雕像方块会随时间氧化，并可以像铜块一样涂蜡
  • 可以通过与其交互来改变方块的姿势
  • 如果使用斧头与没有氧化的铜傀儡雕像方块交互，方块会变成铜傀儡
  • 每种姿势都会发出红石比较器信号

避雷针

  • 避雷针现在会像其他铜块一样氧化，铜傀儡身上的避雷针也是如此

铜制装备

  • 新增铜粒
  • 新增铜制盔甲
    • 新增铜头盔、铜胸甲、铜护腿和铜靴子
    • 铜制盔甲的耐久度高于皮革和金质盔甲
    • 铜制盔甲的附魔能力略低于铁质盔甲
  • 新增铜制工具和武器
    • 新增铜斧、铜锄、铜镐、铜锹和铜剑
    • 铜制工具和武器与石制工具和武器造成相同伤害，但耐久度更高
    • 铜制工具比石制工具效率更高，也更耐用
    • 铜制工具的附魔能力高于钻石，但略低于铁
  • 铜制装备可以使用铜锭合成
  • 铜制装备可以使用铜锭修复
  • 铜制装备在熔炼时会变成铜粒
  • 新增铜马铠
    • 与铁马铠具有相同的战利品表和生成概率
    • 盔甲韧性：4

置物架

  • 置物架是一种新型装饰性方块，有以下变种：
    • 橡木
    • 云杉木
    • 白桦木
    • 丛林木
    • 金合欢木
    • 深色橡木
    • 红树木
    • 樱花木
    • 苍白橡木
    • 竹
    • 绯红木
    • 诡异木
  • 置物架可以使用六个同种的去皮原木、去皮菌柄或去皮竹块合成，放在合成格的第一行和第三行
    • 此配方产出6个置物架
  • 置物架最多可以存储3组物品：
    • 与置物架正面的3个槽位中任意一个交互，会将玩家主手物品与该槽位中的内容交换
    • 置物架会像物品展示框一样，将其包含的所有物品显示在正面
  • 当置物架被红石充能时，其正面纹理会改变以表示已充能；当彼此相邻放置时，最多3个被充能的置物架会连接起来
    • 与单个被充能的置物架交互，会将其所有内容与玩家快捷栏中最右侧的3个物品交换
    • 与两个连接的置物架交互，会将其内容与玩家快捷栏中最右侧的6个物品交换
    • 与三个连接的置物架交互，会将其内容与玩家快捷栏中的所有物品交换
    • 玩家与哪个连接的置物架交互并不重要

辅助功能

  • “攻击/破坏”和“使用物品/放置方块”键位现在可切换，意味着它们可以在控制界面中设置为“按住”或“切换”
  • 在鼠标设置界面中新增“反转鼠标X轴”选项，该选项会反转鼠标X轴
  • 在控制界面中新增“疾跑窗口”选项，它表示双击前进键激活疾跑的时间窗口（以游戏刻为单位）

更改

  • 当难度设置为和平时，怪物刷怪蛋现在会有工具提示警告
    • 尝试使用刷怪蛋时，生物不再会生成1刻
  • 调试屏幕经过重新设计，信息更简洁，且更可配置
  • 世界加载和“出生点区块”的更改
  • 任何有玩家活动、强制加载区块、活动传送门或飞行中的末影珍珠的维度将被视为“活跃”，并将继续处理其中的区块和实体
    • 以前，这仅适用于玩家在该维度中或区块被强制加载的情况

世界加载和出生点区块

  • 固定“出生点区块”的概念已被移除
  • 游戏将确保在玩家加入或服务器启动之前完全加载以下区块，方式与以前的出生点区块相同：
    • 通过forceload命令加载的区块
    • 因传送门活动而活跃的区块
    • 在单人游戏中投掷的末影珍珠（仅单人游戏）
    • 玩家周围的一小片区块（仅单人游戏）
    • 分配全局世界出生点所需的区块（仅世界创建时）
  • 世界加载界面现在会显示玩家即将被放入的区块，而不是世界出生点周围加载的区块
  • 加载界面现在还包含进度条
    • 该进度条涵盖了上述所有类型的区块加载

开发者注： 出生点区块会给所有玩家带来内存和性能开销，而它们最初保持出生点区域准备好供玩家快速加入的技术目的已不再适用。

然而，我们也想承认，多年来出生点区块为各种巧妙的装置和农场提供了可能，因此仅仅移除它们而不在游戏中加入其他机制来支持这些设计，从来都不是一个可选方案。

我们相信，出生点区块所占据的特殊地位现在已被其他区块加载方式所填补，例如使用传送门或末影珍珠，尤其是在此快照中对游戏在世界开始运转前如何加载这些区块所做的更改。

UI

调试屏幕

  • 与之前一样，按下F3即可打开调试屏幕
  • 现在可以在游戏中的任何位置打开它，而不仅仅是在游戏世界中
  • 它现在默认显示较少的信息
  • 新增了调试选项屏幕，可通过按F3 + F5打开
    • 它可以用来配置应显示哪些调试信息
    • 对于每个项目，你可以选择将其关闭、在调试屏幕（F3）打开时可见，或者即使调试屏幕关闭也始终可见
    • 一些以前可用的调试功能，例如区块边界渲染或实体碰撞箱渲染，现在可以通过此调试选项屏幕切换
    • 一些以前社区无法使用的调试功能，例如八叉树可视化，现在可以通过调试选项屏幕使用
    • 调试选项屏幕的状态会在游戏启动之间保存
    • 调试选项屏幕具有以下预设配置：
      • Default将所有内容重置为默认状态
      • Performance显示简单的性能指标，包括始终在屏幕上可见的FPS计数器

开发者注： 以前，每帧收集用于渲染F3屏幕的信息会带来显著的性能开销。因此，打开屏幕查看FPS会明显降低FPS。现在，在Performance配置中查看FPS应该不会影响游戏性能。

辅助功能

  • 在辅助功能设置界面中添加了一个通往控制界面的按钮
    • “自动跳跃”选项以及“潜行”和“疾跑”开关已从辅助功能设置界面中移除
  • “显示字幕”选项已改称为“隐藏式字幕”，以更准确地描述其功能
  • 染料颜色现在有了更新后的图标
    • 这样做的目的是增强整个染料系列的视觉一致性，同时保持不同的形状，以支持色盲辅助功能

性能改进

  • 实体渲染顺序得到了改进，以显著提升性能
    • 在生物密集的区域（如刷怪场），你会明显感到游戏更加流畅
    • 如果你的大部分卡顿来自实体以外的因素，例如在远离大量生物的情况下以高渲染距离游玩，FPS不会有太大提升

开发者注： 这个改动非常大，如果因此引入了一些排序问题，我们也不会感到惊讶。例如，某个生物的某个部分渲染得太早或太晚，导致不可见或视觉异常。请多多尝试，并报告你遇到的漏洞！

技术更改

  • 包版本现在拥有次版本号
  • 数据包版本现在是82.0
  • 资源包版本现在是65.0

包格式

  • 数据包和资源包的包版本现在拥有次版本号
    • 游戏包版本的次版本号递增是向后兼容的，这意味着为同一主版本先前迭代制作的所有包都将继续工作
  • 包可以在次版本号上设置兼容性要求，以防它们依赖于某个次版本号中引入的资源

包元数据

pack.mcmeta格式已更新：

  • supported_formats字段已被移除
    • 如果你的包声明支持以前格式的包版本（数据包< 82，资源包< 65），则仍然需要它
    • 否则，不允许使用，必须移除
  • pack_format字段现在为可选
    • 如果你的包声明支持以前格式的包版本（数据包< 82，资源包< 65），则仍然需要它
  • 新增必填字段min_format——指定支持的最低版本
    • 完整版本由两个整数的列表指定，例如[74, 1]
    • 指定单个整数将被解释为该主版本，例如74与[74, 0]相同
    • 指定只包含一个整数的列表与单独指定该整数含义相同
  • 新增必填字段max_format——指定支持的最高版本
    • 完整版本由两个整数的列表指定，例如[74, 1]
    • 指定单个整数将被解释为任意次版本，即次版本号为0x7fffffff
    • 指定只包含一个整数的列表与单独指定该整数含义相同
  • 对于叠加层条目：
    • formats字段已被移除
      • 如果你的包包含任何涵盖以前格式（数据包< 82，资源包< 65）的叠加层范围，则所有叠加层定义中仍需要它
      • 否则，不允许使用，必须移除
    • 新增必填字段min_format和max_format，其格式与上面pack部分中同名字段的格式相同

战利品表

  • 新增minecraft:entity_interact战利品表类型，它接受以下参数：
    • target_entity——被交互的实体
    • interacting_entity——与target_entity交互的可选实体
    • tool——用于与target_entity交互的工具
  • 新增minecraft:block_interact战利品表类型，它接受以下参数：
    • block_state——被交互的方块实体的方块状态
    • block_entity——被交互的可选方块实体
    • interacting_entity——与block_state交互的可选实体
    • tool——用于与block_state交互的可选工具
  • 战利品表中指定目标实体的字段（例如entity_properties.entity）现在还可以将target_entity和interacting_entity参数类型作为目标
  • 新增charged_creeper/root战利品表，用于实体被闪电苦力怕杀死时的掉落物

  • 新增brush/armadillo战利品表，用于刷扫犰狳时的掉落物
  • 新增gameplay/turtle_grow战利品表，用于海龟成长为成年个体时的掉落物
  • 新增harvest/beehive战利品表，用于使用剪刀收获蜂箱或蜂巢时的掉落物
  • 新增harvest/cave_vine战利品表，用于通过交互收获带有发光浆果的洞穴藤蔓时的掉落物
  • 新增carve/pumpkin战利品表，用于使用剪刀雕刻南瓜时的掉落物

世界生成

  • noise_settings定义中的initial_density_without_jaggedness字段已被preliminary_surface_level字段取代
    • initial_density_without_jaggedness是一个3D密度函数，通过扫描第一个密度大于0.390625的点来确定近似表面高度
    • preliminary_surface_level是一个2D密度函数，应生成近似表面的y高度
    • 可以使用minecraft:find_top_surface密度函数来复现之前的扫描

密度函数

新增minecraft:find_top_surface

  • 近似计算给定密度函数的最顶部表面
  • 它从上限扫描到下限，以找到密度从负变为正的点
    • 为了获得最佳性能，上限应尽可能接近实际表面
    • 上限绝不应低于实际表面

字段：

  • density——用于近似其表面的密度函数
  • upper_bound——提供最高可能y值的2D密度函数
  • lower_bound——整数，最低可能y值
  • cell_height——正整数，定义扫描网格分辨率

新增minecraft:invert

  • 解析为1/argument

字段：

  • argument——密度函数

拼图结构

  • max_distance_from_center字段现在可以在垂直轴上指定与水平轴不同的限制
    • 这可以通过一个具有以下字段的对象来指定：
      • horizontal——必填整数，介于1和128之间
      • vertical——可选整数，介于1和4096之间（默认值：4096）
      • 例如："max_distance_from_center": { "horizontal": 20, "vertical": 500 }
    • 仍然支持以前使用单个内联值同时指定水平和垂直距离的格式

着色器与后处理效果

开发者注： 虽然资源包中覆盖核心着色器是可能的，但这被认为不受支持，并且不是资源包的预期功能。这些着色器作为游戏内部实现的一部分存在，因此，随着游戏内部结构的发展，它们可能随时发生变化。我们理解，覆盖核心着色器被用于实现非常酷的资源包功能，其中许多功能缺乏受支持的替代方案。我们希望将来能提供更好的、受支持的替代方案。

全屏渲染阶段的更改

  • 以下顶点着色器已被移除，并替换为core/screenquad.vsh：
    • core/blit_screen.vsh
    • post/blit.vsh
    • post/blur.vsh
    • post/invert.vsh
    • post/sobel.vsh
    • post/screenquad.vsh
  • 用于后处理效果、光照贴图生成和全屏位块传送的顶点着色器不再接收Position属性，而是必须通过gl_VertexID分配顶点坐标
  • 此外，这些渲染阶段仅使用3个顶点执行，而不是完整的四边形
