23w31a 的新实验性特性

村民交易再平衡

本快照引入了一个新的实验性功能开关，更新了流浪商人和图书管理员的交易。 如果你想测试新的交易，必须在创建新世界时在“实验”菜单中打开此功能开关。你可以在此找到更多关于功能开关的信息。

由于这是一个实验，随着工作的继续，我们非常感激你的反馈，这也能帮助我们决定村民交易的未来方向。请访问此链接分享你的想法！

图书管理员改动

在这些改动之前，玩家可以从任何图书管理员那里获得任何村庄附魔。一个新手图书管理员就能出售游戏中最强的附魔！对一些玩家来说，这感觉太过随机，并且与使用附魔台或在地牢结构中寻找附魔书相比，交易显得过于强大。

根据新规则，来自不同生物群系的图书管理员出售不同的附魔，而且每个村庄生物群系都有一种只有大师级图书管理员才会出售的附魔。

玩家必须努力才能获得最佳交易，而不是依赖随机概率。我们希望这能让图书管理员交易更有趣、更具技巧性，同时通过出售的附魔揭示每种村庄类型的一些历史线索。

  • 来自不同生物群系的图书管理员现在出售不同的附魔书
  • 每个村庄生物群系都有一种特殊附魔，只有满经验的大师级图书管理员才能提供
  • 这意味着玩家必须访问全部七种村庄生物群系才能获得全套村民附魔
  • 有两个秘密的村庄生物群系，不会自然生成村庄
    • 玩家必须自己建造这些村庄才能解锁它们的交易！
  • 一些附魔已从村庄交易中移除，必须通过其他方式获得

流浪商人改动

一些玩家觉得流浪商人的价格不公平，而且出售的有用物品不多。我们降低了价格，增加了更多交易项目，并提高了可用数量。流浪商人现在也会向玩家购买有用物品，因此即使你不打算买任何东西，也可以通过提供补给来帮助他们的旅程。

  • 流浪商人现在价格更低，而且每种物品的库存数量更多
  • 流浪商人现在出售原木
  • 流浪商人现在可以购买许多物品，而不仅仅是出售

改动

  • 钻石矿石现在在主世界的深板岩层中生成更频繁
  • 治疗僵尸村民现在只在第一次时提供大幅折扣
    • 不再因为反复感染和治疗同一个村民而获得额外折扣
  • 屏障方块现在可以在创造模式下被玩家含水
    • 无法通过非直接交互（如发射器）在其中放置或取出水
  • 玩家在骑乘载具时不再能下蹲
  • 紫颂花不再能够支撑悬垂或站立方块

钻石矿石分布

在本快照中，我们增加了在世界最深处发现的钻石矿石数量。我们的目标是让在深板岩层挖掘钻石更有回报。我们希望听到你对此的反馈！请尝试你最喜欢的挖掘技术，并在此反馈网站上告诉我们体验如何。

技术性改动

  • 资源包版本现在为 16
  • 数据包版本现在为 16
  • 使用过的命令历史现在会保存，并可在不同世界间访问
  • 优化了区块发送给客户端的方式，使低带宽互联网连接的玩家可以在多人服务器上游戏
  • 添加了对多版本包的支持
  • 更改了网络协议，为未来更多的数据驱动内容做准备
  • 在server.properties中添加了新的log-ips选项
  • 为数据包和资源包中的符号链接添加了验证
  • 当通过 F3+B 显示碰撞箱时，带有乘客的实体会显示乘客的连接点

命令历史

  • 你在聊天中发送的最后 50 条命令会在游戏会话之间被记住
  • 你可以通过在聊天中按上或下箭头来访问命令和聊天历史
  • 普通聊天仅在同一游戏会话内保留（离开服务器或世界时会清除）
  • 最近的命令存储在游戏文件夹中的command_history.txt中

区块发送优化

  • 区块不再以一大整批的方式通过网络发送到客户端
  • 而是根据可用带宽以较小的批次发送。这意味着：
    • 连接带宽极低的客户端在加载世界时不会超时
    • 低带宽连接客户端可以在某些区块仍在加载时与世界交互
  • 现在只发送客户端渲染距离内的区块

多版本包

为数据包和资源包添加了新特性，以允许创建与多个游戏版本兼容的包。

包元数据

  • 包元数据现在包含一个可选字段supported_formats，用于描述此包支持的包格式范围
    • 示例：16、[16,17]、{"min_inclusive": 16, "max_inclusive": 17}
  • pack_format字段仍然是必需的，其格式保持不变，以便旧版游戏能够读取包数据
    • 如果存在supported_formats，它必须包含pack_format中声明的值
    • 注意：由于旧版游戏会忽略这个新信息，它们始终会将包视为“正常的”单版本包，没有任何扩展兼容性

覆盖层

  • 包现在可以包含覆盖层目录（“overlays”）
  • 覆盖层是应用到包“正常”内容的子包
    • 这些目录与顶层包具有相同的布局，包括assets和data目录
    • 如果覆盖层支持客户端的包格式，则可以应用
    • 覆盖层可以添加和替换文件，但不能删除它们
      • 例如，如果应用了覆盖层foo，文件foo/assets/minecraft/textures/bar.png将替换assets/minecraft/textures/bar.png的内容
    • pack.mcmeta和pack.png在覆盖层目录中被忽略
  • 包元数据中添加了一个名为overlays的新部分
    • 它包含一个entries字段，其中包含一个覆盖层列表
    • 每个覆盖层条目有两个字段：
      • formats - 支持的格式范围
      • directory - 覆盖层目录（允许的字符：a-z、0-9、_和-）
  • 应用顺序：覆盖层从列表底部向顶部叠加
    • 例如，如果一个包有两个覆盖层："entries": [{"directory":"A", ...}, {"directory":"B", ...}]，游戏将首先查找B，然后A，最后在顶层包目录中查找

网络协议

作为持续推进数据驱动特性工作的一部分，网络协议已更改，新增了一个配置阶段。

  • 配置阶段在登录阶段（即客户端账户验证后）自动开始，并持续到玩家加入世界（游戏阶段）
  • 客户端可以无限期停留在配置阶段——由服务器决定何时将其释放到世界
  • 服务器也可以在客户端进入游戏阶段后请求其重新进入配置阶段
    • 其他玩家会将此类客户端视为已断开连接
  • 处于配置阶段的用户不会在玩家列表中显示
  • 配置阶段允许的操作（从游戏阶段移出）
    • 配置数据驱动注册表
    • 配置启用的特性
  • 配置阶段和游戏阶段共享的操作：
    • 应用服务器资源包
    • 更新标签
    • 交换自定义数据包
    • Ping 和保持连接数据包
  • 服务器现在会在配置阶段协商资源包
    • 这意味着玩家在回答提示和重新加载资源时不再处于世界中

server.properties

  • 新选项：log-ips（默认为 true）
    • 当设置为false时，将防止玩家加入游戏时其 IP 被记录在日志中

符号链接验证

为了提高安全性，游戏现在还会检测数据包和资源包内部使用的符号链接。

  • 此功能扩展了上一个版本中添加的世界中的符号链接验证
  • 如果通过拖放添加的包包含不允许的符号链接，游戏现在会警告用户
  • 包含不允许的符号链接的包将不会在 UI 和命令中显示
  • 此外，未被识别为包的目录和文件将不再通过拖放复制
  • 有关详细说明，请参阅这篇帮助文章

        • height：此精灵在屏幕上高度方向覆盖的像素数
        • border：边框切片在屏幕上应覆盖的像素大小，以下之一：
          • 用于所有侧边统一边框大小的常量整数
          • 包含left、top、right和bottom的对象

命令

random

一个用于随机化值和控制随机序列的新命令。value和roll形式可用于抽取随机值。对于roll，结果值也会显示在聊天中供所有玩家看到。

语法：

random value|roll <range> [<sequenceId>]
random reset *|<sequenceId> [<seed>] [<includeWorldSeed>] [<includeSequenceId>]

参数：

  • range：要随机化的值范围，包含两端
    • 例如，1..6 是普通的 D6 掷骰
  • sequenceId：要采样或重置的随机序列的名称
  • seed：重置后用于随机序列的种子
  • includeWorldSeed：一个布尔值 [默认：true]，指定在为序列播种时是否包含世界种子
    • false意味着无论命令在哪个世界中运行，序列都会计算出相同的结果
  • includeSequenceId：一个布尔值 [默认：true]，指定在为序列播种时是否包含序列 ID
    • false意味着无论序列名称如何，所有序列都会计算出相同的结果

默认情况下，所有序列都以0、true、true作为种子。使用*而不是序列 ID 会重置所有序列并设置默认参数。

如果未指定种子，序列将重置为默认参数。

请注意，不带序列 ID 使用的random value|roll <range>可供非管理员玩家使用。

execute if function

一个新的 execute 子命令，用于运行函数或函数标签并匹配返回值。如果给定了标签，所有函数都会运行，无论先前函数的结果如何。语法：

execute if|unless function <function> <continuation>

参数：

  • function：要运行的函数或标签
匹配

运行的函数的返回值匹配：

  • 匹配成功需要至少一个函数成功
  • 成功调用定义为这样的函数：
    • 使用return命令返回值
    • 返回值不为 0

return run

return命令的一种新形式现已可用：return run。语法：

return run <command>

这会从运行指定command中获取result值，并将其作为函数的返回值。在其他所有方面，它都像带有指定返回值的return一样工作。如果给定的命令失败，返回值为0。

函数

  • 一行中最后一个非空白字符为单个反斜杠\ 时，现在允许命令在下一行继续
    • 下一行的前导和尾随空白会在追加前被去除

宏

函数现在可以包含宏行，使其成为函数宏。

  • 任何以$（作为第一个非空格字符）开头的行都标记为宏行
  • 宏行还包含一个或多个$(variable)形式的替换
  • 调用函数宏时，必须提供一个包含所有参数变量数据的复合标签
调用函数宏

function命令有了新形式：

function <id> <compound>
function <id> with <data source> [<path>]

新参数：

  • compound：一个数据复合标签，用{}括起来
  • data source：数据源规范，就像已经可用于data get的那样
  • path：NBT 路径规范

注意：

  • 数据源和路径必须指定一个复合数据条目
  • 复合标签必须包含宏中使用的每个变量的一个条目
  • 复合标签中可能存在更多数据，如果有，则会被忽略
  • 使用数据复合标签调用非宏函数会被静默忽略
  • 调用宏时，提供的值会替换变量规范，然后执行生成的命令
  • 变量替换所产生的行中的任何语法错误都会导致整个函数调用被跳过
性能注意事项

使用宏意味着命令必须在变量替换后重新求值。与运行预解析的函数相比，这会带来额外开销。

常规命令（非宏行）仍然会预解析。只有在调用宏时，才会解析其中包含变量替换的命令，并且游戏会尝试缓存调用中使用的特定参数集的结果。

这使得使用相同参数集的重复调用比使用不同参数的新调用更便宜，但与常规函数相比仍然存在开销。请注意，只有宏作为参数引用的值才会包含在此缓存中，因此提供的复合标签中的任何额外数据都会被忽略。

显示实体插值

  • 显示实体现在会在更新后的第一个游戏刻开始更新其客户端侧的位置和旋转
    • 在以前的版本中，更新在同一刻内应用，导致运动不均匀
    • 新行为现在类似于盔甲架、生物和玩家
  • 在服务器上，位置和旋转仍然会立即更新
  • 此插值的持续时间由teleport_duration字段控制
    • 0表示更新会立即应用
    • 1表示显示实体将在一次游戏刻内从当前位置移动到更新后的位置
    • 更高的值会将移动分散到多个游戏刻
    • 请注意，此值会被限制以避免周期性位置更新导致的故障
    • 新值仅适用于其更改后发生的位置和旋转变化
      • 这意味着任何当前的移动都会保持不变
  • 注意：骑乘时的行为与以前版本保持不变

属性

  • 添加了新属性generic.max_absorption
    • generic.max_absorption的作用类似于generic.max_health，但它是AbsorptionAmount的上限，而不是Health的上限
    • 生物效果absorption会增加generic.max_absorption，并在应用时将AbsorptionAmount填满至最大值

游戏事件

  • entity_roar和entity_shake游戏事件已移除，替换为entity_action游戏事件

标签

  • 添加了no_knockback伤害类型标签，使伤害本身不再造成击退
    • 在原版中用于由事件造成的伤害，例如爆炸，它们会单独施加击退
  • 添加了non_controlling_rider，表示不会覆盖其载具移动控制的实体
  • 为混凝土粉末方块添加了concrete_powder方块标签
  • 为产生entity.camel.step_sand声音的方块添加了camel_sand_step_sound_blocks方块标签
