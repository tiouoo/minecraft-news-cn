我们现在为 Minecraft：Java 版发布 1.20.2。此版本在世界深处增加了更多钻石矿石，并更改了生物攻击范围，同时优化了游戏的网络性能，即使在低带宽连接下也能实现更流畅的在线游戏。

此版本还为地图制作者和数据包及资源包创作者带来了新功能，例如宏函数、random 命令和资源包覆盖层。

在 1.20.2 中，我们对玩家举报工具进行了一些重要更新，以更好地保护玩家的在线安全。您现在可以举报违反我们社区标准的玩家皮肤和用户名。

可选的“村民交易再平衡”实验也在此版本中首次亮相，其中包含您可以尝试的交易变更。

新内容

玩家皮肤与名称举报

我们正在对我们的玩家举报工具进行一些重要更新，以更好地保护玩家的在线安全。

游玩 Minecraft 对每个人来说都应该是包容且安全的体验，因此除了游戏内聊天消息之外，您现在还可以在 Java 版中举报违反我们社区标准的玩家皮肤和用户名。

与聊天举报一样，没有任何自动化流程。任何被举报的皮肤或用户名都将由训练有素的 Minecraft 审核员团队手动审查，他们会根据提交的证据来判断该皮肤和/或用户名是否违反我们的社区标准。违反这些标准的皮肤将被从 Minecraft 中移除，并且任何玩家都无法再使用。违反这些标准的用户名需要在玩家通过共享服务器或 Realm 在线游戏之前进行更改；不过单人游戏模式仍然可用。要了解有关此政策及其他安全政策的更多信息，包括封禁流程、申诉流程以及我们如何处理恶意或重复举报的详细信息，请访问我们的专用常见问题解答页面。

  • 玩家现在可以在社交互动界面中举报皮肤和名称
  • 如果某个皮肤或名称被举报，并被发现违反社区标准，我们的人工审核员团队可以采取以下几种方式：
    • 禁止任何玩家使用该皮肤
    • 禁止任何玩家使用该名称
    • 如果屡次违规，则暂停该玩家的在线游戏权限
  • 当某个皮肤被禁止使用时，使用该皮肤的玩家：
    • 皮肤将被移除
    • 在启动游戏时会收到通知
    • 将自动分配一个默认皮肤
    • 仍可进行多人游戏和单人游戏
    • 可以随时选择新的自定义皮肤
  • 当某个玩家的名称被禁止使用时，该玩家：
    • 需要选择一个新的名称
    • 在启动游戏时会收到通知
    • 在更改名称之前无法在线游戏
    • 仍可进行单人游戏
  • 被禁止使用的皮肤或名称将来不能被任何玩家使用

生物攻击范围更改

用于确定生物能否攻击玩家或其他生物的计算方式已更改。以前，生物的横向宽度用于确定其攻击范围，而高度没有影响。现在，生物可以攻击的区域是其包围盒在水平方向上的延伸。

以下是一些新规则会影响生物攻击范围的情况：

  • 如果生物完全在你下方或完全在你上方，它将无法攻击到你
  • 骑乘中型生物（如马）时，你将免受小型生物（如小僵尸）的攻击
  • 骑乘高大生物（如骆驼）时，你将免受标准体型生物（如僵尸）的攻击
  • 此外，劫掠兽不再能隔着几格厚的墙壁攻击你
  • 然而，要逃离末影人，你需要离地至少 3 格，而不是以前的 1.5 格
  • 假设你的头部在范围内，生物将能用碰撞箱底部攻击你
  • 用于困住敌对生物的建筑可能需要调整以确保安全

此更改不影响玩家的攻击范围，而且生物仍然需要看到目标才能发动攻击。

多版本包

数据包和资源包中添加了新功能，使您可以创建与游戏多个版本兼容的包。

包元数据

  • 包元数据现在包含一个可选字段 supported_formats，用于描述此包支持的包格式范围
    • 示例：16、[16,17]、{"min_inclusive": 16, "max_inclusive": 17}
  • pack_format 字段仍然是必需的，其格式保持不变，以便旧版本的游戏能够读取包数据
    • 如果存在 supported_formats，它必须包含 pack_format 中声明的值
    • 注意：由于旧版本游戏会忽略此新信息，它们始终会看到一个“普通的”单版本包，没有任何扩展兼容性

覆盖层

  • 包现在可以包含覆盖层目录（“overlays”）
  • 覆盖层是应用于包“普通”内容之上的子包
    • 这些目录与顶层包具有相同的布局，包括 assets 和 data 目录
    • 如果覆盖层支持客户端的包格式，则可以应用它们
    • 覆盖层可以添加和替换文件，但不能移除文件
      • 例如，如果应用了覆盖层 foo，则文件 foo/assets/minecraft/textures/bar.png 将替换 assets/minecraft/textures/bar.png 的内容
    • pack.mcmeta 和 pack.png 在覆盖层目录中会被忽略
  • 包元数据中增加了名为 overlays 的新部分
    • 它包含一个 entries 字段，其中包含一个覆盖层列表
    • 每个覆盖层条目有两个字段：
      • formats - 支持的格式范围
      • directory - 覆盖层目录（允许的字符：a-z、0-9、_ 和 -）
  • 应用顺序：覆盖层从列表底部到顶部堆叠
    • 例如，如果一个包有两个覆盖层："entries": [{"directory":"A", ...}, {"directory":"B", ...}]，游戏将首先在 B 中查找，然后是 A，最后在顶层包目录中查找

符号链接验证

为了提高安全性，游戏现在还会检测数据包和资源包中使用的符号链接。

  • 此功能扩展了上一版本中在世界中添加的符号链接验证
  • 如果通过拖放添加的包包含不允许的符号链接，游戏现在会警告用户
  • 包含不允许的符号链接的包将不会在界面和命令中可见
  • 此外，未被识别为包的目录和文件将不再通过拖放复制
  • 有关详细说明，请参阅此帮助文章

网络协议

作为迈向更多数据驱动功能的持续工作的一部分，网络协议已更改，增加了新的配置阶段。

  • 配置阶段在登录阶段（即客户端账户验证后）自动开始，并持续到玩家加入世界（游戏阶段）为止
  • 客户端可以无限期停留在配置阶段 - 由服务器决定何时将其释放到世界中
  • 服务器也可以在客户端进入游戏阶段后要求其重新进入配置阶段
    • 其他玩家会将此类客户端视为已断开连接
  • 处于配置阶段的用户不会出现在玩家列表中
  • 配置阶段允许的操作（从游戏阶段移入）：
    • 配置数据驱动注册表
    • 配置启用的功能
  • 配置阶段和游戏阶段共有的操作：
    • 应用服务器资源包
    • 更新标签
    • 交换自定义数据包
    • Ping 和保活数据包
    • 发送客户端选项
  • 服务器现在将在配置阶段协商资源包

命令

random

一个用于随机化数值和控制随机序列的新命令。value 和 roll 形式可用于抽取随机值。使用 roll 时，结果值还会在聊天中显示给所有玩家。

语法：

random value|roll <range> [<sequenceId>]
random reset *|<sequenceId> [<seed>] [<includeWorldSeed>] [<includeSequenceId>]

参数：

  • range：要在之间随机化的值的范围，包含两端
    • 例如，1..6 就是常规的 D6 掷骰
  • sequenceId：要采样或重置的随机序列的名称
  • seed：重置后用于随机序列的种子
  • includeWorldSeed：一个布尔值 [默认：true]，指定在为序列设定种子时是否包含世界种子
    • false 表示无论命令在哪个世界中运行，该序列的结果都会相同
  • includeSequenceId：一个布尔值 [默认：true]，指定在为序列设定种子时是否包含序列 ID
    • false 表示无论序列名称是什么，所有序列的结果都会相同

默认情况下，所有序列都以 0、true、true 作为种子。使用 * 而不是序列 ID 会重置所有序列并设置默认参数。

如果未指定种子，序列将重置为默认参数。

请注意，不带序列 ID 使用的 random value|roll <range> 可供非管理员玩家使用。

函数

  • 行末最后一个非空白字符为单个反斜杠 \ 时，现在允许命令在下一行继续
    • 下一行的前导和尾随空白会在追加前被去除

宏

函数现在可以包含宏行，从而成为函数宏。

  • 任何以 $ 开头（作为第一个非空格字符）的行都会标记为宏行
  • 宏行还包含一个或多个 $(variable) 形式的替换
  • 调用函数宏时，必须提供一个包含所有参数变量数据的复合标签

调用函数宏

function 命令有新的形式：

function <id> <compound> function <id> with <data source> [<path>]

新参数：

  • compound：一个数据复合标签，用 {} 括起来
  • data source：数据源说明，类似于已经可用于 data get 的数据源
  • path：一个 NBT 路径说明

注意：

  • 数据源和路径必须指定一个复合数据条目
  • 复合标签必须包含宏中使用的每个变量的一个条目
  • 复合标签中可能包含更多数据，如果有，则会被忽略
  • 使用数据复合标签调用非宏函数会被静默忽略
  • 调用宏时，提供的值会替换变量说明，并执行生成的命令
  • 变量替换后得到的行中出现任何语法错误都会导致整个函数调用被跳过

性能注意事项

使用宏意味着命令必须在变量替换后重新求值。与运行预解析的函数相比，这会产生额外开销。

常规命令（非宏行）仍会被预解析。只有在调用宏时，包含变量替换的命令才会被解析，并且游戏会尝试缓存调用中使用的特定参数集的结果。

这使得使用相同参数集重复调用比使用不同参数的新调用成本更低，但与常规函数相比仍存在额外开销。请注意，此缓存仅包含宏作为参数引用的值，因此提供的复合标签中的任何额外数据都会被忽略。

显示实体插值

  • 显示实体现在会在更新后的第一个游戏刻开始更新其客户端侧的位置和旋转
    • 在以前的版本中，更新在同一游戏刻内应用，导致运动不均匀
    • 新行为与盔甲架、生物和玩家类似
  • 在服务器上，位置和旋转仍然立即更新
  • 此插值的持续时间由字段 teleport_duration 控制
    • 0 表示更新立即应用
    • 1 表示显示实体将在一个游戏刻内从当前位置移动到更新后的位置
    • 更高的值会将移动分散到多个游戏刻
    • 请注意，此值会被钳制以避免周期性位置更新导致的故障
    • 新值只适用于在其更改之后发生的位置和旋转更改
      • 这意味着任何当前的移动都将继续不变
  • 注意：骑乘时的行为与先前版本保持不变

属性

  • 添加了新属性 generic.max_absorption
    • generic.max_absorption 的作用类似于 generic.max_health，但它是 AbsorptionAmount（伤害吸收量）的上限，而不是 Health（生命值）的上限
    • 状态效果 absorption（伤害吸收）会增加 generic.max_absorption，并在应用时将 AbsorptionAmount 填满至最大值

    • 在原版中用于由事件引起的伤害，例如爆炸，这些伤害会单独施加击退
  • 添加了 non_controlling_rider，用于表示不会覆盖其载具移动控制的实体

数据包版本 18

此数据包版本移除了在此版本开发期间存在过一段时间的 execute if function 和 return run 功能。这些命令的缺陷（参见漏洞 MC-264595、MC-264699 和 MC-264710）需要一些重大更改才能修复，而我们不希望临近发布时进行这些更改。

这些命令反而会在下一个快照系列早期重新引入，届时我们可以与包创作者一起花时间进行迭代和测试。

  • 移除了 return run 命令形式
  • 用作宏参数的数字现在无论数字类型如何，始终不带后缀插入
  • 添加了游戏规则 enderPearlsVanishOnDeath，控制投出的末影珍珠在投掷者死亡时是否消失（默认 true，与先前版本中的现有行为一致）

实验性功能

村民交易再平衡

创建世界时的实验性功能界面现在有一个启用“村民交易再平衡”的选项。选择此选项后，一些村民交易将会改变。

此实验对普通世界没有影响。您可以在此处了解更多关于特性开关的信息。

图书管理员更改

  • 来自不同生物群系的图书管理员现在出售不同的附魔书
  • 每个村庄生物群系都有一种特殊附魔，只有经验值满的大师级图书管理员才能提供
  • 这意味着玩家必须访问全部七个村庄生物群系才能获得全套村民附魔
  • 有两个隐藏的村庄生物群系不会生成村庄
    • 玩家必须建造这些村庄才能访问其交易！
  • 一些附魔已被从村庄交易中移除，必须通过其他方式获得

制图师更改

  • 制图师现在可以出售七种新的探险家地图
    • 五种新地图指向五种不同类型的村庄
    • 另外两种新地图指向沼泽小屋和丛林神庙
  • 来自不同生物群系的制图师现在出售的地图范围不同

流浪商人更改

  • 流浪商人现在价格更低，并且每种物品的库存量更高
  • 流浪商人现在出售原木
  • 流浪商人现在可以购买许多物品，而不仅仅出售

盔甲匠更改

  • 来自不同生物群系的盔甲匠现在出售带有不同附魔的不同盔甲
  • 购买钻石盔甲现在需要少量钻石以及绿宝石
  • 许多其他盔甲匠交易也已更新

结构战利品

某些附魔书现在有很高的几率在一些结构中生成：

  • 远古城市：经验修补
  • 废弃矿井：效率（I 到 V）
  • 掠夺者前哨站：快速装填（I 到 III）
