我们现正发布 Minecraft Java 版 1.20.3。此次发布为饰纹陶罐带来了新功能，蝙蝠有了新外观，盾牌也得到了改进。

此版本还为地图制作者和包创作者带来了新功能，例如记分板显示名称、execute 和 return 命令的扩展，以及一个新的管理工具：tick 命令。

可选的 1.21 实验性更新也在此版本中作为下一次 Minecraft 主要版本功能的抢先预览出现。

更改

  • 饰纹陶罐现在可以存储物品，并可被弹射物击碎
  • 当玩家使用盾牌格挡时，从第三人称视角观看，持盾的手臂现在会跟随玩家视线方向
  • 蝙蝠现在有了新外观
  • 添加了一个辅助功能选项，允许隐藏主菜单中的黄色闪烁文本
  • 为数据缺失的世界添加了恢复界面（例如，由于意外关闭导致保存失败时）
  • 其他细微调整

饰纹陶罐

  • 饰纹陶罐现在最多可存储一组物品
  • 漏斗、投掷器和漏斗矿车现在可以向饰纹陶罐放入和/或取出物品
  • 比较器现在可以读取饰纹陶罐中的物品数量
  • 玩家可以与饰纹陶罐交互来放入物品
  • 饰纹陶罐没有 GUI，玩家需要将其破坏才能取回或发现其中内容
  • 玩家与饰纹陶罐交互时会导致饰纹陶罐晃动，并触发频率为 11 的振动
  • 饰纹陶罐可被弹射物击碎，碎裂后会掉落其中内容
  • 饰纹陶罐现在可堆叠至 64 个

蝙蝠

  • 蝙蝠的模型、动画和纹理已更新

细微调整

  • 从内部观察刷怪笼时，其内部面现在会渲染
  • 投掷的末影珍珠在撞击时会产生传送音效
  • 对遥测数据收集界面进行了细微调整

技术性更改

  • 数据包版本现在为 26
  • 资源包版本现在为 22
  • 对聊天组件序列化进行了一些细微更改

命令

函数

（更多更改见数据包版本 23）

  • function 命令已更改，以更好地适应新的 return 命令
  • 函数现在不再有任何结果，除非它们使用了 return，或在查找或实例化期间出现错误
    • 这意味着 function 命令将不再返回（甚至显示）执行期间运行的命令数量
    • 错误情况：
      • 调用不存在的函数
      • 调用空函数标签
      • 宏实例化失败
  • 此处的“结果”指通过 execute store 存储的值
  • 以前如果使用 execute store ... run function 调用函数，函数中的每个命令都会执行一次存储，此行为已被移除
    • 现在单次调用 function 最多存储一次（如果未调用 return，则为零次）
    • 对于包含多个条目的函数标签，函数结果会被累加，但部分结果会在每个函数结束时存储

限制

现有的函数限制已进行细化，以适应新的执行规则并防止更广泛的漏洞利用：

  • 即使是从服务器控制台或聊天输入运行的命令，现在也会受到限制（因此现在总是表现得就像它们被放在函数中一样）
    • 例如，由 execute as @e run function 调用的所有函数都将计入同一限制
    • 来自命令方块的执行仍被视为独立执行
  • 函数的 maxCommandChainLength 限制现在会计算“操作”，例如：
    • 为单个上下文执行命令
    • 在 execute 中执行一个阶段（无论修改了多少个上下文）
    • 调用函数
  • 一个新的游戏规则 maxCommandForkCount 现在限制像 execute 这样的函数在单个状态下可以创建的上下文总数
    • 例如：如果世界中有 5 个实体，execute as @e 会创建 5 个上下文，而 execute as @e at @e 会创建 5*5 = 25 个上下文

execute if function

execute 的一个子命令，用于运行函数或函数标签并匹配返回值。这是对先前版本中移除的功能的重新引入。如果给定的是标签，则所有函数都会运行，无论先前函数的结果如何。

语法： execute if|unless function <function> <continuation>

参数：

  • function：要运行的函数或标签

匹配

对运行的函数的返回值进行匹配：

  • 至少有一个函数必须成功，匹配才会成功
  • 成功调用定义为满足以下条件的函数：
    • 使用 return 命令返回一个值
    • 返回值不为 0
  • 如果没有函数通过 return 退出，则 if 和 unless 都不会执行

return run

return 命令的一种形式现在可用：return run。这是对先前版本中移除的功能的重新引入。

语法： return run <command>

这会从运行指定 command 的结果中取得 result 值，并将其作为函数的返回值返回。

  • 如果命令没有返回任何值（例如调用没有 return 的 function），则 return 不会执行，函数将继续执行（在数据包版本 23 中更改）
  • 如果给定命令失败，返回值为 0
  • 在其他所有方面，它与指定返回值的 return 相同
  • 在分叉的情况下（例如 return run execute as @e run some_command），命令的第一次执行将返回
    • 如果没有执行（例如在 return run execute if entity @e[something_impossible] run some_command 中），函数将不会返回并继续执行（在数据包版本 23 中更改）

tick 命令

添加了一条新的 tick 命令。这是一条管理和调试命令，允许控制游戏刻的流程并测量游戏性能。该命令需要提升的权限（管理员及以上），因此默认情况下在命令方块和数据包中不可用。

语法：

tick query - 输出当前目标游戏刻速率，并附带游戏刻时间性能的信息。

tick rate <rate> - 将自定义目标游戏刻速率设置为指定值。该值必须大于 1.0 且小于 10000.0。设置非常低的游戏刻速率可能会使游戏感觉无响应，而将游戏刻速率设置得过高则可能导致游戏崩溃，因为游戏现在会认为它始终落后于目标游戏刻。请使用 tick query 或 <F3> + 2（仅内置服务器）调试界面来测量游戏性能，并相应地调整游戏刻速率。将游戏刻目标设置为低于默认值 20.0 还会导致玩家以较低的速率进行模拟（包括玩家移动和输入控制），而设置较高的游戏刻速率会导致玩家以默认的每秒 20 游戏刻的速率进行模拟，以保持预期的游戏响应性，但可能会导致实体插值出现伪影。

tick freeze - 冻结所有游戏玩法元素，但玩家和玩家骑乘的任何实体除外。这对于调试和隔离游戏问题很有用，允许玩家自由移动并检查世界。

tick step [<time>] - 仅在游戏被冻结时有效。它以指定的游戏刻数运行游戏，然后再次冻结游戏。这允许一次按设定的游戏刻数逐步运行游戏。如果未指定时间，则单步执行 1 个游戏刻。

tick step stop - 停止当前的单步执行过程，并重新冻结游戏。

tick unfreeze - 解冻游戏并恢复所有游戏玩法元素。

tick sprint <time> - 在指定的游戏刻数内运行游戏，同时忽略设定的游戏刻目标速率（意味着游戏将尽可能快地运行）。在加速运行结束时，游戏将恢复先前的游戏刻目标，并显示加速运行期间游戏刻时间的性能信息。这对于测试依赖时间的游戏玩法元素特别有用，例如红石装置，或隔离环境中的生物行为，这些环境允许更快的模拟。

tick sprint stop - 停止当前的 tick 加速运行，并恢复先前的游戏刻目标。

拼图选择与放置优先级

  • 选择优先级
    • 当父拼图正在处理连接时，这会控制此拼图方块尝试连接到其目标拼图的顺序
    • 拼图将按优先级降序处理，并在同一优先级内随机处理
  • 放置优先级
    • 当此拼图方块连接到一个拼图时，这是该拼图在更大的结构中处理连接的顺序
    • 拼图将按优先级降序处理，默认插入顺序用于在同一优先级内打破平局
  • 添加此功能是为了支持拼图结构以深度优先顺序生成分支，并更精细地控制连接的顺序
  • 所有现有的拼图方块默认将选择优先级和放置优先级设为 0，这与引入这两个可配置值之前的行为相同

命令

return

  • return run 现在总会返回
    • 如果返回的命令没有有效结果，包含 return run 的函数将失败（即 success=0 且 result=0）
  • return run 现在会将成功值与结果值一起传递（以前它总是将 success 设为 1）
  • return run 现在也允许存储值 - 这意味着 execute store ... run return run some_command 将同时存储该值并将其返回函数外部
  • 添加了一个新的子命令 return fail，使整个函数失败（即返回 success=0 和 result=0）

function

  • 如果 function <function tag> 与 return run 结合运行多个函数，执行将在任一函数中的第一个 return 后停止
  • 当与 return run 一起运行时，对 function 命令的单个调用总会返回
    • 例如，return run execute [split context] run function <some function with conditional return> 在处理第一个上下文后总会返回

execute if|unless function

  • execute if|unless function 在没有任何函数具有 return 时不再总是失败
    • 如果调用的函数中没有 return，则 if 将失败，unless 将通过
    • 任何被调用函数中的第一个 return 将返回（对于单个上下文）

显示名称

记分板中的每个条目现在都可以有自定义显示名称。

  • 这些值按计分项和分数持有者分别保留
  • 如果名称不存在，则使用分数持有者的名称（即旧行为）
  • 如果分数被重置或整个计分项被移除，该名称不会被保留
  • 队伍装饰仍会照常应用于名称
  • 用于管理名称的子命令：
    • scoreboard players display name <targets> <objective> <text component> - 设置显示名称
    • scoreboard players display name <targets> <objective> - 清除显示名称

显示名称自动更新

为了使显示名称管理更轻松，还可以将计分项配置为在每次分数更新时自动更新显示名称。

  • 此选项默认禁用
  • 如果分数持有者没有显示名称（因为无法归属于任何当前加载的实体），则保留当前名称
  • 控制计分项自动更新的命令：
    • scoreboard objectives modify <scoreboard> displayautoupdate [true|false]

数字格式

数字形式的分数现在可以设置格式。

  • 可以为计分项和单个分数设置格式
  • 设置了格式的分数将在所有上下文中以相同方式渲染（侧边栏、玩家名称下方等）
  • 用于管理格式的子命令：
    • scoreboard objectives modify <objective> numberformat <format> - 设置计分项的默认格式
    • scoreboard objectives modify <objective> numberformat - 清除计分项的默认格式
    • scoreboard players display numberformat <targets> <score> <format> - 为特定分数持有者设置格式
    • scoreboard players display numberformat <targets> <score> - 清除特定分数持有者的格式
  • 格式：
    • styled <style> - 分数将使用所选样式显示（如 {"bold":true}）
    • fixed <text component> - 分数将被文本组件替换
    • blank - 分数将不显示

  • 收到信号后，合成器会从正面弹出配方结果
  • 如果输出结果包含多种类型的物品，所有结果物品将一起弹出
  • 放置时，合成器的正面将朝向玩家

合成器用户界面

  • 合成器有一个 3x3 的可交互合成网格
  • 合成器的合成网格槽位是可切换的，意味着玩家可以在未手持物品时与其交互来改变槽位的行为
  • 被“切换”的槽位不能容纳任何物品
    • 其他方块如漏斗和投掷器也不能将物品放入其中
  • 与工作台不同，合成器会显示将要在下一次红石脉冲时合成并弹出的物品预览，但玩家不能手动取出
  • 合成器的用户界面在所有与它交互的玩家之间共享，意味着多个玩家可以同时与合成器交互，类似于箱子和漏斗

合成器与其他方块的交互

  • 比较器读取合成器的信号强度为 0-9，其中每个非空或已切换的槽位增加 1 点强度
  • 漏斗和漏斗矿车可以用于向合成器放入和取出物品
  • 投掷器可以用于向合成器放入物品
  • 从其他方块（例如漏斗、投掷器）放入的物品将根据以下规则填充合成器的槽位：
    • 优先选择第一个空槽位（从左到右，从上到下）
    • 如果没有空槽位，则优先选择同种物品的最小堆叠（如果有多个，则选择第一个）
    • 如果有已切换的槽位，则跳过。物品随后会被移入容器
    • 如果物品无法移动，它将被弹出到世界中
  • 漏斗和漏斗矿车从合成器中取出物品的顺序与从箱子等其他容器中取出的顺序相同

铜质方块家族

铜质方块家族已扩展，包括：

  • 錾制铜块
  • 铜格栅
  • 铜灯
  • 铜门
  • 铜活板门
  • 以上所有方块的氧化和涂蜡变种

錾制铜块

  • 由 2 个相同氧化等级的切制铜台阶合成
  • 可以在切石机中合成

铜格栅

  • 一种铜质家族独有的新型装饰性方块
  • 由 4 个相同氧化等级的铜块合成
    • 可以在切石机中合成
  • 属性：
    • 透明，允许光线穿过
    • 生物不会在其中窒息
    • 不能传导红石
    • 敌对生物不能在其上自然生成
    • 可以含水

铜灯

  • 一个发光方块，可以通过红石脉冲切换其发光状态
  • 像其他铜块一样氧化，并根据氧化程度发光
    • 铜灯：光照等级 15
    • 斑驳的铜灯：光照等级 12
    • 风化的铜灯：光照等级 8
    • 氧化的铜灯：光照等级 4
  • 放置时，其灯光默认关闭
    • 当铜灯未通电时，它会在收到红石脉冲时切换灯光的开或关
    • 即使移除红石源，铜灯也会保持开启，直到收到另一个红石脉冲将其关闭
  • 当铜灯被红石信号供电时，其中心会有一个红石晶体发光
  • 如果铜灯的灯是亮的，比较器将读取到 15 的信号强度
  • 铜灯不传导红石能量
  • 合成 4 个铜灯的配方是：
    • 3 个相同氧化等级的铜块
    • 1 个烈焰棒
    • 1 个红石粉

铜门和铜活板门

  • 门和活板门的铜质变种，可以随时间氧化并涂蜡
  • 像木门一样，可以通过交互以及红石打开和关闭
  • 由具有相同氧化等级的铜块合成

凝灰岩方块家族

凝灰岩已扩展为拥有自己的方块家族，包括：

  • 楼梯、台阶、墙和錾制变种
  • 凝灰岩砖及其楼梯、台阶、墙和錾制变种
  • 磨制凝灰岩及其楼梯、台阶和墙变种

所有凝灰岩变种都可以在切石机中合成。

添加了旋风人生物

  • 旋风人是一种狡猾的敌对生物，由试炼密室中某些房间内的试炼刷怪笼生成
  • 旋风人主要通过在其目标周围跳跃来移动
  • 作为一个具有攻击性的对手，旋风人会以风弹弹射物的形式向目标发射不稳定的风能
  • 风弹直接碰撞实体时会造成少量伤害
  • 风弹弹射物在碰撞实体或方块后会产生风爆，击退区域内的实体
  • 风弹在碰撞时会破坏饰纹陶罐和紫颂花方块
  • 风爆还具有“激活”某些方块的效果：
    • 非铁门和活板门被翻转
    • 栅栏门被翻转
    • 按钮被按下
    • 拉杆被拨动
    • 钟被敲响并摆动
    • 点燃的蜡烛被熄灭
  • 风爆对铁门、铁活板门或任何被红石信号固定在其位置的方块无效

试炼刷怪笼

  • 试炼刷怪笼是刷怪笼的新变种，会在完成后弹出奖励
  • 试炼刷怪笼每注意到附近一位新玩家，挑战等级就会增加
    • 在试炼刷怪笼冷却期间重置之前，挑战等级不会降低
  • 与普通刷怪笼不同，试炼刷怪笼会生成与其当前挑战等级成比例的有限数量生物
    • 它只能在视线范围内的位置生成生物
    • 无论生物是否有光照等级要求，它都可以生成生物
    • 生成的生物不会消失
  • 一旦所有生物被击败，试炼刷怪笼将弹出与当前挑战等级成比例的一组奖励
    • 奖励弹出后，试炼刷怪笼将进入 30 分钟的冷却，期间不再生成生物
  • 试炼刷怪笼无法在生存模式中合成或获得——相反，它们可以自然生成在试炼密室中
  • 试炼刷怪笼的挖掘速度极慢，且抗爆炸，即使使用精准采集也不会掉落
  • 在创造模式中放置时，试炼刷怪笼默认不设置生物类型
    • 手持刷怪蛋与其交互可以设置生物类型
  • 创造模式和旁观模式的玩家不会被试炼刷怪笼检测或注意到

试炼密室

  • 试炼密室是主世界中的一种新结构，玩家可以在其中探索并接受战斗挑战
    • 试炼密室由各种铜和凝灰岩方块构成，以不同大小生成
    • 在地下深板岩层中，试炼密室是比较常见的发现
  • 每个试炼密室的布局是程序化生成的，可能包含陷阱、奖励箱和各种战斗区域
    • 在不同房间之间可以找到补给箱，它们会提供方块和物品，帮助你完成试炼
    • 奖励箱由每个房间中的挑战守卫，可以成为许多高级附魔书和装备的来源
    • 奖励箱中的战利品仍在迭代中，绝对尚未最终确定
  • 每个试炼密室都会包含具有近战、小型近战或远程类别的试炼刷怪笼：
    • 近战
      • 僵尸
      • 尸壳
      • 史莱姆
    • 小型近战
      • 蜘蛛
      • 洞穴蜘蛛
      • 小僵尸
      • 蠹虫
    • 远程
      • 骷髅
      • 流浪者
      • 使用剧毒之箭的骷髅
  • 生成时，每个试炼刷怪笼类别在整个结构中只会使用一种生物，这些生物对每个试炼密室都是随机的
    • 例如，一个试炼密室可能只生成僵尸、洞穴蜘蛛和流浪者，而另一个可能只生成史莱姆、蠹虫和骷髅
    • 例外是独特房间中的一些试炼刷怪笼，它们总是生成旋风人
  • 试炼密室内不会自然生成生物
