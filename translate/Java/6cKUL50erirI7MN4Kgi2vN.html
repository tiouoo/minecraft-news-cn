在本快照中，我们对红石线做了一些更改，并修复了大量漏洞。

20w18a 的更改

  • 红石线更改
  • 标靶方块现在会传导红石信号

​

红石线

红石线的方块状态、渲染和行为现在更加一致。红石会向所有视觉上连接的方向提供信号，而不会向没有视觉连接的方向提供信号。 ​

  • 单条红石线现在显示为十字形。
  • 位于方块顶部、被从下方转向的红石线现在会向其转向的方向提供信号。例如，转向线上方的栅栏门会接收到信号。
  • 过去，向上转向到非导电方块上的红石线仅会进行视觉转向。现在这种转向也会应用到行为上。
  • 被转向越过方块的红石线现在总会向该方块提供信号。当信号强度为 1 时最为明显。

​

20w18a 中的技术性更改

  • 为 server.properties 添加了 enable-status 选项，将其设为 false 时，将不回复来自客户端的状态请求。这会使服务器在多人游戏界面中显示为离线。
  • 添加了对服务器向客户端发送实体数据量的控制
  • 进度系统更改

​

实体广播

现在可以控制服务器在多大范围内向客户端发送实体数据。 ​

  • 添加了 entity-broadcast-range-percentage 服务器属性，用于控制实体在距离多近时才会发送给客户端。值越高，实体在离玩家更远的地方可见，但会产生更多网络流量。该值指定为默认值的百分比，例如 50 表示默认范围的一半。

​

进度

  • 为每个触发器（除了 impossible）添加了 player 检查
  • 触发器中的实体检查现在可以使用战利品表条件语法

​

扩展的实体检查

触发器中的实体检查现在可以使用战利品表条件语法。旧写法：

{
  "trigger": "minecraft:player_killed_entity",
  "conditions": {
    "entity": {
      "type": "minecraft:blaze"
    }
  }
}

现在等同于：

{
  "trigger": "minecraft:player_killed_entity",
  "conditions": {
    "entity": [
      {
        "condition": "minecraft:entity_properties",
        "predicate": {
          "type": "minecraft:blaze"
        },
        "entity": "this"
      }
    ]
  }
}

注 1：与战利品表一样，顶层数组中的所有条件都必须满足，整个条件才会触发。 ​ 注 2：要使用新功能，顶层元素必须是 JSON 数组。JSON 对象则按旧写法解释。
​ 扩展触发器的完整列表：

  • 每个触发器中的新字段 player
  • bred_animals - parent, partner, child
  • channeled_lightning - victims
  • cured_zombie_villager - zombie, villager
  • fishing_rod_hooked - entity
  • killed_by_crossbow - victims
  • player_killed_entity - entity
  • entity_killed_player - entity
  • player_hurt_entity - entity
  • summoned_entity - entity
  • tame_animal - entity
  • target_hit - projectile
  • villager_trade - villager

​

其他触发器更改

  • 由于新增了 player，location、slept_in_bed、hero_of_the_village、voluntary_exile 的现有内容现在可以放在 location 字段中，而不必放在顶层对象中。旧语法仍受支持，但已弃用。
