收纳袋

  • 收纳袋是一种可以将不同物品打包进同一个物品堆叠中的物品
  • 一个收纳袋只能容纳一组物品（通常为 64 个），但可以是许多不同物品类型的混合
  • 你可以直接在物品栏中将物品放入收纳袋
  • 收纳袋有一个工具提示，显示其中的物品
    • 如果收纳袋内的物品种类少于 12 种，工具提示将显示全部物品
    • 否则，工具提示将显示前三行物品（至少 8 种物品类型），其余物品将被隐藏在下
  • 你可以选择任意可见物品从收纳袋中取出
    • 右键点击取出第一个物品
    • 使用滚轮选择其他物品，然后右键点击将其取出
  • 选择要取出的物品时，收纳袋图标会显示该物品从收纳袋中伸出的样子
  • 手持收纳袋时，你可以通过右键点击或长按右键将物品清空到地上
  • 收纳袋由一根线放在一块皮革上方合成
  • 控制方式与原始原型相比有所更改：
    • 使用左键将物品放入收纳袋
    • 使用右键从收纳袋中取出顶部的物品种类
    • 当收纳袋工具提示可见时，使用鼠标滚轮选择其他物品种类，然后使用右键将其取出

稀有度

  • 稀有度是一组类别，用于决定物品或方块名称显示的颜色
    • 它对游戏玩法没有影响，但用于表明获取某物的难度
    • 默认情况下，除非另有说明，所有物品和方块都具有“常见”稀有度，其名称以白色显示
  • 我们重新评估了游戏中所有物品和方块的稀有度，以更准确地反映当前获取它们的难度，依据以下准则：
    • 物品和方块根据以下因素变得更加稀有：
      • 在战利品表中找到它的几率，包括生物掉落物
      • 获取它所需的旅行量
      • 必须克服的障碍的难度
      • 该物品或方块在世界上可能存在的数量
    • 任何可以合成的物品或方块必须继承其合成材料中最高的稀有度
      • 例如，重锤具有史诗稀有度，因为其材料之一（沉重核心）具有史诗稀有度
      • 同样，任何仅有常见合成材料的合成物品也必须是常见稀有度

rotate 命令

用于旋转实体的新命令。

语法：

rotate <target> <rotation>
rotate <target> facing <facingLocation>
rotate <target> facing entity <facingTarget> [<facingAnchor>]

参数：

  • target：要旋转的实体
  • rotation：以度数表示的两个旋转值，分别表示水平和垂直旋转
    • 可以使用相对（~）坐标表示法来指定相对于当前上下文旋转的旋转值
  • facingLocation：世界中一个位置的坐标，被旋转的实体将面向该位置
  • facingTarget：被旋转的实体要面向的实体
  • facingAnchor：指定 facingTarget 实体朝向的锚点 - feet 或 eyes（默认为 feet）

注意：参数与 teleport 命令中的含义相同。

      • 默认值：false

minecraft:fire_resistant -> minecraft:damage_resistant

  • 新增字段：types，带 # 前缀的伤害类型标签
    • 具有此组件的物品在实体形态下，将对此标签中包含的伤害类型免疫
    • 此组件还影响当穿戴者受到特定伤害类型伤害时，已装备的物品是否会受损

  • 此组件现在始终存在于每个物品上
  • 此组件提供的名称始终具有最低优先级
    • 这意味着它会被诸如 minecraft:potion_contents 或 minecraft:written_book_content 等组件覆盖

    • 存在时，将用于生成所包含物品堆叠的名称
    • 例如，如果值为 foo 且物品是 minecraft:lingering_potion，则物品名称将是 item.minecraft.lingering_potion.effect.foo 的翻译

新物品组件

minecraft:consumable

  • 存在时，此物品可以在使用时被食用
    • 如果此物品上同时存在 food、potion_contents、ominous_bottle_amplifier 或 suspicious_stew_contents，食用将应用这些组件的属性和效果
  • 格式：包含字段的对象
    • consume_seconds：非负浮点数，玩家食用此物品所需的秒数
      • 默认值：1.6
    • animation：食用物品期间使用的动画
      • 默认值：eat
      • 接受的值：
        • none
        • eat
        • drink
        • block
        • bow
        • spear
        • crossbow
        • spyglass
        • toot_horn
        • brush
    • sound：声音事件，在物品食用期间和完成时使用的声音
      • 默认值：entity.generic.eat
    • has_consume_particles：布尔值，食用此物品时是否发出食用粒子
      • 默认值：true
    • on_consume_effects：可选的副作用列表，作为食用此物品的结果触发
      • 目前有 5 种有效的食用效果，通过 type 字段标识
      • minecraft:apply_effects
        • effects：食用后应用的状态效果实例列表
        • probability：浮点数，上述效果在食用后被应用的概率
          • 默认值：1.0
      • minecraft:remove_effects
        • effects：食用后移除的状态效果集合，可以是状态效果 ID、带 # 前缀的标签或 ID 列表
      • minecraft:clear_all_effects
        • 清除食用者的所有状态效果
      • minecraft:teleport_randomly
        • diameter：正浮点数，食用者将被传送到的直径范围
          • 默认值：16.0
      • minecraft:play_sound
        • sound：声音事件，食用后播放
    • 例如 consumable={consume_seconds:3.0, animation:'eat', sound:'entity.generic.eat', has_consume_particles:true, on_consume_effects:[{type:'minecraft:clear_all_effects'}]}

minecraft:use_remainder

  • 存在时，如果物品堆叠数量在使用后减少，将替换为余物物品
    • 如果物品在使用后堆叠数量仍大于 0，余物物品将被添加到物品栏中
    • 如果尝试将余物物品添加到已满的物品栏时，它将被掉落到地上
  • 格式：单个物品堆叠值
    • 例如 use_remainder={id:'minecraft:stick',count:1}

minecraft:use_cooldown

  • 存在时，此物品在使用后将对所有相同类型或“冷却组”中的物品施加冷却时间
  • 格式：包含字段的对象
    • seconds：正浮点数，冷却持续的时间（秒）
    • cooldown_group：可选的命名空间 ID，表示冷却组
      • 具有相同冷却组的物品将共享应用于该组中其他物品的冷却时间
      • 如果未指定，冷却组默认为基础物品类型的 ID
    • 例如 use_cooldown={seconds:1.5,cooldown_group:"minecraft:custom_weapon"}

minecraft:item_model

  • 控制物品模型
  • 存在于每个物品上
  • 格式：命名空间 ID
    • namespace:id 将引用模型 /assets/<namespace>/models/item/<id>

minecraft:equippable

  • 存在时，此物品可以被玩家装备到所选槽位
  • 格式：包含字段的对象
    • slot：head、chest、legs、feet、body、mainhand 或 offhand 之一
    • equip_sound（可选）：装备物品时播放的声音事件
      • 如果未指定，将播放默认的盔甲装备声音
    • model（可选）：装备时使用的装备模型的命名空间 ID
      • 这些模型定义从资源包中加载
      • 如果未指定，在头部槽位时将回退为以物品本身渲染（如不适用则不渲染）
    • camera_overlay（可选）：装备时使用的叠加纹理的命名空间 ID
      • 如果未指定，则不使用叠加纹理
      • 该 ID 指向 textures/ 文件夹下的纹理，并自动假定为 .png
        • 例如，misc/pumpkinblur 指向 textures/misc/pumpkinblur.png
    • allowed_entities（可选）：实体 ID、实体标签或实体 ID 列表，用于限制哪些实体可以装备此物品
      • 如果未指定，则允许任何（可以穿戴此类装备的）实体装备此物品
    • dispensable：布尔值（默认值：true），是否可以通过发射器来装备此物品
      • 如果物品类型具有特殊的发射器行为，则此属性无效
    • swappable：布尔值（默认值：true），是否可以通过右键点击将物品装备到相关槽位
    • damage_on_hurt：布尔值（默认值：true），当穿戴实体受伤时此物品是否会受损
    • 例如 equippable={slot:'chest',equip_sound:'item.armor.equip_chain'}

minecraft:glider

  • 存在时，此物品在装备后将允许玩家滑翔（如同鞘翅）
  • 格式：空对象
    • 例如 glider={}

minecraft:tooltip_style

  • 存在时，此物品可以为工具提示背景和边框使用自定义精灵图
  • 格式：工具提示样式的命名空间 ID
    • namespace:path 的工具提示样式将使用以下 ID 的精灵图：
      • <namespace>:tooltip/<path>_background 和 <namespace>:tooltip/<path>_frame
    • 例如 tooltip_style='minecraft:special_sword'

minecraft:death_protection

  • 存在时，此物品将保护持有者免于死亡，恢复 1 点生命值
  • 格式：包含字段的对象
    • death_effects：可选的触发效果列表，当物品保护持有者时应用
      • 这些效果与 consumable 组件中 on_consume_effects 字段指定的效果相同

minecraft:repairable

  • 存在时，且此物品是可损耗的，则此物品可以在铁砧中使用指定材料修复
  • 格式：包含字段的对象

    • 例如 repairable={items:'stick'}

minecraft:enchantable

  • 存在时（且有任何适用的附魔），此物品可以在附魔台中被附魔
  • 格式：包含字段的对象
    • value：正整数，值越高允许选择成本越高的附魔
    • 例如 enchantable={value:15}

    自定义装备层

    玩家或某些生物装备时的装备外观现在可以通过在资源包中定义“装备模型”来自定义。

    • 装备模型定义从 assets/<namespace>/models/equipment/<path>.json 加载
      • 然后可以被 equippable 组件通过模型 ID namespace:path 引用
    • 模型定义是一个包含字段的对象：wolf_body、horse_body、llama_body、humanoid、humanoid_leggings、wings
      • 所有字段都是可选的，可以用于为给定的模型层类型指定层列表
      • 每个字段包含层对象列表：
        • texture：此层的命名空间纹理位置
          • namespace:path 将解析为 assets/<namespace>/textures/entity/equipment/<layer_type>/<path>.png
        • dyeable：可选对象，包含指定此层在被染色时（在 dyeable 物品标签中，且具有 dyed_color 组件时）行为的字段
          • color_when_undyed：rgb 颜色整数（可选）
          • 如果指定，此层将被 dyed_color 组件中包含的颜色着色
            • 如果物品不可染色或未染色，将根据 color_when_undyed 指定的颜色着色
            • 如果未指定 color_when_undyed 且物品未染色，该层将被隐藏
        • use_player_texture：布尔值（默认值：false），如果此层纹理应被玩家提供的纹理覆盖，则为 true
          • 仅用于 wings 层，将使用玩家的自定义鞘翅纹理进行覆盖

    同时指定玩家和马盔甲层的模型定义可能如下所示：

    {
  "layers": {
    "horse_body": [
      { "texture": "minecraft:iron" }
    ],
    "humanoid": [
      { "texture": "minecraft:iron" }
    ],
    "humanoid_leggings": [
      { "texture": "minecraft:iron" }
    ]
  }
}

    着色器与后期处理效果

    开发者注：虽然在资源包中是可行的，但覆盖核心着色器被视为不受支持的功能，并非资源包的本意功能。这些着色器作为游戏内部实现的一部分存在，因此可能随着游戏内部的演变而随时变化。我们理解覆盖核心着色器被用于制作非常酷的资源包功能，其中许多功能缺乏受支持的替代方案。我们希望在将来提供更好的、受支持的替代方案。

    • 着色器程序配置现在可以指定要应用于其链接着色器的预处理宏指令
      • 通过利用这一点，许多着色器实现已被合并
    • 核心着色器和后期处理着色器配置的格式已统一
    • 后期处理效果配置的格式已更新
    • 地形着色器中的 ChunkOffset 统一变量已重命名为 ModelOffset
    • rendertype_entity_glint_direct 着色器已移除（由 rendertype_entity_glint 取代）
    • rendertype_entity_translucent_cull 着色器已移除（由 rendertype_item_entity_translucent_cull 取代）

    着色器程序定义

    • 后期处理效果的程序定义（assets/<namespace>/shaders/program/<name>.json）已与核心着色器定义（assets/<namespace>/shaders/core/<name>.json）保持一致
      • blend 字段已移除，因为它没有用处
      • attributes 字段已移除，取而代之的是 Position 属性将始终被绑定
      • 提供的统一变量已与提供给核心着色器的统一变量合并
        • Time 已重命名为 GameTime
    • 程序定义（包括后期处理效果）中的 vertex 和 fragment 着色器引用现在是命名空间着色器 ID
      • 顶点着色器 <namespace>:<path> 将解析为 assets/<namespace>/shaders/<path>.vsh
      • 片段着色器 <namespace>:<path> 将解析为 assets/<namespace>/shaders/<path>.fsh
    • 着色器源文件不再需要位于 shaders/core 子目录中，该目录仅为组织目的而存在
    • 在程序定义中加入了 defines 字段（包含字段的对象）
      • 允许将 GLSL 宏指令注入着色器源中，可供着色器引用
      • values（字符串到字符串的映射）
        • 将以 #define <key> <value> 的形式注入到文件顶部
      • flags（字符串列表）
        • 将以 #define <key> 的形式注入到文件顶部

    着色器导入

    • #moj_import 指令现在支持使用绝对路径的命名空间包含
      • 例如，#moj_import <minecraft:fog.glsl> 将导入 assets/minecraft/shaders/include/fog.glsl
    • 相对导入不进行命名空间解析，行为与之前相同

    后期处理效果定义

    • 后期处理效果配置已从 assets/<namespace>/shaders/post 目录移出，移至 assets/<namespace>/post_effect
    • 这些效果使用的顶点和片段着色器已从 assets/<namespace>/shaders/program 移至 assets/<namespace>/shaders/post
    • name 已重命名为 program，现在是一个着色器程序配置的命名空间 ID
      • <namespace>:<path> 将解析为 assets/<namespace>/shaders/<path>.json
    • intarget 和 auxtargets 已合并为单个 inputs 列表，如下面的输入格式所述
    • outtarget 已重命名为 output，格式相同
    • targets 现在是目标名称与目标定义之间的映射，而不是列表
      • 内联目标名称被替换为空对象
        • 例如，["swap"] 变为 {"swap": {}}
      • 具有特定大小的目标定义保持不变，name 字段移入映射键中
        • 例如，[{"name": "potato", "width": 16, "height": 16}] 变为 {"potato": {"width": 16, "height": 16}}

    输入格式

    对于渲染目标和纹理输入，可以指定以下字段：

    • sampler_name：字符串 - 前缀，用于同时设置 _Sampler 和 _Size 统一变量
      • 例如，"sampler_name": "Diffuse" 将链接到 DiffuseSampler 和 DiffuseSize 统一变量
      • 对于 intarget，先前始终是 DiffuseSampler 和 InSize
      • 对于 auxtargets，name 定义了采样器统一变量，大小以 AuxSize<index> 给出
    • bilinear：布尔值（默认值：false）- 如果为 true，输入将使用双线性过滤器进行采样
      • 这先前仅存在于纹理输入上，但现在对渲染目标也有效
      • 对于渲染目标，取代了传递定义上现已移除的 use_linear_filter 字段

    对于来自渲染目标的输入，可以指定以下字段：

    • target：命名空间 ID - 渲染目标 ID
      • 可以是同一文件中定义的自定义目标 ID，或者 minecraft:main 以引用主屏幕目标
      • 这取代了先前的 id 字段，该字段是自由格式字符串
    • use_depth_buffer：布尔值（默认值：false）- 为 true 时从深度纹理采样，为 false 时从颜色纹理采样
      • 这取代了先前应用于目标 ID 的 :depth 后缀

    对于来自静态纹理的输入，可以指定以下字段：

    • location：命名空间字符串 - 可被效果采样的静态纹理文件的位置
      • 与先前的 id 字段一样，这解析为 assets/<namespace>/textures/effect/<path>.png 处的纹理
    • width：正整数 - 纹理的像素宽度
    • height：正整数 - 纹理的像素高度

    外部目标

    • “极佳！”画质的透明度后期处理配置不再将排序帧缓冲指定为自定义目标
      • 它们改为以与 minecraft:main 目标相同的方式导入
      • translucent、itemEntity、particles、weather、clouds 现在分别是 minecraft:translucent、minecraft:item_entity、minecraft:particles、minecraft:weather 和 minecraft:clouds
    • 实体轮廓处理着色器类似地导入 minecraft:entity_outline 目标

    翻译的移除和重命名

    • 加载期间，一些废弃的翻译字符串现在将被移除和/或重命名
    • 使用这些翻译的包需要手动重新添加它们
    • 完整列表可在游戏 JAR 文件中的 /assets/minecraft/lang/deprecated.json 文件中找到

    • 如果有生存或冒险模式玩家正在看着嘎枝，被激活的嘎枝不会移动
    • 嘎枝对伤害免疫
    • 嘎枝具有火焰抗性
    • 被玩家击中时，嘎枝与其连接的嘎枝之心方块之间会显示粒子轨迹

    • 头上戴着雕刻南瓜的玩家可以看着嘎枝而不会让它冻结不动

      • 在可能的情况下，顺序根据引起更新的上下文确定性地决定
      • 当没有足够的上下文来完全确定顺序时，其余部分随机选择

    开发者注：我们知道红石中的随机性通常是不受欢迎的。
    我们在这里使用它是因为我们已经在有意义的地方使事情变得确定，但有时确实没有意义 - 我们不希望某些隐藏状态（比如基于位置的哈希！）决定顺序，使机器在不同坐标或不同朝向下工作方式不同。

    一条红石线变化的顺序

    • 当一条红石线开启时，离电源更近的线会先引起方块更新
    • 当一条红石线关闭时，离原电源更近的线会先引起方块更新
    • 当两条线与电源距离相同时，在传播方向上左侧的线先更新
      • 如果没有足够的上下文来确定传播方向（当线路从上方或下方被供电时），先更新的那一侧是随机选择的

    线路周围的方块更新

    • 线路周围方块更新的顺序基于线路接收更新的方向
    • 更新顺序为：后、前、左、右、下、上
    • 当更新通过实心方块进一步传播时，同样适用相同的顺序
