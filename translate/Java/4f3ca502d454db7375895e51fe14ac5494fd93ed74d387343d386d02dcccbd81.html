更改

  • 现在，村民职业解锁哪些交易由确定性随机序列决定，就像战利品掉落和以物易物战利品一样
  • 将方块光照和天空光照等级映射到屏幕上显示亮度的算法已被完全重写
  • 引入了新的光照图调试渲染器，可使用 F3 + 4 键位启用

光照图算法更改

  • 新算法理应提供与之前大体相同的整体结果，但是：
    • 它更简单、更直接，并修复了旧算法的多个问题，详见下文“修复的漏洞”部分
    • 黑暗效果和凋灵战斗中的世界变暗效果现在在所有维度中的表现都相同
    • 夜视效果现在只是增加环境光，而不是缩放最终颜色
      • 这意味着完全黑暗的区域不再比被方块光或天空光照亮的区域看起来更亮
    • 算法的更多方面（例如方块光色调、环境光颜色和夜视颜色）现在通过环境属性进行数据驱动，如下文数据包部分所述

光照图调试渲染器

  • 添加了新的光照图调试渲染器，可通过 F3 + 4 键位启用
  • 它与 FPS/TPS 和网络图表互斥
  • 它会在屏幕右下角实时显示光照图纹理
  • 纹理的纵轴表示天空光照等级（从下到上为 0-15）
  • 纹理的横轴表示方块光照等级（从左到右为 0-15）
  • 每个像素的颜色代表将应用于具有相应方块光和天空光照等级照亮的方块和实体的最终颜色

数据驱动的村民交易

村民和流浪商人提供的交易现在由数据驱动，数据包开发者可以自定义这些交易

村民交易

  • 位于 villager_trade 文件夹中，代表交易的蓝图，村民和流浪商人使用它来生成实际交易
  • 条目格式：
    • wants：一个对象，表示交易所需的物品类型和数量
      • id：物品的 ID
      • count：一个可选的数字提供器，表示交易需要多少该物品
        • 默认为常量 1
      • components：一个可选的组件映射，表示物品上预期的数据组件
        • 默认为空映射
    • additional_wants：一个可选对象，表示商人额外要求的物品，格式与 wants 相同
    • gives：一个物品堆叠，表示交易时商人给出的结果物品
      • 使用现有的物品堆叠格式
    • given_item_modifiers：一个可选的物品修饰器列表，表示应用于 gives 中物品的修饰器（例如附魔或药水），用于为交易增添动态性，而不是硬编码某些值
      • 使用现有的物品修饰器格式（也称为战利品修饰器、物品函数、战利品函数……）
      • 如果其中任何一个返回空物品，则整个交易将被丢弃
      • 尚不支持物品修饰器引用
      • 如果最终物品的 stored_enchantment 组件包含 #double_trade_price 标签中的附魔，则 wants 的数量会加倍
    • max_uses：一个可选的数字提供器，表示交易最多可使用的次数
      • 如果数字提供器返回较低的值，则设置为 1
      • 默认为 4
    • reputation_discount：一个数字提供器，表示需求、折扣或惩罚等因素对 wants 所表示成本的影响程度
      • 如果数字提供器返回较低的值，则设置为 0.0
      • 默认为 0.0
    • xp：一个可选的数字提供器，表示交易完成后商人获得的经验值数量
      • 如果数字提供器返回较低的值，则设置为 0
      • 默认为 1
    • merchant_predicate：一个谓词，表示商人需要满足的条件，才能提供该交易
      • 使用现有的谓词格式（也称为战利品条件）
      • 尚不支持谓词引用
    • double_trade_price_enchantments：一个可选的附魔 ID、命名空间附魔 ID 列表或带有 # 前缀的附魔标签，表示在 minecraft:enchant_randomly 和 minecraft:enchant_with_levels 的 include_additional_cost_component 设置为 true，且物品的 minecraft:stored_enchantments 组件包含所提供的值之一时，会使额外成本翻倍的附魔。

一个仅由沙漠村民提供的交易示例：用一颗绿宝石和一本书换取一本附魔书

{
  "additional_wants": {
    "id": "minecraft:book"
  },
  "double_trade_price_enchantments": "#minecraft:double_trade_price",
  "given_item_modifiers": [
    {
      "function": "minecraft:enchant_randomly",
      "include_additional_cost_component": true,
      "only_compatible": false,
      "options": "#minecraft:trades/desert_common"
    },
    {
      "function": "minecraft:filtered",
      "item_filter": {
        "items": "minecraft:enchanted_book",
        "predicates": {
          "minecraft:stored_enchantments": [
            {}
          ]
        }
      },
      "on_fail": {
        "function": "minecraft:discard"
      }
    }
  ],
  "gives": {
    "count": 1,
    "id": "minecraft:enchanted_book"
  },
  "max_uses": 12.0,
  "merchant_predicate": {
    "condition": "minecraft:entity_properties",
    "entity": "this",
    "predicate": {
      "predicates": {
        "minecraft:villager/variant": "minecraft:desert"
      }
    }
  },
  "reputation_discount": 0.2,
  "wants": {
    "id": "minecraft:emerald"
  }
}

交易集合

  • 位于 trade_set 文件夹中，它们是村民和流浪商人提供的交易分组
  • 目前我们只有硬编码的集合，村民使用的是 <profession>/level_<level>，流浪商人使用的是 wandering_trader/buying、wandering_trader/special、wandering_trader/common
  • 条目格式：
    • trades：一个村民交易 ID、命名空间村民交易 ID 列表或带有 # 前缀的村民交易标签，表示属于此交易集合的交易
    • amount：一个数字提供器，表示使用此集合时生成的交易数量
      • 如果生成的数字大于可用 trades 的数量，则只会生成到每个 trades 都使用过一次为止，除非 allow_duplicates 设置为 true
    • allow_duplicates：一个布尔值，表示交易集合是否可以多次使用同一个村民交易来生成交易
      • 默认为 false
    • random_sequence：一个可选的命名随机序列，用于决定生成哪些交易
      • 默认为非确定性随机序列

一个交易集合示例，从 #minecraft:armorer/level_1 标签提供 2 个交易，并允许重复

{
  "amount": 2.0,
  "trades": "#minecraft:armorer/level_1",
  "random_sequence": "minecraft:trade_set/armorer/level_1",
  "allow_duplicates": true
}

命令

新增 swing

  • 新增命令，可控制实体手臂的摆动
  • 并非所有实体都支持摆动动画。对于这些实体，swing 会成功，但客户端只会在可能的情况下显示动画
  • 例如，这使得摆动模特假人的手臂成为可能
  • 返回已发送摆动请求的实体数量

语法：/swing <entity selector> <mainhand|offhand>

minecraft:visual/block_light_tint

方块光的色调。方块光颜色在低光照等级时以深灰色开始，在中等等级时被此属性染色，在高等级时变为白色。默认情况下，它提供火把的淡黄色色调。亮色最适合此属性，至少有一个颜色分量是完全亮的。此色调全局应用于屏幕上可见的所有光源。单个光源不能以不同方式染色。

  • 值类型：RGB 颜色
  • 默认值：#FFD88C
  • 修饰器：RGB 颜色修饰器
  • 可插值：是
  • 在相机位置解析

minecraft:visual/ambient_light_color

定义环境光的色调和亮度。此光在光照等级为 0 时应用于世界。方块光和天空光在其上叠加。

  • 值类型：RGB 颜色
  • 默认值：主世界为 #0A0A0A，下界为 #302821，末地为 #3f473f
  • 修饰器：RGB 颜色修饰器
  • 可插值：是
  • 在相机位置解析

minecraft:visual/night_vision_color

此颜色的使用方式类似环境光颜色。当夜视效果激活时，将使用 minecraft:visual/night_vision_color 和 minecraft:visual/ambient_light_color 的逐分量最大值作为环境色。默认情况下，夜视不带色调。

  • 值类型：RGB 颜色
  • 默认值：#999999
  • 修饰器：RGB 颜色修饰器
  • 可插值：是
  • 在相机位置解析

数据组件

新增 minecraft:additional_trade_cost

  • 瞬态组件，用于修改村民交易中 gives 物品所需的 count，在交易生成后会被移除
  • 格式：整数

战利品函数

  • 新增 minecraft:villager_trade 战利品表类型，该类型采用以下参数：
    • this：提供交易的实体
    • origin：实体脚部所在的方块位置

新增 minecraft:set_random_dyes

  • 如果物品在 #dyeable 标签中，则向物品的 minecraft:dyed_color 数据组件累加添加染料。字段：
  • conditions - 函数应用的条件
  • number_of_dyes - 数字提供器，表示从十六种染料中随机应用到物品上的染料数量
    • 可能会重复选择同一种染料。

新增 minecraft:set_random_potion

  • 随机设置物品上的 minecraft:potion_contents 数据组件。字段：
  • conditions - 函数应用的条件
  • options - 可选的药水 ID、命名空间药水 ID 列表或带有 # 前缀的药水标签，表示可供选择的药水。
    • 默认为 potions 注册表中的任意药水。

更改 minecraft:enchant_with_levels

现在还会采用以下字段：

  • include_additional_cost_component - 可选布尔值，表示是否应根据附魔成本将 minecraft:additional_cost_component 添加到物品上。
    • 默认为 false
    • 该值由 levels 数字提供器决定，与用于确定附魔等级的值相同。

更改 minecraft:enchant_randomly

现在还会采用以下字段：

  • include_additional_cost_component - 可选布尔值，表示是否应根据附魔成本将 minecraft:additional_cost_component 添加到物品上。
    • 默认为 false
    • 该值由 levels 选择的值或其默认值通过以下公式确定：2 + random(0, 5 + level * 10) + 3 * level
