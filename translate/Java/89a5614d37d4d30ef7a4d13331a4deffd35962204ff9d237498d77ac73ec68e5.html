以下更改仅在其对应的实验被启用时生效，可通过激活相应的实验性数据包或在创建世界时在“实验性玩法”屏幕中开启。

收纳袋

收纳袋回来了！收纳袋于 2020 年作为实验性内容加入 Java 版。现在我们重新开始制作收纳袋！要测试收纳袋，你必须开启“收纳袋”实验并创建一个新世界。（创建新世界时，点击‘更多’，然后点击‘实验性玩法’，再点击‘收纳袋’旁边的按钮。）收纳袋是一种物品，可以将不同的方块或物品堆叠在同一个物品栏槽位中。不同的物品通常不能堆叠在一起，因此每个槽位只有几个物品时可能会浪费空间。收纳袋可以将这些物品打包在一起，从而避免空间浪费。

收纳袋有一个提示框，显示袋中的部分物品。如果收纳袋内最多有 8 种物品类型，你会看到全部物品，并可以立即取出任何物品。如果超过 8 种物品类型，有些物品行会被隐藏。你可能想合成一个新的收纳袋，以便轻松取用所有物品。收纳袋可以由 1 根线和 1 块皮革合成。请尝试这个全新版本的收纳袋，并告诉我们你的想法！

  • 收纳袋只能容纳一组（通常为 64 个物品），但可以是多种不同物品类型的混合
  • 你可以直接在物品栏中将物品放入收纳袋
  • 收纳袋有一个提示框，显示袋中的物品
    • 如果收纳袋内少于 8 种物品类型，提示框会显示全部
    • 否则提示框会显示前两行物品，其余物品会隐藏在下文
  • 你可以选择任何可见物品，将其从收纳袋中取出
    • 右键点击取出第一个物品
    • 使用数字键或滚动滚轮选择其他物品，然后右键点击取出

开发者备注：在最初的收纳袋实验中，你只能取出最上面的物品。我们收到了很多反馈，说玩家希望在取出物品时有更多灵活性。为了解决这个问题，我们在收纳袋中添加了一个子菜单，这在 Minecraft 中从未有过！

  • 选择要取出的物品时，收纳袋图标会显示该物品从袋中露出
  • 手持收纳袋时，右键点击可以将其倒空到地上
  • 收纳袋由 1 根线放在 1 块皮革上方合成

开发者备注：最初的收纳袋原型合成成本要高得多，而且使用了只能在特定生物群系找到的兔皮，因此玩家必须探索才能获得第一个收纳袋。在这个版本中，我们降低了成本，使其几乎可以在任何生物群系的家中合成。我们希望在新世界中轻松获得收纳袋，这样你就可以在早期冒险中使用它。

  • 与最初原型相比，操作方式已更改：
    • 使用左键将物品放入收纳袋
    • 使用右键从收纳袋中取出最上层的物品类型
    • 当收纳袋提示框可见时，使用数字键或鼠标滚轮选择不同的物品类型，然后使用右键将其取出

红石线

  • 红石线（相连的红石粉方块）的性能影响已得到改善
  • 红石线现在只对可能从该线路接收能量的方块触发方块更新
  • 在一段线路导致方块更新之前，所有相连线路的新信号强度会被设置好
  • 红石线周围的更新顺序已更改
    • 目标是让红石线的工作方式与位置和朝向无关
    • 在可能的情况下，顺序根据引发更新的上下文确定
    • 当上下文不足以完全确定顺序时，其余部分将随机选择

开发者备注：我们知道红石中的随机性通常是不受欢迎的。
我们在这里使用了随机性，因为我们在有意义的情况下让事物变得确定，但有时候这并不合理——而且我们不希望某些隐藏状态（例如基于位置的哈希值！）决定顺序，导致机器在不同坐标或朝向下以不同方式工作。
下面的截图展示了‘随机’与‘非随机’红石线的示例——我们认为这实际上相当合理，并且玩家可以控制在其中建造确定性行为的机器。
但我们期待听到你尝试后的想法！

红石线变化顺序

  • 当一段红石线开启时，离电源更近的红石线会先引发方块更新
  • 当一段红石线关闭时，离原电源更近的红石线会先引发方块更新
  • 当两条红石线到电源距离相同时，哪条先引发更新是随机选择的
    • 随机选择会对整段红石线做一次，以限制可能的结果数量
    • 这意味着，当从侧面为一段红石线供电时，它会随机选择两种可能的更新顺序之一
    • 可能更新顺序较少的优点是结果更可预测

红石线周围的方块更新

  • 红石线周围方块更新的顺序基于红石线接收更新时的方向
  • 目前顺序为：后、前、左、右、下、上
    • 左和右可能互换，具体取决于红石线做出的随机选择
  • 当更新通过实心方块进一步传递时，同样适用该顺序

已知问题

由于此实验只更改了红石线，与其他组件的交互可能并不总是符合预期，尤其是在更新顺序方面。

矿车改进

添加了一个包含多种矿车移动方式更改的新实验。可以在创建世界时在“实验性玩法”菜单中选择“矿车改进”来启用它。

我们的长期目标是让矿车等载具旅行成为玩家可行的选择，而不是像目前主导大多数玩法的其他后期选项那样。为了实现这一目标，我们致力于让乘坐矿车成为一种流畅的体验，具有一致且可预测的运动和旋转。通过这个功能开关，我们正在为未来的发展奠定基础。我们认识到这些更改会破坏一些现有装置，这也是我们希望与社区合作，共同塑造矿车的升级和未来乘坐体验的原因。

请注意，此开关背后的实验性功能目前并不针对任何未来版本。相反，这里是我们尝试更改和收集反馈的地方。

我们很期待听到你对这些更改的看法：请在这个反馈页面上分享你的反馈。

移动更改

  • 矿车在高速行驶时会更好地表现其移动，并且始终行驶在轨道上
    • 矿车现在会随着轨道平滑转弯，更不容易停下来或脱轨
  • 矿车现在可以更好地跳跃
    • 当轨道以斜坡结束时，矿车会保持其垂直动量
    • 矿车在空中时会倾斜以在视觉上表现动作
    • 矿车在空中飞行时不会播放轨道摩擦声
  • 添加了一个新的无障碍选项，使玩家跟随所乘坐矿车的旋转
    • 默认关闭
    • 仅在启用该实验的世界中生效
  • 添加了新的游戏规则 minecartMaxSpeed，用于更改矿车的最大速度
    • 默认为 8，最高可达每秒 1000 格
    • 将其设置为特定值并不保证矿车能达到该最大速度——因为存在固有的空气阻力以及类似效果，需要通过斜坡或充能铁轨增加的速度来克服
    • 此游戏规则仅存在于启用该实验的世界中

矿车更改

  • 玩家或发射器不再可以将矿车放置在另一个矿车内
  • 矿车现在可以一致地沿着轨道彼此相邻放置
  • 矿车在沿轨道移动时现在可以更一致地拾取生物

稀有度

  • 稀有度是一组类别，用于决定物品或方块名称显示的颜色
    • 它没有游戏玩法影响，但用于表示获得某物的难度
    • 默认情况下，除非另有指定，所有物品和方块的稀有度都为常见，名称以白色显示
  • 我们重新评估了游戏中所有物品和方块的稀有度，以更准确地反映当前获取它们的难度，根据以下指导原则：
    • 物品和方块根据以下因素变得更加稀有：
      • 在战利品表中找到它的几率，包括生物掉落
      • 获得它所需的旅行量
      • 为获得它而必须克服的任何障碍的难度
      • 世界中可能存在的那种物品或方块的数量
    • 任何可以合成的物品或方块必须继承其合成材料中最高的稀有度
      • 例如，重锤具有史诗稀有度，因为其材料之一（沉重核心）具有史诗稀有度
      • 同样，任何合成材料仅为常见的合成物品也必须是常见

不活动 FPS 限制

  • 游戏现在会在某些情况下限制最大帧率
  • 这些情况由新的视频设置 Reduce FPS when 控制
  • 可能的选项包括：
    • Mimimized
      • 仅在游戏窗口最小化时将帧率限制为 10 FPS
    • AFK
      • 当游戏在超过一分钟内没有收到任何玩家输入时，将帧率限制为 30 FPS
      • 在没有输入的另外 9 分钟后，进一步限制为 10 FPS
      • 当游戏窗口最小化时也限制为 10 FPS
  • 默认值为 AFK

      • 例如，[{"name": "potato", "width": 16, "height": 16}] 变成 {"potato": {"width": 16, "height": 16}}

输入格式

对于渲染目标和纹理输入，可以指定以下字段：

  • sampler_name：字符串 - 用于同时设置 _Sampler 和 _Size uniform 变量的前缀
    • 例如，"sampler_name": "Diffuse" 将链接到 DiffuseSampler 和 DiffuseSize uniform 变量
    • 以前对于 intarget，这始终是 DiffuseSampler 和 InSize
    • 对于 auxtargets，name 定义了采样器 uniform 变量，大小由 AuxSize<index> 给出
  • bilinear：布尔值（默认：false）- 如果为 true，则输入将使用双线性过滤器进行采样
    • 这以前仅存在于纹理输入上，但现在也适用于渲染目标
    • 对于渲染目标，取代了已移除的通道定义上的 use_linear_filter 字段

对于来自渲染目标的输入，可以指定以下字段：

  • target：带命名空间的 ID - 渲染目标 ID
    • 可以是在同一文件中定义的自定义目标 ID，也可以是引用主屏幕目标的 minecraft:main
    • 这取代了以前作为自由格式字符串的 id 字段
  • use_depth_buffer：布尔值（默认：false）- true 表示从深度纹理采样，false 表示从颜色纹理采样
    • 这取代了以前应用于目标 ID 的 :depth 后缀

对于来自静态纹理的输入，可以指定以下字段：

  • location：带命名空间的字符串 - 可供效果采样的静态纹理文件的位置
    • 与以前的 id 字段一样，这解析为 assets/<namespace>/textures/effect/<path>.png 处的纹理
  • width：正整数 - 纹理的宽度（以像素为单位）
  • height：正整数 - 纹理的高度（以像素为单位）

外部目标

  • ‘华丽’图形透明后期处理配置不再将排序帧缓冲指定为自定义目标
    • 这些改为与 minecraft:main 目标相同的方式导入
    • translucent、itemEntity、particles、weather、clouds 现在分别为 minecraft:translucent、minecraft:item_entity、minecraft:particles、minecraft:weather 和 minecraft:clouds
