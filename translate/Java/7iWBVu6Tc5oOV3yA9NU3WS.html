遥测

此版本包含 WorldUnloaded 事件（一个必需事件），以及几个可选事件。诊断跟踪是一种工具，可帮助我们了解你喜欢 Minecraft 的哪些方面，从而让我们改进这些方面。

WorldUnloaded 与 WorldLoaded 一样是必需事件，原因在于我们查看的信息属于必需信息。作为 Xbox 的一部分，我们都需遵循一定的操作标准，你可以此处查看详细说明。我们 Mojang Studios 团队与 Xbox 协同确定了哪些数据对我们的工作至关重要。

我们想要了解的是你认为 Minecraft 有多有趣。有很多方法可以做到这一点，例如反馈、试玩、体验和魔法。我们希望在数据中增加这些内容，这就是 WorldLoaded 和 WorldUnloaded 的用武之地。WorldLoaded 测量你启动游戏会话的时间，WorldUnloaded 测量你关闭它的时间。两者结合，将使用游戏时长以及玩家选择的游戏模式等指标来衡量 Minecraft 的趣味性。仅此而已。我们收集的所有数据，无论是必需的还是可选的，都遵循 GDPR 和 CCPA 的最佳实践，以保护你的信息安全。

当前的其他遥测事件都是可选的，这意味着你可以选择是否向我们发送额外数据。唯一无法选择加入的是 Microsoft 儿童帐户，但所有人都仍然可以将反馈发送到 feedback.minecraft.net。

就像我们在反馈网站上从你那里获得的所有想法和评论一样，这能极大地帮助我们改进 Minecraft。我们希望制作一款你想玩的游戏，因此我们想知道这款游戏需要什么。即使是更多岩浆也没关系。

      • “最小”仅发送必需数据
      • “全部”发送必需数据以及可选数据
    • 默认数据级别为“最小”（仅必需数据）

    • 这些文件可在 logs/telemetry 目录下找到
      • 可通过遥测数据收集界面上的“打开我的数据”按钮打开该目录的快捷方式

必需遥测事件

  • 添加了 WorldUnloaded 事件
  • 从 WorldLoaded 事件中移除了客户端 Java 版本

WorldLoaded 与 WorldUnloaded

了解 Minecraft 的游玩方式有助于我们将游戏更新和改进集中在与玩家最相关的领域。让我们了解这些的数据包括游戏模式、客户端或服务器是否安装模组的状态，以及游戏版本。

WorldLoaded 和 WorldUnloaded 是一对事件，用于计算世界会话持续了多长时间（以秒和刻为单位）。世界启动时发送 WorldLoaded 数据，世界关闭时（退出到标题画面、从服务器断开连接）发送 WorldUnloaded 数据。

可选遥测事件

  • 添加了 PerformanceMetrics 和 WorldLoadTimes 事件

PerformanceMetrics

了解 Minecraft 的总体性能概况有助于我们针对各种机器规格和操作系统调整和优化游戏。

定期性能指标包括帧率、渲染性能、内存使用量、操作系统以及客户端和服务器的模组状态等数据。

其中包含游戏版本，以帮助我们比较 Minecraft 新版本的性能概况。

WorldLoadTimes

了解加入世界所需的时间以及随时间的变化对我们来说非常重要。例如，当我们添加新功能或进行较大的技术更改时，我们需要查看这对加载时间产生了什么影响。

此事件包括世界加载的总毫秒数、这是否为新世界，以及游戏版本和平台详细信息。

纹理加载更改

  • 背景：游戏加载方块和物品模型使用的所有纹理时，需要将其拼接（合并）为单个图像，称为“图集”（atlas）
    • 被拼接在图集上的单个纹理称为“精灵图”（sprite）
  • 为了提高加载性能，方块和物品纹理现在会在被方块和物品模型处理之前加载
    • 默认情况下，不在 textures/item 和 textures/block 目录中的纹理将不再被自动识别，并且会加载失败
  • 资源包现在可以在 atlases 目录中放置配置文件，以控制图集包含哪些图像

图集配置文件

  • 资源包现在新增了 atlases 目录
  • 此目录包含用于配置图集的 JSON 条目：
    • blocks - 方块和物品模型使用的纹理
    • banner_patterns、beds、chests、shield_patterns、shulker_boxes、signs - 用于渲染某些特殊情况的模型
    • mob_effects - 用于 UI 中效果图标的纹理
    • paintings - 用于画的纹理
    • particles - 用于粒子的纹理（由 particles 目录内文件中的 textures 字段引用）
  • 如果多个包包含这些文件，则按照包内的顺序合并（与数据包中的标签相同）
  • 这些文件内部是一个 JSON 对象，其中只有一个名为 sources 的列表
    • sources 中的每个条目都会在加载时按定义顺序运行，向纹理列表添加或移除新文件；以供之后方块模型、粒子等引用
  • 来源类型：
    • directory - 列出目录及其子目录中的所有文件，跨所有命名空间
      • source - 要列出的包内目录（相对于 textures 目录）
      • prefix - 加载时要附加到精灵图名称的字符串
    • single - 添加单个文件
      • resource - 包内资源的位置（相对于 textures 目录，隐含 .png 扩展名）
      • sprite - 精灵图名称（可选，默认为 resource）
    • filter - 移除与给定模式匹配的精灵图
      • namespace、path - 要移除的 ID 的模式（正则表达式）（仅对列表中已有的条目生效）
        • 如果省略，则匹配任何值
    • unstitch - 从其他图像复制矩形区域
      • resource - 包内资源的位置（相对于 textures 目录，隐含 .png 扩展名）
      • divisor_x、divisor_y - 用于确定区域使用的单位
      • regions - 要从源图像复制的区域列表
        • sprite - 精灵图名称
        • x、y - 区域左上角的坐标
        • width、height - 区域的大小
      • 像 x 这样的值会先除以其除数，再乘以真实图像尺寸，从而转换为真实图像坐标
  • 示例：如果某个包具有名为 assets/test/textures/fancy/iridium.png 的文件，且来源为 {"type": "directory", "source": "fancy", "prefix": "custom/"}，则该纹理会以 test:custom/iridium 的形式在模型中可用

命令

  • 新命令：fillbiome
  • 新的 execute 子命令：execute if|unless biome

fillbiome

更改某个区域的生物群系条目。请注意，生物群系并非按方块存储，因此受影响的位置可能与输入不完全一致。

语法：

fillbiome <from> <to> <biome>

参数：

  • from：要填充区域的一个角
  • to：要填充区域的另一个角
  • biome：要设置的生物群系

execute

execute 命令现在可以基于生物群系作为条件。

语法：

execute if|unless biome <pos> <biome>
