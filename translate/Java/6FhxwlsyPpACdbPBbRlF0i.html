我们现在为 Minecraft: Java Edition 发布 1.19.4。此版本带来了马匹繁殖与唱片机的改进、药水的新外观、新的无障碍功能，以及许多新的技术能力，例如 damage 和 ride 命令、展示实体和交互实体。

update_1_20 实验也已更新，首次展示嗅探兽、考古、盔甲纹饰和樱花树林特性。

更改

  • 更新了马的繁殖
  • 唱片机已改为与基岩版保持一致
  • 手持盔甲或鞘翅物品时进行交互，现在会与已装备的装备交换
  • 受伤时的视角倾斜现在基于所受伤害的方向
  • 调整了药水的颜色，使不同类型的药水更容易区分
  • 药水不再有附魔闪光，因为它会遮挡药水内容的颜色
  • 物品和盔甲上的附魔闪光现在更加柔和
  • 盔甲架在放置和破坏时现在会保留自定义名称
  • 恼鬼在空手时现在使用单独的蓄力动画
  • 调整了配方解锁机制，让新玩家更容易发现重要的合成配方
  • 更新了创建新世界界面
  • 新增无障碍选项和改进
  • 更新了领域界面，使其更符合单人游戏和多人游戏界面
  • 为领域添加了通知系统，用于告知你关于领域的重要信息
  • 在选项菜单中添加了“制作人员与声明”按钮

马、驴和羊驼

幼崽的速度、跳跃高度和生命值现在会基于双亲属性的平均值产生变异，而不再偏向于可能的平均值。

这一改动使马的繁殖成为获得优秀马匹的可行途径——只要玩家从优良的双亲开始，并投入足够的时间和金胡萝卜。

命令

clone

clone 命令现在支持指定源维度和目标维度。

新语法：

clone [from <sourceDimension>] <begin> <end> [to <targetDimension>] <destination> ...

参数：

  • sourceDimension：要从中克隆的维度 ID
  • targetDimension：要克隆到的维度 ID

damage

用于对实体造成伤害的新命令。

语法：

  • damage <target> <amount> [<damageType>] [at <location>]
  • damage <target> <amount> [<damageType>] [by <entity>] [from <cause>]

参数：

  • target：要伤害的实体
  • amount：造成的伤害量
  • damageType：造成的伤害类型
    • 这决定了伤害如何影响实体，以及显示哪条死亡消息
  • entity：造成伤害的实体
  • cause：间接伤害时的伤害原因
    • 例如：被箭射中时，entity 是箭矢投射物，而 cause 可能是骷髅
  • location：伤害来源的位置（当没有实体造成伤害时）
    • 例如，location 可能代表床在下界爆炸的位置

data

新的数据源可用：

  • string <entity|block|storage> [path] [start] [end] - 将值作为文本读取，结果为字符串值

新参数：

  • start：字符串开头要包含的第一个字符的索引
  • end：字符串末尾要排除的第一个字符的索引

effect

  • infinite 现在是效果持续时间的有效选项
    • 无限效果持续时间在玩家物品栏视图中显示为“∞”

execute

execute if|unless

execute if|unless 子命令新增以下可用条件：

  • execute if|unless loaded <pos> - 检查给定位置是否已完全加载（包括方块和实体）
  • execute if|unless dimension <dimension> - 检查执行是否在匹配的维度中

参数：

  • pos：要检查的方块位置
  • dimension：维度 ID

execute on

新的 execute 子命令，用于根据与当前执行实体的关系选择实体：

  • execute on <relation>

关系：

  • vehicle - 执行实体正在骑乘的实体
  • passengers - 所有直接骑乘执行实体的实体（不包括次级乘客）
  • controller - 控制执行实体的实体（例如：船上的第一名乘客）
  • owner - 执行实体的主人，如果它是可驯服动物（如猫、狼或鹦鹉）
  • leasher - 用拴绳牵引执行实体的实体（如果拴在栅栏上，则可能是拴绳结）
  • target - 执行实体的攻击目标
  • attacker - 在之前 5 秒内伤害过执行实体的最近实体
  • origin：
    • 射手，如果执行实体是投射物（如箭、火球、三叉戟、烟花、投掷药水等）
    • 投掷者，如果执行实体是物品
    • 效果来源，如果执行实体是区域效果云
    • 点燃者，如果执行实体是已点燃的 TNT
    • 召唤者，如果执行实体是唤魔者尖牙或恼鬼

如果该关系不适用于执行实体，或没有匹配的实体，选择器将返回零个元素。

execute positioned over

新的 execute 子命令，用于查找高度图顶部的坐标。将执行位置的高度更改为给定高度图的顶部。

语法：

  • execute positioned over <heightmap>
高度图

高度图根据某些标准记录一列方块中的最高位置。可用选项：

  • world_surface：任何非空气方块
  • motion_blocking：任何阻挡移动的材料（例如忽略花和草）
  • motion_blocking_no_leaves：任何非树叶的阻挡移动材料
  • ocean_floor：任何非流体的阻挡移动材料

execute summon

新的 execute 子命令，用于召唤新实体并将其上下文（@s）绑定到该实体。旨在简化实体设置，减少对原始 NBT 编辑的需求。

语法：

  • execute summon <entity id>

fillbiome

  • 优化了使用 fillbiome 命令时传输的网络数据量

title

  • title times 的所有时间参数现在都是时间持续时间，支持 t、s 和 d 后缀

weather

  • 天气变化的持续时间在未指定时，现在会与游戏常规天气循环一致
  • duration 参数现在是 tick 为单位的时间持续时间，支持 t、s 和 d 后缀
    • 要保留现有功能，你需要在已有命令中添加 s 后缀

ride

允许实体开始或停止骑乘其他实体的新命令。

语法：

  • ride <target> mount <vehicle>
    • 使单个目标骑乘单个载具
    • 在以下情况下，命令会失败：
      • vehicle 是玩家
      • target 已经在骑乘载具
      • target 和 vehicle 是同一实体
      • vehicle 已经是 target 的乘客（直接或间接）
  • ride <target> dismount
    • 使 target 从其骑乘的任何载具上下来
    • 如果 target 没有骑乘任何东西，则失败

伤害类型

伤害类型是一个可以通过数据包扩展的新注册表。伤害类型决定了游戏如何处理伤害，包括伤害具有哪些属性，以及实体因该类伤害死亡时使用哪条死亡消息。

示例：

{
  "exhaustion": 0.1,
  "message_id": "arrow",
  "scaling": "when_caused_by_living_non_player"
}

字段：

  • message_id：由该伤害类型造成的死亡所使用的消息 ID
    • 将与其他字符串片段组合形成翻译键
  • exhaustion：该伤害类型造成的饥饿值消耗量
  • scaling：该伤害类型是否随难度等级调整。可能的值：
    • never：伤害始终相同
    • always：伤害始终随难度调整
    • when_caused_by_living_non_player：如果伤害由非玩家的生物造成，则伤害随难度调整
  • effects：可选字段，控制对玩家造成伤害时的表现方式。可能的值：
    • hurt（默认）：默认受伤音效
    • thorns：荆棘受伤音效
    • drowning：溺水音效
    • burning：单个 tick 的燃烧音效
    • poking：浆果丛刺扎音效
    • freezing：冰冻 tick 音效
  • death_message_type：可选字段，控制是否使用特殊的死亡消息变种。可能的值：
    • default（默认）：不应用特殊死亡消息逻辑
    • fall_variants：显示摔落伤害死亡的变种消息，而不是普通死亡消息，例如 death.fell.assist.item
    • intentional_game_design：显示“有意的游戏设计”消息，而不是普通死亡消息

伤害类型标签控制着来自不同来源的伤害如何被解释的许多方面。

谓词

伤害类型谓词

以下字段已从伤害类型谓词中移除：is_projectile、is_explosion、bypasses_armor、bypasses_invulnerability、bypasses_magic、is_fire、is_magic、is_lightning。

添加了一个新的 tags 数组，当所有条目匹配时谓词匹配。每个条目有两个字段：

  • id：伤害类型标签的 ID
  • expected：谓词匹配时，伤害预期具有或不具有该标签

游戏规则

  • 添加了 commandModificationBlockLimit，控制 clone、fill 和 fillbiome 单次执行中更改的最大方块数
  • 添加了 doVinesSpread 游戏规则，决定藤蔓是否会蔓延到附近的方块
    • 默认为 true

文本组件

为 translate 文本组件添加了可选的 fallback 字段。

  • 新字段是一个字符串，当翻译缺失时将用作替代
  • 如果缺少 fallback，则保留旧行为（即使用键本身作为翻译）

展示实体

添加了三种新实体，用于灵活展示物品、方块和文本

  • 这些实体与 marker 类似，不会 tick，也没有碰撞或物理效果
  • 模型在实体位置渲染，围绕 X 和 Y 轴正常旋转（因此可以通过传送命令控制），同时还支持额外的任意模型变换

通用数据类型

展示实体的标签内容包含一些具有复杂结构的新数据类型。任何形式都可以用于修改数据，但只有一种形式用于保存。

变换

任意仿射变换。

  • 矩阵形式：由 16 个数字组成的数组，描述行主序矩阵
  • 分解形式（用于保存）：包含以下字段的对象：
    • translation - 3D 向量
    • left_rotation、right_rotation - rotation
    • scale - 3D 向量
    • 变换按 translation、left_rotation、scale、right_rotation 的顺序组合

旋转

  • 四元数形式（用于保存）：由 4 个数字组成的数组，描述分量 (x, y, z, w)
  • 轴角形式：包含以下字段的对象：
    • axis - 单位 3D 向量
    • angle - 以弧度为单位

插值

展示实体的某些属性可以进行插值。这意味着客户端会看到随时间逐渐变化，而不是瞬时跳跃。

展示实体会跟踪插值属性的当前值和先前值：

  • 所有标记为“interpolated”的属性都属于同一个插值集合
  • 对插值属性的任何更新都会导致插值集合中的所有值被保存为“当前”值
    • 未更改属性值的 data 命令执行（即使该值存在于 NBT 中）不计为更新
    • 更新最多每 tick 向客户端同步一次，因此命令中的多次更新仍算作一次更新
  • 更新前生成的最后一个值会被保存为“先前”值
  • 如果启用插值，实体将在 interpolation_duration tick 内从“先前”值过渡到“当前”值
  • 可以通过写入 start_interpolation 字段来启动插值（该字段通常不存在于 NBT 中）
    • 此字段的值是客户端收到更新与插值开始之间的延迟（以 tick 为单位）
    • 0 tick 表示插值将在收到更新后的下一个客户端 tick 开始
    • 正值会进一步增加此延迟
  • 在收到更新后的 start_interpolation + interpolation_duration tick 时，插值将结束（实体完全处于“当前”状态）
  • 可以在不设置 start_interpolation 的情况下更新插值目标，但其行为仍会像是在上次更新 start_interpolation 时启动的
    • 这意味着，如果更新了值，但自上次 start_interpolation 更新以来已过去超过 interpolation_duration tick，实体将立即跳到新值

通用属性

所有展示实体类型都具有以下字段：

  • transformation - 应用于模型的变换（在正常实体方向之后）。默认为单位变换。可插值
  • billboard - 控制实体在渲染时是否应转向面向玩家的选项：
    • fixed - 不旋转（默认）
    • vertical - 实体可以围绕其垂直轴旋转
    • horizontal - 实体可以围绕其水平轴旋转
    • center - 实体可以围绕其中心点旋转
  • brightness - 如果存在，则覆盖用于渲染的光照值。默认省略（意味着渲染使用实体位置的光照值）。对象有两个字段：
    • sky - 天空光照值，0..15
    • block - 方块光照值，0..15
  • view_range - 该实体的最大视距。实际距离取决于客户端的渲染距离和实体距离缩放。默认值为 1.0（与火球大致相同）
  • shadow_radius - 阴影大小。默认为 0（无阴影）。可插值
  • shadow_strength - 阴影强度。控制阴影不透明度与下方方块距离的关系。默认为 1。可插值
  • width、height - 描述剔除包围盒的大小
    • 包围盒垂直方向从 y 延伸到 y+height，水平方向从实体位置向各个方向延伸 width/2
    • 如果任一字段设置为 0，则禁用剔除
    • 两者默认为 0
  • glow_color_override - 覆盖发光边框颜色。默认为 -1（使用队伍颜色）。忽略 Alpha 分量

item_display

展示单个物品堆叠。

  • 可以通过命令设置 container.0 槽位来更改物品堆叠

字段：

  • item - 要展示的物品堆叠。格式与物品栏中相同（示例：{id: "minecraft:dirt", Count: 1}）
  • item_display - 描述应用于物品的物品模型变换（如模型 JSON 的 display 部分所定义）
    • 值：none（默认）、thirdperson_lefthand、thirdperson_righthand、firstperson_lefthand、firstperson_righthand、head、gui、ground、fixed

block_display

展示一个方块状态。

  • 不会展示所有方块实体，即使它们通常会在方块放置时生成（如箱子）

字段：

  • block_state - 要展示的方块状态。格式与末影人手持物品相同（示例 {Name:"minecraft:dirt"}）

text_display

展示一个文本组件。

字段：

  • text - 要展示的文本。组件使用展示实体的上下文进行解析
  • line_width - 用于换行的行宽（注意：也可以使用 \n 字符添加新行）。默认为 200
  • text_opacity - 渲染文本的不透明度（Alpha 分量）。默认为 255。可插值
  • background - 背景颜色。包含 Alpha 通道。默认为 0x40000000。可插值
  • default_background - 如果为 true，渲染使用默认文本背景颜色（与聊天中相同）。默认为 false
  • shadow - 文本是否应带阴影显示。默认为 false
  • see_through - 文本是否应透过方块可见。默认为 false
  • alignment - 文本应如何对齐
    • 值：center（默认）、left、right

注意：文本展示背景使用新的着色器类型 rendertype_text_background 和 rendertype_text_background_see_through。

交互实体

一种记录攻击（“左键”）和交互（“右键”）的新实体类型。交互实体不可见，且具有自定义尺寸。

字段：

  • width：实体包围盒的宽度（默认 1）
  • height：实体包围盒的高度（默认 1）
  • attack：记录对该实体的最近一次攻击操作
  • interaction：记录对该实体的最近一次交互操作
  • response：布尔值，指定交互是否应触发响应（手臂摆动、音效等 - 默认 false）

操作格式

存储操作时，它始终有两个字段：

  • player：执行操作的玩家的 UUID（以标准整数数组格式存储）
  • timestamp：事件发生时的游戏 tick 时间戳（以 long 存储）

进度触发器

  • 与交互实体交互会触发 player_interacted_with_entity
  • 攻击交互实体会触发 player_hurt_entity

与交互实体一起使用 execute on

交互实体会将最后与其交互的玩家作为目标。这使得以下操作成为可能：

  • execute on attacker：以最后攻击该实体的玩家身份执行
  • execute on target：以最后与该实体交互的玩家身份执行

调色板排列

  • paletted_permutations 是一种新类型的图集配置源，用于根据一组调色板在内存中动态生成新纹理
  • 调色板允许你交换纹理的颜色，而无需在资源包中提供纹理变种的所有文件
  • 这对于盔甲纹饰等功能非常有用，你可以更改盔甲部分的颜色，而无需为每种颜色创建新纹理
  • paletted_permutations 源有一组必需参数：
    • textures 基础纹理的命名空间位置列表
      • 这些纹理将用于生成经过调色板修改的变种
    • palette_key 调色板键文件的命名空间位置
      • 调色板键用于定义我们要用下面定义的调色板替换的关键像素颜色集合
    • permutations 从后缀到颜色调色板文件命名空间位置的排列映射
      • 后缀将附加到输出变种纹理的资源位置的开头，使用 _ 字符分隔后缀和基础纹理名称
      • 调色板是一个包含一组像素的纹理文件，用于替换每个基础纹理中与调色板键匹配的像素
      • 每个调色板中的像素数量必须与此源定义的 palette_key 的像素数量相同
      • 键匹配通过比较 palette_key 中每个像素的 RGB 值与调色板中每个像素的 RGB 值来完成
      • 键匹配时忽略 Alpha 通道，但在生成的纹理中，Alpha 通道会与调色板的 Alpha 通道相乘
      • 不匹配 palette_key 的像素将原样复制到生成的纹理中
  • 定义 paletted_permutations 源后，你可以在资源包的其他资源中引用这些命名空间的输出纹理

例如，如果你有以下 paletted_permutations 源：

{
    "type": "paletted_permutations",
    "textures": [
        "minecraft:item/leather_helmet",
        "minecraft:item/leather_chestplate",
        "minecraft:item/leather_leggings",
        "minecraft:item/leather_boots"
    ],
    "palette_key": "minecraft:colormap/color_palettes/leather_armor_color_key",
    "permutations": {
        "red": "minecraft:colormap/color_palettes/red",
        "green": "minecraft:colormap/color_palettes/green",
        "blue": "minecraft:colormap/color_palettes/blue"
    }
}

然后你可以像这样在其他资源中引用生成的纹理：

{
    "textures": {
        "layer0": "minecraft:item/leather_helmet_red",
        "layer1": "minecraft:item/leather_chestplate_green",
        "layer2": "minecraft:item/leather_boots_blue"
    }
}

纹饰图案与材料

  • 盔甲的纹饰图案和材料分别由服务器通过 trim_pattern 和 trim_material 注册表定义
    • 因此，可以通过数据包添加新的纹饰图案和材料
  • 这些会在客户端加入服务器时同步到客户端
    • 但是，客户端必须同时拥有相应的资源包才能看到这些已注册的纹饰图案和材料
    • 这些纹理的路径根据 pattern json 的文件名推断，并将尝试在与纹饰图案的 name 字段相同的命名空间内查找纹理
  • 纹饰图案定义以下数据：
    • asset_id，一个用于推断纹理位置和本地化的命名空间 ID
    • template_item，用于应用纹饰图案的锻造模板物品的 ID
    • description，一个文本组件，用于在悬停盔甲物品堆叠时显示盔甲纹饰的图案名称
  • 纹饰材料定义以下数据：
    • asset_name，用作盔甲纹饰纹理位置后缀的字符串
    • ingredient，用于应用纹饰材料的材料物品的 ID
    • item_model_index，一个浮点数，定义每个盔甲物品模型为了更改此材料的视觉效果而应针对的物品模型覆盖
    • override_armor_materials，一个可选的盔甲材料到覆盖调色板的映射
      • 映射键是此纹饰材料想用不同调色板覆盖的盔甲材料
      • 映射值是将此纹饰材料应用于具有相应盔甲材料的盔甲件时使用的调色板名称
    • description，一个文本组件，用于在悬停盔甲物品堆叠时显示盔甲纹饰的材料名称
      • 此描述中定义的样式也会应用于盔甲纹饰图案的 description

实验性功能

以下更改仅在开启一个或多个实验时生效，可以通过激活相应的实验性数据包，或在创建世界时在“实验”界面中开启。

  • 添加了锻造模板物品
  • 重新设计了锻造台
  • 更改了下界合金装备的合成方式
  • 添加了新的盔甲纹饰系统，用于在视觉上自定义你的盔甲
  • 添加了嗅探兽生物和火把花
  • 添加了樱花树林生物群系
  • 添加了考古系统
  • 生物头颅现在可以无需潜行地放置在音符盒顶部

锻造模板

  • 锻造台已被重新设计为进行装备实体升级和修改的工作站
  • 除了用于组合装备和材料的槽位外，现在还有一个必需的槽位，用于放置称为锻造模板的物品类型
  • 锻造模板定义了你将对装备进行的升级类型
    • 它既指定了你可以升级哪些类型的物品，也指定了哪些材料可以用于自定义升级
    • 目前有两类锻造模板：盔甲纹饰和下界合金升级
  • 锻造模板在锻造台中用于升级物品时会被消耗
  • 你可以在工作台中用 7 个钻石 + 1 个模板对应的材料方块 + 1 个锻造模板来合成一个锻造模板的副本，输出 2 个相同的锻造模板

下界合金装备

  • 下界合金装备的合成现在还需要下界合金升级锻造模板
  • 下界合金升级锻造模板可以在所有堡垒遗迹的箱子中随机找到，并且每个藏宝室堡垒遗迹中保证有 2 个
  • 这一改动是出于多种原因：
    • 增加玩家在下界合金之前使用钻石装备的时间
    • 使下界合金装备成为游戏进程中更重要的成就
    • 使下界合金更自然地融入新的锻造台合成系统

盔甲纹饰

  • 你现在可以在锻造台上使用各种独特的纹饰来在视觉上自定义你的盔甲
  • 盔甲纹饰纯粹是视觉上的，没有游戏玩法加成，只能应用于头盔、胸甲、护腿和靴子
    • 所有纹饰图案在盔甲物品图标上视觉相同，但颜色仍会根据纹饰材料而变化
    • 要查看一件盔甲具有哪种纹饰图案，你可以在物品栏中悬停在该物品上
  • 盔甲纹饰锻造模板可以在世界各地找到，以下每个结构都包含其独特的锻造模板：
    • 掠夺者前哨站：哨兵盔甲纹饰
    • 沙漠神殿：沙丘盔甲纹饰
    • 沉船：海岸盔甲纹饰
    • 丛林神庙：荒野盔甲纹饰
    • 海底神殿：潮汐盔甲纹饰
    • 远古城市：守护盔甲纹饰
    • 林地府邸：恼鬼盔甲纹饰
    • 下界要塞：肋骨盔甲纹饰
    • 堡垒遗迹：猪鼻盔甲纹饰
    • 要塞：眼眸盔甲纹饰
    • 末地城：尖塔盔甲纹饰
  • 锻造模板在其对应结构的箱子中生成
    • 海底神殿没有箱子，远古守卫者有时会在死亡时掉落锻造模板
  • 有些盔甲纹饰锻造模板比其他模板更稀有，所以要多留意它们，让你的朋友刮目相看！
  • 盔甲纹饰有两个属性：图案和材料
    • 图案由用于应用纹饰的锻造模板定义，代表纹饰的视觉图案
    • 材料由你用于应用纹饰的材料定义，代表纹饰的颜色
  • 可用于定义盔甲纹饰颜色的材料如下：
    • 铁、铜、金、青金石、绿宝石、钻石、下界合金、红石、紫水晶、石英

嗅探兽

  • 嗅探兽是 Minecraft Live 2022 的生物投票获胜者
  • 嗅探兽无法被引诱或驯服
  • 嗅探兽是被动、友好的生物
  • 嗅探兽会嗅闻空气，并偶尔挖掘种子，产出火把花种子
  • 可以通过喂食火把花种子来繁殖嗅探兽
  • 嗅探兽目前仅在创造模式物品栏中作为生成蛋提供

火把花

  • 火把花种子可以种在耕地上，长成一朵花
  • 种子可用于繁殖两只嗅探兽
  • 长成的花可以收获并重新种植，也可以合成染料

樱花树林

  • 添加了新的樱花树林生物群系，其中有美丽的樱花树
    • 该生物群系可以在山脉中找到，与草甸类似的位置
  • 添加了新的樱花木系列，以及所有可以制作的相应木制物品
  • 樱花树叶下方会飘落粉红色粒子
  • 添加了新的粉红色花簇方块，地面有大量粉红色花朵
    • 每个粉红色花簇方块最多可包含 4 片花瓣
    • 对其使用骨粉会增加花瓣数量
    • 在方块上放置花瓣会增加花瓣数量
    • 挖掘该方块会掉落与方块中花瓣数量相同的花瓣

考古

刷子

  • 刷子是一种可合成的物品，你可以用它来刷东西

可疑的沙子

  • 可以在沙漠神殿和沙漠水井中找到
  • 这种脆弱的方块很难发现，也很容易破坏，所以要小心！
  • 用刷子刷可疑的沙子会提取出很久以前埋藏的物品

陶片

  • 陶片上带有图案
  • 它们无法合成，只能通过刷可疑的沙子获得

饰纹陶罐

  • 将四个陶片合成在一起会得到一个饰纹陶罐，每面都有一个图案
  • 在饰纹陶罐配方中，红砖物品可以替代陶片
    • 用红砖物品制作的面不会有图案
  • 使用任何破坏方块的工具敲碎饰纹陶罐，将其打碎并取回陶片
    • 徒手、使用精准采集工具或任何其他物品击打陶罐，会掉落一个完整的陶罐
