我们现在为 Minecraft: Java Edition 发布 1.19.3。此版本为恼鬼带来了全新外观，同时还包含技术改进和漏洞修复。

1.19.3 中的新特性

  • 某些实验性功能现在可通过内置的实验性数据包使用
  • 新增了一个“全景图滚动速度”辅助功能选项
  • 为离线玩家新增了默认皮肤
  • 新的木质方块音效

音效

  • 各种木质方块在放置、破坏或行走时现在会发出独特的声音
    • 共有三组独特的声音：主世界木质类型、下界木质类型和竹子（启用时）
  • 现在在地毯、睡莲和小型紫水晶芽上行走时可以听到脚步声
  • 现在在下界苗、发光地衣、绯红菌索和诡异菌索中行走时可以听到脚步声

1.19.3 中的更改

  • 重新设计了创造模式物品栏标签页
  • 在控制菜单中新增了“管理员物品标签页”选项，默认关闭
  • 恼鬼现在有了新外观
  • 在下界维度中，末影人、骷髅和凋灵骷髅现在只在光照等级 7 及以下生成（之前是 11 及以下）
  • 对方块支撑的更改
  • 对刷怪笼方块的更改
  • 对聊天的更改
  • 新增了草稿版玩家举报
  • 对开放到局域网屏幕的改进
  • Realms 新闻按钮现在会在打开链接前显示确认屏幕
  • 要塞放置代码已更改为更高效，导致要塞位置发生偏移
    • 它们仍以同心圆环的方式放置，但在圆环中的位置可能会偏移几度
  • 旁观者菜单中的“传送到队员”选项现在只对存在有效目标玩家的队伍显示
  • 对提示信息的更改
  • 荒野更新的音乐已调整得稍微不那么响亮

创造模式物品栏

创造模式物品栏中的标签页顺序和内容已进行调整，使查找相关方块和物品的体验更加轻松。

  • 方块和物品已移动到更适合它们的类别中
  • 方块现在尽可能按材质排序
    • 例如，所有橡木方块及其变体现在都相邻排列
  • 某些物品现在可以在多个标签页中找到
  • 多个标签页已重命名或合并到其他标签页
  • 搜索标签页现在按其他标签页分组顺序列出物品
    • 例如，在建筑方块中找到的物品总是出现在红石方块中的物品之前
  • 新增了“彩色方块”标签页，其中包含所有具有 16 种颜色变体的方块
  • 石化橡木台阶已从创造模式物品栏中移除
    • 它仍然可以通过命令访问
  • 以下缺失的物品已添加到创造模式物品栏：
    • 迷之炖菜
      • 提示信息会在从创造模式物品栏中拿起炖菜前显示其效果
      • 只会列出可以通过合成或哞菇获得的具有效果的炖菜
    • 龙蛋
    • 不祥之旗
    • 刷怪笼
    • 所有 3 种飞行时长的烟花
    • 仅管理员可用的方块和物品
      • 只有在同时满足以下条件时，它们才会出现在“管理员工具”标签页中：
        • 控制菜单中的“管理员物品标签页”选项设置为 ON
        • 拥有所需的管理员权限
  • 创造模式菜单中，单类别标签页之外的物品提示信息将显示该物品所在的类别
    • 之前这仅在搜索标签页中出现

恼鬼

  • 生物类型现在显示在刷怪笼物品堆的悬停描述中

物品

聊天

  • 移除了聊天预览

新增草稿版玩家举报

现在，在连接到服务器时，玩家举报可以暂时保存为草稿。

  • 退出玩家举报屏幕时，可以选择丢弃举报或将其保存为草稿
    • 如果屏幕被强制关闭（例如玩家死亡），草稿将始终保留
  • 草稿举报会一直保留到玩家离开当前服务器或世界
    • 离开时，玩家会被提示丢弃或完成并发送举报

功能开关

一般说明

  • 功能开关是启用或禁用某些游戏元素组（如方块、实体和物品）的选项，后文称为“功能”
  • 由开关控制的游戏元素是硬编码的
  • 功能开关存储在世界中

配置和数据包更改

  • 功能开关通过数据包启用
    • 新增了名为 features 的包元数据部分，其中包含名为 enabled 的列表，列出已启用的功能开关
  • 游戏现在包含内置数据包（类似于“程序员美术”资源包），用于启用功能并提供相关的配方、进度、战利品表等
  • 在 server.properties 中新增了字段，以允许初始选择包（仅在世界创建期间有效）
    • initial-enabled-packs - 要启用的包的逗号分隔列表（功能包需要显式启用）
    • initial-disabled-packs - 不自动启用的包的逗号分隔列表
  • 在世界创建后发现的数据包，如果它们需要已加载世界未启用的功能，则将被禁用
  • 新增了实体子谓词类型：axolotl、boat、fox、mushroom、painting、rabbit、horse、llama、villager、parrot、tropical_fish

功能开关的影响

方块

  • 被禁用的方块 ID 不会被可以创建新方块的命令识别
  • 被禁用方块的方块物品会被禁用
  • 被禁用的方块不会在结构中生成
  • 被禁用的方块不会作为实体的一部分加载（例如下落的沙子或末影人携带的方块）
  • 玩家无法与被禁用的方块互动

实体

  • 被禁用的实体 ID 不会被可以召唤新实体的命令识别
  • 被禁用的实体不会生成或加载
  • 被禁用实体的刷怪蛋物品会被禁用

物品

  • 被禁用的物品会从创造模式菜单中隐藏
  • 配方和战利品表会阻止生成被禁用的物品
  • 被禁用的物品 ID 不会被可以创建新物品的命令识别
  • 被禁用的物品不能用于互动或攻击

命令

  • 新命令：fillbiome
  • 新的 execute 子命令：execute if|unless biome
  • 对 publish 命令的改进

fillbiome

更改区域的生物群系条目。请注意，生物群系不是按方块存储的，因此受影响的位置可能无法与输入完全匹配。

语法：

fillbiome <from> <to> <biome> [replace <filter>]

参数：

  • from：要填充区域的一个角
  • to：要填充区域的另一个角
  • biome：要设置的生物群系
  • filter：要替换的生物群系或生物群系标签

execute

execute 命令现在可以以生物群系为条件。

语法：

execute if|unless biome <pos> <biome>

publish

publish 命令新增了参数，用于启用命令和设置默认游戏模式。

语法：

publish [allowCommands] [gamemode] [port]

遥测

此版本包含 WorldUnloaded 事件（必需事件）以及多个自愿加入的事件。诊断跟踪是一种帮助我们了解你喜欢 Minecraft 的哪些方面，从而让我们改进这些方面的工具。

WorldUnloaded 与 WorldLoaded 之所以是必需事件，是因为我们查看的信息确实是必需的。作为 Xbox 的一部分，我们都需要遵循一套实践标准，你可以在此处找到详细说明。我们认为对工作至关重要的数据参数由 Mojang Studios 团队与 Xbox 保持一致来设定。

我们想了解的是你认为 Minecraft 有多有趣。有许多方法可以实现这一点，例如反馈、游戏测试、体验和魔法。我们希望在数据方面也加入其中，这就是 WorldLoaded 和 WorldUnloaded 的用武之地。WorldLoaded 衡量你启动会话的时间，WorldUnloaded 衡量你关闭会话的时间。它们将共同通过游戏时长和玩家选择的游戏模式等指标来衡量 Minecraft 的趣味性。仅此而已。我们收集的所有数据，无论是必需的还是自愿加入的，都遵循 GDPR 和 CCPA 最佳实践来保护你的信息安全。

当前其他遥测事件均为自愿加入，这意味着你可以选择是否向我们发送额外数据。唯一不能自愿加入的玩家是 Microsoft 儿童账户，但每个人仍然可以将所有反馈发送到 feedback.minecraft.net。

就像我们在反馈网站上收到的你的所有想法和评论一样，这极大地帮助我们改进 Minecraft。我们想制作一款你想玩的游戏，所以我们需要了解这款游戏需要什么。即使只是更多的岩浆。

透明度

  • 新增了遥测数据收集屏幕
    • 此屏幕显示有关所发送数据类型的信息
    • 发送数据的级别可以在“最小”和“全部”之间控制
      • “最小”仅发送必需数据
      • “全部”发送必需数据以及可选数据
    • 默认数据级别为“最小”（仅必需数据）
  • 客户端发送的每个遥测事件现在都会记录到磁盘
    • 旧日志文件会在 7 天后移除
    • 这些文件可以在 logs/telemetry 目录下找到
      • 通过遥测数据收集屏幕上的“打开我的数据”按钮可以访问此目录的快捷方式

必需事件

  • 新增了 WorldUnloaded 事件
  • 从 WorldLoaded 事件中移除了客户端 Java 版本

WorldLoaded 与 WorldUnloaded

了解 Minecraft 的游玩方式使我们能够将游戏更新和改进集中在与玩家最相关的领域。告诉我们这些的数据包括游戏模式、客户端或服务器是否安装模组的状态以及游戏版本。

WorldLoaded 和 WorldUnloaded 是两个配对事件，用于计算世界会话持续了多长时间（以秒和刻为单位）。WorldLoaded 的数据在世界启动时发送，WorldUnloaded 的数据在世界关闭时发送（退回到标题界面、从服务器断开连接）。

可选事件

  • 新增了 PerformanceMetrics 和 WorldLoadTimes 事件

PerformanceMetrics

了解 Minecraft 的整体性能概况有助于我们针对各种机器规格和操作系统调整和优化游戏。

定期的性能指标包括帧速率、渲染性能、内存使用情况、操作系统以及客户端和服务器的模组状态等数据。

包含游戏版本是为了帮助我们比较 Minecraft 新版本的性能概况。

WorldLoadTimes

了解加入世界需要多长时间以及随时间的变化对我们来说很重要。例如，当我们添加新功能或进行较大的技术更改时，我们需要看看这对加载时间产生了什么影响。

此事件包括世界加载的总时间（以毫秒为单位）、是否是新建世界，以及游戏版本和平台详细信息。

游戏规则

  • 新增了 blockExplosionDropDecay、mobExplosionDropDecay 和 tntExplosionDropDecay 游戏规则
    • 设置为 false 时，所有方块都会掉落战利品
    • 设置为 true 时，方块会根据距离爆炸中心的远近随机掉落战利品
    • TNT 默认为 false，方块和生物默认为 true
  • 新增了 snowAccumulationHeight 游戏规则
    • 当下雪时，此游戏规则决定每个方块可以积累的最大层数
    • 默认值为 1
    • 设置为 0 时不会形成任何雪
    • 设置为 8 或以上时，雪可以形成到完整方块的高度
  • 新增了 waterSourceConversion 和 lavaSourceConversion 游戏规则
    • 设置为 true 时，允许该流体形成新的源头
    • 水默认为 true，熔岩默认为 false
  • 新增了 globalSoundEvents 游戏规则，用于控制某些游戏时刻是否无论位置都被所有玩家听到
    • 默认值为 true

  • 适用于 shaped/shapeless 和各种特殊合成配方的类别：
    • building
    • redstone
    • equipment
    • misc（默认）
  • 适用于 smelting、blasting、smoking、campfire_cooking 的类别：
    • food

  • 某些配方书会将多个类别合并到单个标签页中

资源包

  • 资源包版本现在为 12
  • 移除了版本 3 和 4（扁平化之前）资源包的“修复器”
    • 游戏将不再尝试将这些版本的包适配到当前版本
  • 游戏现在会加载适当目录中的所有方块模型和方块状态定义
    • 这意味着如果包中存在无效模型，将阻止包加载，即使该模型未被使用

纹理加载更改

  • 背景：当游戏加载方块和物品模型使用的所有纹理时，需要将它们拼接（合并）为单个图像，称为“图集”
    • 被拼接在图集上的单个纹理称为“精灵”
  • 为了提高加载性能，方块和物品纹理现在在方块和物品模型处理之前加载
    • 默认情况下，不在 textures/item 和 textures/block 目录中的纹理将不再被自动识别，并且会加载失败
  • 资源包现在可以在 atlases 目录中包含配置文件，用于控制哪些图像包含在图集中

图集配置文件

  • 资源包现在新增了 atlases 目录
  • 此目录包含用于配置图集的 JSON 条目：
    • blocks - 方块和物品模型使用的纹理
    • banner_patterns、beds、chests、shield_patterns、shulker_boxes、signs - 用于渲染某些特殊情况的模型
    • mob_effects - UI 中效果图标使用的纹理
    • paintings - 画使用的纹理
    • particles - 粒子使用的纹理（由 particles 目录中的文件内的 textures 字段引用）
  • 如果多个包包含这些文件，它们将按包内的顺序合并（与数据包中的标签相同）
  • 这些文件内部是一个 JSON 对象，其中包含一个名为 sources 的列表
    • sources 中的每个条目都会在加载时按定义顺序运行，向纹理列表中添加或移除新文件；以供稍后由方块模型、粒子等引用
  • 源的类型：
    • directory - 列出目录及其子目录中的所有文件，涵盖所有命名空间
      • source - 要列出的包中的目录（相对于 textures 目录）
      • prefix - 加载时附加到精灵名称的字符串
    • single - 添加单个文件
      • resource - 包中资源的位置（相对于 textures 目录，隐式包含 .png 扩展名）
      • sprite - 精灵名称（可选，默认为 resource）
    • filter - 移除匹配给定模式的精灵
      • namespace、path - 要移除的 ID 的模式（正则表达式）（仅对已在列表中的条目有效）
        • 如果省略，则会匹配任何值
    • unstitch - 从其他图像复制矩形区域
      • resource - 包中资源的位置（相对于 textures 目录，隐式包含 .png 扩展名）
      • divisor_x、divisor_y - 用于确定区域使用的单位
      • regions - 要从源图像复制的区域列表
        • sprite - 精灵名称
        • x、y - 区域左上角的坐标
        • width、height - 区域的大小
      • 诸如 x 之类的值会通过除以各自的除数，然后乘以真实图像大小来转换为真实图像坐标
  • 示例：如果包中有一个名为 assets/test/textures/fancy/iridium.png 的文件，且源为 {"type": "directory", "source": "fancy", "prefix": "custom/"}，则该纹理将在模型中作为 test:custom/iridium 使用

  • 功能开关旨在隐藏未完成或实验性的特性，以确保你的现有世界不受影响
  • 使用实验性特性的世界将在世界选择列表中标记为“实验性”
  • 现有世界无法切换实验性特性

新增骆驼

启用 1.20 更新实验性特性后，骆驼现在可用。

  • 骆驼可以装备鞍，并可容纳两名玩家骑行
  • 骆驼会自然生成在沙漠村庄中
  • 骆驼很高
    • 当你骑在骆驼上时，大多数敌对生物无法够到你
    • 它们可以轻松走过栅栏和墙
  • 骆驼非常优雅，但脾气暴躁
    • 它们会随机坐下
    • 坐下时，很难说服它们移动
  • 骆驼既可以缓慢行走，也可以快速冲刺
  • 它们也可以向前猛冲，但这样做会暂时失去体力

竹制方块组

启用 1.20 更新实验性特性后，新的竹制方块组现在可用。

  • 新的木质方块
    • 竹块
    • 去皮竹块
    • 竹木板
    • 竹门
    • 竹活板门
    • 竹告示牌
    • 竹楼梯
    • 竹台阶
    • 竹栅栏
    • 竹栅栏门
    • 竹按钮
    • 竹压力板

  • 由竹块合成的竹木板只能得到 2 块木板，而原木可以得到 4 块
  • 新增了一种竹子独有的“马赛克”木板变体，称为竹马赛克

    • 你可以合成竹马赛克的楼梯和台阶变体

錾制书架

启用 1.20 更新实验性特性后，新的錾制书架变体现在可用。

  • 由 6 个木板和 3 个木质台阶合成
  • 可以存储书、书与笔、成书和附魔书
    • 最多容纳 6 本书
    • 安全保存你世界中的故事和传说
    • 可以通过对准特定槽位来添加或移除这些书

  • 可以与漏斗配合使用

悬挂式告示牌

是否曾经想悬挂你的告示牌？拿几条锁链，剥一些原木，现在你可以了！启用 1.20 更新实验性特性后，悬挂式告示牌现在可用。

  • 悬挂式告示牌是普通告示牌的更昂贵版本
    • 由 2 条锁链和 6 个你喜欢的木质类型的去皮原木合成
    • 合成结果为 6 个悬挂式告示牌
  • 可以通过以下方式悬挂：
    • 在可以从中心提供支撑的方块下方，例如完整方块或栅栏
    • 附着在方块的实心侧面
    • 附着在另一个悬挂式告示牌的侧面或下方
  • 与普通告示牌不同，它们不能在没有侧面或上方支撑的情况下直接放置在地面上
    • 但是，带有横杆的悬挂式告示牌在支撑方块被移除时不会弹出

  • 猪灵头颅在被红石充能时，或当玩家佩戴行走时，会扇动耳朵
