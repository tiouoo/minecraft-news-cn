现在是 Minecraft 1.20.5 第一个预发布版发布的时候了，其中包含对试炼密室和不祥试炼的一些调整，以及新的进度、大量的技术调整和更改，还有大量的漏洞修复。

从现在起，你应该会看到漏洞在陆续被修复。除此之外，预发布版不遵循常规的周三快照发布节奏，所以请留意下一个预发布版。

实验性特性

试炼密室

  • 现在在地下生成时会更一致地被地形掩埋
  • 重做了 'Chamber 6'，增加了变体，并更名为 'Assembly'
  • 为密室添加了新的陷阱发射器样式
  • 修复了走廊中各种断裂的拼图连接
  • Chamber Eruption：
    • 阻止凝灰岩砖在空中生成
    • 为象限添加了更多灯光

不祥试炼

  • 能够穿戴装备的生物现在通常会携带附魔武器和盔甲生成
    • 盔甲附魔包括保护 IV、弹射物保护 IV 和火焰保护 IV
    • 武器附魔包括锋利 I、击退 I、力量 I 和冲击 I
  • 穿戴装备的生物死亡时不再有机会掉落其装备
  • 当不祥试炼刷怪笼选择将弹射物投射到哪个实体上时，现在有 50% 的几率选择玩家
    • 弹射物现在会在所选实体上方更精准地生成

编织

  • 现在死亡时会更一致地生成 2-3 个蜘蛛网
  • 玩家现在会受到通过蜘蛛网时的移动增益影响
    • 以正常速度的 50% 而不是 25% 移动通过蜘蛛网

寄生

  • 现在有 10% 的几率生成 1-2 只蠹虫，而不是 5%
  • 蠹虫现在会在实体边界框的中心生成，并朝实体面朝的方向甩出

渗浆

  • 在给定的 5x5x5 区域内，只会生成最多不超过实体挤压上限数量的史莱姆

进度

  • 添加了 Revaulting - 使用不祥试炼钥匙解锁不祥宝库

1.20.5-pre1 的新特性

进度

  • 添加了以下进度：
    • Isn't it Scute? - 使用刷子从犰狳身上获得犰狳鳞甲
    • Snip it! - 使用剪刀从狼身上移除狼铠
    • Good as New - 使用犰狳鳞甲修复损坏的狼铠
    • The Whole Pack - 驯服每种狼变体中的一只

1.20.5-pre1 的更改

  • 添加了对 Viossa 语言的支持

技术性更改

  • 数据包版本现在为 39

数据包版本 39

  • 添加了新的物品子谓词和战利品函数
  • 为结构添加了新的地形适应类型：encapsulate
    • 会在结构的每个部分周围增加密度
    • 非常适合需要完全被地下覆盖的结构
  • 已移除成书中的页数限制
  • 在命令和数据包定义中，不再允许组合使用 max_stack_size 和 max_damage 组件
  • 在实体 equipment 子谓词中添加了一个新选项 body，用于匹配实体身体盔甲槽中的物品
  • food 组件上的 saturation_modifier 字段已替换为 saturation
    • saturation 是添加到玩家饱和度的确切值
    • 相对于以前的 saturation_modifier，其定义为 saturation = nutrition * saturation_modifier * 2
  • 命令和区域效果云中的粒子表示方式已更改
  • 更改了刷怪笼的 SpawnPotentials 和试炼刷怪笼配置的 spawn_potentials 中的可选 equipment_loot_table 字段
    • 现在命名为 equipment，而不是 equipment_loot_table
    • 格式：包含字段的对象
      • loot_table - 用于生成装备的战利品表
      • slot_drop_chances - 可选的装备槽位到指定掉落几率的映射
        • 也可以是单个值而不是列表，以应用于所有槽位：例如，slot_drop_chances: 0.0f 将对所有槽位应用 0% 的几率
    • 例如 equipment: {loot_table: "minecraft:equipment/trial_chamber", slot_drop_chances: {"head": 0.0f, "chest": 0.25f, "legs": 1.0f, "feet": 0.25f}}
    • 如果存在，从指定战利品表中抽取的物品将装备到生成的生物身上
  • 移除了物品标签 minecraft:tools（与 minecraft:breaks_decorated_pots 重叠）
  • 添加了实体类型标签 minecraft:punchable_projectiles，用于应能被拳头击中并偏转向玩家视线方向的弹射物
  • 添加了附魔标签 minecraft:tooltip_order，用于控制附魔在工具提示中的列出顺序

修改的战利品函数

set_contents

  • 未使用的字段 type 已被移除
  • 添加了新的必填字段 component：
    • 描述要用物品填充的目标组件
    • 现有内容将被替换
    • 允许的值：container、bundle_contents、charged_projectiles
    • bundle_contents 和 charged_projectiles 将忽略空堆叠

set_custom_data

字段 tag 现在既接受以字符串形式编写的 SNBT 数据（现有格式），也接受未展平的标签

新的战利品函数

modify_contents

  • 将修饰符函数应用于组件内的每个物品
  • 如果组件不存在，则不会添加它
  • 字段：
    • conditions - 用于过滤此函数的条件列表
    • component - 目标组件
      • 允许的值：container、bundle_contents、charged_projectiles
    • modifier - 要应用于容器内每个物品的函数或函数列表

set_item

  • 替换物品堆叠的物品类型，而不改变数量和组件
  • 字段：
    • conditions - 用于过滤此函数的条件列表
    • item - 新的物品类型

filtered

  • 仅对匹配物品谓词的物品应用子函数
  • 字段：
    • conditions - 用于过滤此函数的条件列表
    • item_filter - 用于匹配物品的物品谓词
    • modifier - 应用于匹配物品的函数

set_custom_model_data

  • 设置 custom_model_data 组件
  • 字段：
    • conditions - 用于过滤此函数的条件列表
    • value - 整数数字提供器

新的物品子谓词

组件谓词的通用规则：

  • 除非另有说明，谓词中与组件中字段同名的字段（即与谓词同名）将匹配该字段的值
  • 这些字段通常与组件中的类型相同，但将是可选的
  • 例外：
    • 列表字段将被替换为集合匹配器（见下文）
    • 整数和浮点字段将被替换为范围
    • 注册表 ID 将被替换为接受 ID、ID 列表或标签的类型

集合匹配器

集合匹配器是用于匹配集合的谓词共享部分。此匹配器的每个实例都具有相同字段和相同功能，唯一不同的是所匹配元素的类型。字段：

  • size - 用于匹配集合大小的整数范围
  • contains - 元素谓词列表
    • 所有条件都必须匹配，谓词才能通过
    • 并非测试容器中的所有元素都必须匹配
    • 元素可以按任意顺序排列
    • 单个元素可以匹配多个谓词
    • 示例（当匹配物品堆叠时）：
      • {contents:[{item:diamond}]} - 当至少有一个钻石物品时匹配
      • {contents:[{item:diamond}, {item:dirt}]} - 当至少有一个钻石物品且至少有一个泥土物品时匹配
  • count - 关于元素数量的匹配器列表
    • 条目字段：
      • test - 元素匹配器
      • count - 可选的整数范围，用于检查通过 test 的元素数量
    • 示例（当匹配物品堆叠时）：
      • {count:[{count:3,test:{items:diamond}}]}} 仅当正好有 3 堆钻石时（无论堆叠大小）才会匹配

container

  • container 组件的匹配器（例如潜影盒）
  • 字段：
    • items - 可选的集合匹配器
      • 注意：空物品会被忽略。这意味着 container~{items:{size:3}} 仅在容器中恰好有 3 个非空堆叠时才会通过

bundle_contents

  • bundle_contents 组件的匹配器
  • 字段：
    • items - 可选的集合匹配器

firework_explosion

  • firework_explosion 组件的匹配器
  • 字段
    • shape - 可选形状匹配器，与 minecraft:firework_explosion 组件中的 shape 字段值相同
    • has_trail - 可选的布尔值
    • has_twinkle - 可选的布尔值

fireworks

  • fireworks 组件的匹配器
  • 字段：
    • explosions - 可选的集合匹配器，用于 firework_explosion 谓词
    • flight_duration - 可选的飞行持续时间整数范围检查
  • 示例：minecraft:fireworks~{explosions:{contains:[{shape:small_ball}]}}] - 如果烟花至少有一个 small_ball 形状的爆炸，则匹配

writable_book_content

  • writable_book_content 组件的匹配器
  • 字段
    • pages - 可选的字符串集合匹配器（仅匹配页面未过滤的内容）

fireworks

  • written_book_content 组件的匹配器
  • 字段
    • pages - 可选的聊天组件集合匹配器（仅匹配页面未过滤的内容）
    • author - 可选的字符串值
    • title - 可选的字符串值（仅匹配值）
    • generation - 可选的世代整数范围检查
    • resolved - 可选的布尔值

attribute_modifiers

  • attribute_modifiers 组件的匹配器
  • 字段：
    • modifiers - 可选的集合匹配器，用于以下具有以下字段的条目：
      • attribute - 可选的 ID、ID 列表或标签，用于匹配属性
      • id - 可选的 UUID
      • name - 可选的字符串
      • amount - 可选的双精度范围检查
      • operation - 可选的操作类型（与 attribute_modifiers 组件中的 operation 字段值相同）
      • slot - 可选的适用槽位类型（与 attribute_modifiers 组件中的 slot 字段值相同）

trim

  • trim 组件的匹配器
  • 字段：
    • material - 可选的 ID、ID 列表或标签，用于匹配材料
    • pattern - 可选的 ID、ID 列表或标签，用于匹配图案

粒子表示方式

  • 命令和区域效果云中的 Particles 等字段中的粒子选项现在使用与世界生成文件相同的表示方式（例如现有生物群系的环境粒子设置）
  • 例如，命令 /particle minecraft:dust 1.0 0.0 0.0 2.0 ... 变成 /particle minecraft:dust{color:[1.0, 0.0, 0.0], scale:2.0} ...
  • 没有额外选项的粒子语法（如 minecraft:villager）保持不变
  • 方块粒子（minecraft:block、minecraft:block_marker、minecraft:falling_dust、minecraft:dust_pillar）选项的更改：
    • 字段 value 已重命名为 block_state
    • 字段 block_state 现在也接受纯方块名称来表示默认方块状态
    • 示例转换：
      • minecraft:block minecraft:redstone_lamp[lit=true] -> minecraft:block{block_state: {Name: "minecraft:redstone_lamp", Properties: {lit: "true"}}}
      • minecraft:block minecraft:diamond_block -> minecraft:block{block_state: "minecraft:diamond_block"}
  • minecraft:item 选项的更改：
    • 字段 value 已重命名为 item
    • 字段 item 现在也接受纯物品名称来表示具有默认组件的物品堆叠
    • count 字段现在被忽略
    • 示例转换：
      • minecraft:item minecraft:dirt -> minecraft:item{item: {id: "minecraft:dirt"}}
      • minecraft:item minecraft:dirt -> minecraft:item{item: "minecraft:dirt"}
  • dust_color_transition 选项的更改：
    • 字段 fromColor 已重命名为 from_color
    • 字段 toColor 已重命名为 to_color
    • 示例转换：dust_color_transition 1.0 0.0 0.0 0.5 0.0 1.0 0.5 -> dust_color_transition{from_color: [1.0f, 0.0f, 0.0f], scale: 0.5f, to_color: [0.0f, 1.0f, 0.5f]}
  • entity_effect 选项的更改：
    • 字段 value 已重命名为 color
    • 字段 color 现在也接受表示 RGBA 颜色的浮点数列表
