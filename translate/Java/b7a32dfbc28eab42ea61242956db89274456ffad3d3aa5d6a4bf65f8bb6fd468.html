游戏测试主入口

这个新的入口点会自动启动服务器、运行所有可用的游戏测试，然后退出。

选项：

  • --help - 显示用法信息
  • --packs <path> - 设置一个要包含在世界中的数据包文件夹
    • 任何包含 pack.mcmeta 文件的 zip 文件或文件夹都会被包含
  • --report <path> - 将结果以类似 junit 的 XML 报告形式导出到指定路径
  • --tests <selection> - 通过选择表达式指定要运行的测试 - 一个与命名空间测试实例 ID 匹配的通配符表达式
    • 如果省略，或使用空 ID，则运行所有测试
  • --universe <path> - 测试服务器世界将在此路径下创建
    • 任何现有文件夹都将被替换
    • 默认值：gametestserver
  • --verify <boolean> - 启用测试验证
    • 对于每个 90 度旋转步骤，运行 test 或 testNamespace 指定的测试 100 次
    • 默认值：false

用法示例：java -DbundlerMainClass="net.minecraft.gametest.Main" -jar server.jar --packs mytestpacks

游戏测试

游戏测试系统是一个用于测试游戏各方面的新集成系统。每个测试是一个定义测试执行方式参数的数据文件，并结合一个包含基础设置的已保存结构文件。

通常，测试框架期望在独立的超平坦世界中运行测试。

测试实例

测试实例在注册表 test_instance 中定义。它们是定义要运行测试的小型资源。

字段：

  • environment：测试环境的命名空间 ID，该实例将作为此环境的一部分运行
  • structure：用于测试的结构的命名空间 ID
  • max_ticks：一个正整数，表示在测试被视为超时之前允许经过的最大游戏刻数
  • setup_ticks：可选的非负整数（默认：0），表示在放置结构后、开始测试之前等待的游戏刻数
  • required：可选的布尔值（默认：true） - 该测试是否被视为整个测试套件通过所必需的
  • rotation：应用于测试结构的可选旋转
    • 可为 none（默认）、clockwise_90、180 或 counterclockwise_90
  • manual_only：可选的布尔值（默认：false），对于不包含在自动化测试运行中的测试设置为 true
  • sky_access：测试是否需要无障碍的天空访问
    • 默认（false）情况下，测试被包围在屏障方块中 - 如果设置为 true，顶部将保持开放
  • max_attempts：运行测试的尝试次数（默认：1）
  • required_successes：测试被视为成功所需成功的尝试次数（默认：1）
  • type：测试的类型 - 可为 block_based 或 function

函数测试

函数测试依赖内置函数来运行测试并指示成功或失败。它们有一个额外字段：

  • function：要运行的测试函数的命名空间 ID

更多信息请参阅“从代码中使用游戏测试框架”更新日志部分。

基于方块的测试

基于方块的测试使用测试结构中的测试方块来运行测试并指示成功或失败。

测试环境

测试环境是将测试分组并为它们提供正确运行前提条件的一种方式。测试环境是 test_environment 注册表中的一种资源。每个测试环境定义都有一个 type 字段决定其设置：

  • all_of 定义会应用 definitions 字段中多个子定义的设置
  • function 定义使用 mcfunction 文件作为设置和清理
    • setup：可选的用于设置的 mcfunction 命名空间 ID（如果有）
    • teardown：可选的用于清理的 mcfunction 命名空间 ID（如果有）
  • game_rules：定义可设置任意数量的游戏规则
    • bool_rules：要设置的布尔游戏规则列表及其值
    • int_rules：要设置的整数游戏规则列表及其值
    • 每条规则是一个包含两个字段的对象：
      • rule：要设置的规则的确切名称
      • value：要设置的值
    • 游戏规则会在测试环境完成后重置为默认值
  • weather 定义设置天气状态
    • weather：要设置的天气 - 可为 clear、rain 或 thunder
  • time_of_day 定义设置指定的时间
    • time：以游戏刻数表示的每天时间，为非负整数

游戏默认提供一个空的测试环境：minecraft:default。

测试方块

测试方块是用于实现基于方块的测试的方块。它有四种模式：

  • start：测试开始时触发红石脉冲
  • log：被红石充能时向日志文件记录一条消息
  • fail：被红石充能时使测试失败
  • accept：被红石充能时完成测试

基于方块的测试要求在结构中至少有一个 start 方块和一个 accept 方块。

test 命令

test 命令是一个用于创建和运行测试的新命令。

语法：

test clearall [<radius>]
test clearthat
test clearthese

test create <test> [<width>] [<height> <depth>]

test locate <selector>

test resetclosest
test reseetthese
test resetthat

test pos [<variable>]

test run <selector> [<numberOfTimes>] [<untilFailed>] [<rotationSteps>] [<testsPerRow>]
test runclosest [<numberOfTimes>] [<untilFailed>]
test runfailed [<numberOfTimes>] [<untilFailed>] [<rotationSteps>] [<testsPerRow>]
test runmultiple <selector> [<amount>]
test runthat [<numberOfTimes>] [<untilFailed>]
test runthese [<numberOfTimes>] [<untilFailed>]

test stop

test verify <tests>

参数：

  • radius：清除测试的半径范围
  • test：测试的命名空间 ID
  • selector：用于测试 ID 的通配符选择器
    • 支持 * 和 ? 匹配命名空间 ID
    • 如果未提供命名空间，默认使用 minecraft
    • 示例：
      • *:* - 匹配所有 ID
      • * - 匹配 minecraft 命名空间中的所有内容
      • custom:folder/*_test_? - 匹配 custom 命名空间 folder 文件夹中的 ID，其前缀后跟 _test_ 再跟一个有效字符
  • width：测试结构的宽度 - 如果省略，使用 5
  • height：测试结构的高度 - 如果省略，使用宽度
  • depth：测试结构的深度 - 如果省略，使用宽度
  • variable：要包含在复制的代码片段中的变量名
  • numberOfTimes：每个测试重复的次数 - 如果省略，使用 1
  • untilFailed：布尔值（默认 false），表示一旦某次迭代失败就应立即停止测试
  • rotationSteps：应用于测试的额外 90 度步进数 - 如果省略，使用 0
  • testsPerRow：在网格布局中每行放置的测试数量 - 如果省略，使用 8

test clear*

这些子命令会清除与所选测试关联的结构和方块。

test create

该子命令会在当前位置为给定测试创建测试设置，为指定大小的结构做准备。这为创建测试结构提供了一个起点。

test locate

尝试定位给定的测试。注意只搜索已加载的区块。

test reset*

这些子命令会重置所选测试的结构，移除周围的屏障并从零开始放置结构。

test pos

显示测试中指向方块的本地坐标。如果指定了可选的变量名，该变量名将用于通过点击输出消息中的坐标所获得的代码片段中。

test run*

运行一个或多个测试。如果同时运行多个测试，它们会被放置在网格中并行运行，但有一个数量上限。超过该限制后，测试将分轮运行，每轮完成后再开始下一轮的任何测试。

对于每个测试，会加载给定的结构并运行关联的测试。每个测试位置都会有一个信标光束展示测试状态。

  • 灰色信标 = 进行中
  • 红色 = 失败（必需测试）
  • 橙色 = 失败（可选测试）
  • 绿色 = 成功

如果测试失败，错误会显示在讲台上的书和屏幕覆盖层中。

请注意，游戏测试设计为在标准超平坦世界中运行。运行时会用石头替换每个测试周围的区域，并且正在运行的测试会被包围在屏障方块中。

test stop

这会停止所有正在运行的测试。请注意，由测试触发的游戏内事件可能仍然存在。

test verify*

通过运行同一测试的多个实例来验证一个或多个测试。

测试实例方块

要在世界中运行测试，需要使用测试实例方块。这种方块代表放置在世界中的测试，用于与该测试交互、保存结构、重置或运行测试。

使用 test 命令运行或创建测试时，也会放置一个测试实例方块来控制该测试。

从代码中使用游戏测试框架

游戏测试框架也可以以比基于方块的测试更灵活的方式从代码中使用。要做到这一点，你需要通过模组修改游戏，将你的测试函数添加到 test_function 注册表（Registries.TEST_FUNCTION）中。

在某个启动方法（预注册表引导）中挂接以添加你的加载器 - 调用 TestFunctionLoader.registerLoader()，并传入 TestFunctionLoader 的实现。然后你的实现可以使用提供的 register 消费者来注册测试函数，并指定它们的命名空间 ID。该命名空间 ID 之后可以在 function 类型的测试实例中引用。

测试函数是一个 Consumer<GameTestHelper>，使用该 GameTestHelper 实例来操作世界并对结果世界的状态进行断言。

该辅助器可用于生成生物、放置方块、查询方块和实体，并断言测试的状态。大多数 GameTestHelper 方法接受测试本地坐标，你也可以使用 /test pos 找到这些坐标。

示例代码，可能需要与一个测试结构配合，该结构包含一个带有鳕鱼的锁定漏斗，指向熔炉：

public void furnace_smelts_item(final GameTestHelper helper) {
    helper.setBlock(0, 4, 0, Blocks.AIR);
    helper.succeedWhen(() -> helper.assertContainerContainsSingle(new BlockPos(0, 0, 0), Items.COOKED_COD));
}

更复杂的设置通常使用 helper.startSequence() 来建模必须发生的事件序列。

与基于方块的测试相比，函数测试失败时通常会生成更有帮助的错误消息，包括失败内容的位置以及该位置的预期内容。
