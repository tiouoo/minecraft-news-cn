嘿！这是 1.21.6 的第一个预发布版。从现在开始，你们将主要看到我们在修复漏洞，发布计划可能每周会包含不止一个预发布版。我们即将迎来今年的第二次更新！

更改

  • 干恶魂方块的状态改变时，现在会发出振动频率 11
  • 用剪刀剪下鞍、马铠和地毯时，现在会发出振动频率 6，同时卸下这些装备时的频率为 4
  • 干恶魂的环境音效现在由“方块”音效选项调整，而不是“环境/氛围”选项
  • 骑乘快乐恶魂的玩家不再能完全穿过另一位玩家骑乘的快乐恶魂

技术性更改

  • 数据包版本现在为 79
  • 资源包版本现在为 63

数据包版本 79

  • 对话框现在可以配置是否暂停游戏，以及在执行操作后是否关闭
  • 每个对话框现在都可以包含输入项并可提交信息
    • 动作的定义已相应修改以支持该功能
    • 专用的输入对话框类型已被移除，因为现在它们已多余
    • 元素顺序为：
      • 正文
      • 输入项
      • 动作
  • minecraft:custom 点击事件已扩展为可携带完整的 NBT 标签
  • 新增了一个名为“快速操作”的按键绑定，允许访问内容配置的对话框

快速操作按键绑定

  • 新增了一个按键绑定，允许用户访问一组对话框
  • 默认按键：G
  • 该功能由 minecraft:quick_actions 对话框标签配置
    • 如果此标签为空，按键绑定不执行任何操作
    • 如果此标签只有一个元素，按键绑定将打开该对话框
    • 如果此标签有多个元素，按键绑定将打开 minecraft:quick_actions 对话框，该对话框（默认情况下）允许用户选择标签元素之一
      • 如果该对话框被移除，按键绑定不执行任何操作
  • 此选项旨在用于自定义内容和服务器，因此此标签默认为空

通用对话框字段

新字段：

  • pause - 对话框界面是否应在单人模式中暂停游戏，默认：true
  • after_action - 在点击或提交动作后对对话框执行的附加操作，默认：close
    • close - 关闭对话框并返回之前的非对话框界面（如果有）
    • none - 不执行任何操作，即保持当前对话框界面打开
      • 仅在 pause 为 false 时可用，以避免在单人模式中锁定游戏
    • wait_for_response - 将当前对话框替换为“等待响应”界面
      • 此选项旨在防止用户在连接较慢时发送多个操作
        • 服务器预计最终会用新的对话框替换此界面
      • 为避免意外锁定，“返回”按钮将在 5 秒后变为可用
        • 点击此按钮将继续，如同对话框已关闭（即游戏返回之前的非对话框界面，如果有）
      • “等待响应”界面将在单人模式中取消暂停游戏，以避免锁定游戏

对话框类型

更改了 minecraft:multi_action、minecraft:server_links、minecraft:dialog_list

  • 将字段 on_cancel 替换为 exit_action，该字段包含一个可选动作
    • 如果存在 exit_action，则其按钮将出现在页脚中，否则不显示页脚
    • exit_action 也用于 Esc 动作

移除了 minecraft:simple_input_form

  • 由于任何对话框现在都可以包含输入项，此对话框可由 minecraft:notice 替代

移除了 minecraft:multi_action_input_form

  • 由于任何对话框现在都可以包含输入项，此对话框可由 minecraft:multi_action（不指定任何 exit_action）替代

输入控件类型

  • 为适应新的 minecraft:custom 点击事件，所有输入现在将返回字符串或 NBT 标签，具体取决于上下文

minecraft:text

  • 输出值：
    • 作为模板替换：内容不做修改
    • 作为标签：一个字符串标签，内容不做修改

minecraft:boolean

  • 输出值：
    • 作为模板替换：选中时为 on_true，未选中时为 on_false
    • 作为标签：选中时为 1b，未选中时为 0b

minecraft:number_range

  • 输出值：
    • 作为模板替换：当前值的文本表示
      • 整数将不带小数点发送
    • 作为标签：一个浮点标签，包含当前值

对话框主体类型

主体中文本组件的悬停和点击事件现在可以正常工作

  • 点击事件由对话框界面像任何其他动作一样处理 - 这意味着它也会执行 after_action

动作

  • 由于普通对话框和输入对话框的合并，动作的格式已更改
  • 每次动作后，对话框将始终评估 after_action 字段的内容（见上文）

字段：

  • 保留字段：label、tooltip、width
  • 新字段：action（替换 on_click 和 on_submit）- 点击按钮时执行的动作，可选对象，包含字段：
    • type - 来自 minecraft:dialog_action_type 注册表的值
    • <type-specific> - 见下文，取决于 type

静态对话框动作类型

所有现有的 click_event 动作（除了 open_file）都作为对话框动作类型包含在内。

使用与文本组件上的 click_event 相同的格式（但将 action 替换为 type）。例如，当使用 show_dialog 时，动作按钮的条目将如下所示：

{
    "label": "some label",
    "action": {
        "type": "show_dialog",
        "dialog": "some:id"
    }
}

minecraft:dynamic/run_command 动作类型

  • 此动作将使用提供的宏模板构建 run_command 事件
  • 宏将使用所有输入的字符串值进行展开
    • 例如，如果宏模板为 some_command $(some_input)，则输入中 key 为 some_input 的字符串值将用于模板展开
    • 宏中未使用的输入将被忽略，而未匹配任何输入的宏参数将被替换为空字符串

字段：

  • template - 一个包含宏模板的字符串，将被解释为命令
minecraft:dynamic/custom 动作类型
  • 此方法将使用所有输入值构建 minecraft:custom 事件
  • 所有输入内容将一起发送到复合标签中，每个输入的标签值将放在该输入 key 字段对应的 id 下
  • 可以向载荷中添加额外的静态字段

字段：

  • additions - 要添加到载荷的字段，可选复合标签
  • id - 命名空间 ID

资源包版本 63

  • 新增了 oversized_in_gui 物品模型字段
  • 引入了新的玩家头颅特殊模型类型

物品模型

  • 物品模型定义现在有一个布尔字段 oversized_in_gui，默认为 false
    • 如果为 true，则允许物品模型大于其物品槽位
    • 如果为 false，则在 GUI 中渲染时物品模型将被裁剪到物品槽位大小
    • 物品在槽位外渲染的能力不应被视为官方支持的，由于许多服务器依赖此功能，因此暂时作为例外恢复
    • 我们希望在未来某个时候，用官方支持的方式来实现类似功能，从而取代此做法
  • 引入了新的物品模型 minecraft:player_head 来处理玩家档案纹理的加载和渲染
  • 移除了 minecraft:head 中对 minecraft:profile 的支持

minecraft:player_head 特殊模型类型

  • 渲染玩家头颅
  • 使用 minecraft:profile 组件中的档案来加载纹理。在档案纹理完全加载前，会渲染默认纹理
  • 无字段

minecraft:head 特殊模型类型

  • 不再支持使用 minecraft:profile 组件中的档案来加载玩家纹理
  • 当 kind 为 player 且未提供纹理覆盖时，渲染默认玩家纹理
  • 字段保持不变
